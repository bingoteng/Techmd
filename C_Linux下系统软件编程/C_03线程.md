## 3.进程和线程的核心区别:？

一句话概括：**资源拥有权与调度单位的分离**

- **进程是操作系统`资源分配`和保护的最小单位**
- **线程是操作系统 `任务调度`和执行的最小单位**

```
线程创建时资源少、效率高、速度快
1.进程 --- 重量级的进程 
CPU资源分配的基本单位---- 更侧重作为一个资源分配的单位
2.线程 --- 轻量级的进程 
CPU任务调度的基本单位---- 更侧重作为一个任务执行的单位
```

- 线程是依附于进程的，多个线程共享了进程的资源 ，进程如果不存在，线程也不复存在。
- 一个进程中，可以有多个线程 。
- 一个进程中，如果只有一个线程，单线程的进程 。

## 5.多线程vs多进程

- 都可以实现多任务的并发；
  - 并发指的是单核CPU，任务调度切换轮流执行
  - 并行指的是多核CPU，每个核心都在执行一个任务，多个进程同时运行
  - 对于单核CPU，多进程或多线程都只能通过操作系统调度算法，让任务交替执行。宏观上用户看到是并行，微观上只有一个任务在CPU上执行。这就是**宏观并行、微观串行**

- 进程是程序的一次执行过程,是CPU的资源分配的基本单位 ；
- 线程是轻量级的进程，作为CPU调度执行的基本单位，是进程中的执行单元。
- 进程:
  - 优点:
    - 稳定性，可靠性高：创建多个子进程，进程之间空间相互独立  
  - 缺点:
    - 资源开销大
    - 共享数据不方便。  
- 线程:
  - 优点:
    - 创建以及切换的速度快、效率高 。
    - 线程间(线程共享了进程的资源)共享资源很方便 。
  - 缺点:
    - 线程间资源竞争，数据操作可能不是预期效果 
    -  线程稳定性，可靠性 不如进程 。

### 3.死锁 (Deadlock)

#### 1. 什么是死锁？

- **定义**：两个或两个以上的进程（或线程）在执行过程中，因争夺资源而造成的一种**互相等待**的现象。
- **结果**：若无外力作用，它们都将无法推进下去，系统处于僵死状态。
- **本质**：资源竞争 + 推进顺序非法。

💡 *通俗比喻*：
```
你拿着钥匙 A，想要钥匙 B 开门；
我拿着钥匙 B，想要钥匙 A 开门；
我们都不放手，谁都进不去。
```

---

#### 2. 产生死锁的四个必要条件

🔴 **必须同时满足以下四个条件，死锁才会发生**（缺一不可）：

| 条件                                     | 含义                                                         | 举例                             |
| ---------------------------------------- | ------------------------------------------------------------ | -------------------------------- |
| **1. 互斥条件**<br>(Mutual Exclusion)    | 资源是独占的，同一时刻只能被一个进程占用                     | 打印机、互斥锁、临界区           |
| **2. 请求与保持条件**<br>(Hold and Wait) | 进程已经保持了至少一个资源，但又提出了新的资源请求，而该资源已被其它进程占有 | 拿着锁 A，再去申请锁 B           |
| **3. 不剥夺条件**<br>(No Preemption)     | 进程已获得的资源，在未使用完之前，不能强行剥夺，只能由自己释放 | 锁不能强行抢走，必须持有者解锁   |
| **4. 循环等待条件**<br>(Circular Wait)   | 若干进程之间形成一种头尾相接的循环等待资源关系               | 线程 1 等线程 2，线程 2 等线程 1 |

💡 *面试高频*：**破坏其中一个条件即可预防死锁**。

---

#### 3. 死锁 vs 饥饿 vs 活锁

| 概念                  | 定义                                 | 区别                                                       |
| --------------------- | ------------------------------------ | ---------------------------------------------------------- |
| **死锁 (Deadlock)**   | 进程互相等待，永远无法执行           | 🔴 **状态不变**，资源被占用，CPU 空闲                       |
| **饥饿 (Starvation)** | 进程长期得不到资源，无法执行         | 🟡 **动态等待**，资源被高优先级进程抢占                     |
| **活锁 (Livelock)**   | 进程不断改变状态响应对方，但无法推进 | 🟡 **状态改变**，CPU 忙碌，但无进展（类似两人过道互相礼让） |

---

#### 4. 处理死锁的策略

##### 1. 死锁预防 (Prevention)
**破坏四个必要条件之一**（静态策略，实现简单但效率低）：

- **破坏互斥条件**：
  - 将独占资源改造为共享资源（如 SPOOLing 技术虚拟打印机）。
  - 🟡 *限制：很多资源本质上无法共享（如临界区）。*

- **破坏请求与保持条件**：
  - **一次性分配**：进程运行前申请所有资源，否则不分配任何资源。
  - 🟡 *缺点：资源利用率低，可能导致饥饿。*

- **破坏不剥夺条件**：
  - 允许强行剥夺资源（如 CPU 时间片）。
  - 🟡 *限制：锁、打印机等资源难以强行剥夺（状态难以保存）。*

- **破坏循环等待条件**：
  - **有序资源分配法**：给资源编号，进程只能按序号递增申请。
  - 🟢 *最常用方案：定义锁的获取顺序（如 Lock A → Lock B）。*

##### 2. 死锁避免 (Avoidance)
**动态检测，确保系统不会进入不安全状态**：

- **银行家算法 (Banker's Algorithm)** 💡 *经典算法*
  - 每次分配资源前，检查系统是否处于"安全状态"。
  - 若分配后可能导致死锁，则暂不分配。
  - 🟡 *缺点：开销大，需预先知道最大资源需求，实际 OS 很少用。*

##### 3. 死锁检测 (Detection)
**允许死锁发生，定期检测并解除**：

- **资源分配图 (Resource Allocation Graph)**
  - 检测图中是否存在**环路**。
  - 单实例资源：有环 = 死锁。
  - 多实例资源：有环 ≠ 死锁（需进一步算法判断）。

##### 4. 死锁解除 (Recovery)
**检测到死锁后的补救措施**：

- **资源剥夺**：挂起某些进程，抢占其资源。
- **撤销进程**：终止死锁进程（代价大）。
- **进程回退**：让进程回退到某个检查点（Checkpoint）。

#### 5. 代码示例：线程死锁

##### 1. 典型死锁场景

```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

pthread_mutex_t lockA = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t lockB = PTHREAD_MUTEX_INITIALIZER;

// 线程 1：先锁 A，后锁 B
void* thread1_func(void *arg) {
    pthread_mutex_lock(&lockA);
    sleep(1);  // 模拟操作，增加死锁概率
    pthread_mutex_lock(&lockB);  // 🔴 阻塞：等待线程 2 释放 B
    
    // 临界区
    printf("Thread 1 done\n");
    
    pthread_mutex_unlock(&lockB);
    pthread_mutex_unlock(&lockA);
    return NULL;
}

// 线程 2：先锁 B，后锁 A
void* thread2_func(void *arg) {
    pthread_mutex_lock(&lockB);
    sleep(1);  // 模拟操作
    pthread_mutex_lock(&lockA);  // 🔴 阻塞：等待线程 1 释放 A
    
    // 临界区
    printf("Thread 2 done\n");
    
    pthread_mutex_unlock(&lockA);
    pthread_mutex_unlock(&lockB);
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, thread1_func, NULL);
    pthread_create(&t2, NULL, thread2_func, NULL);
    
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
```

💡 *运行结果*：程序卡死，无输出，CPU 占用低（阻塞等待）。

##### 2. 解决方案：统一锁顺序

```c
// 修正：两个线程都按 A->B 顺序加锁
void* thread2_func_fixed(void *arg) {
    pthread_mutex_lock(&lockA);  // ✅ 改为先锁 A
    sleep(1);
    pthread_mutex_lock(&lockB);
    
    printf("Thread 2 done\n");
    
    pthread_mutex_unlock(&lockB);
    pthread_mutex_unlock(&lockA);
    return NULL;
}
```

#### 6. 如何避免死锁（最佳实践）

##### 1. 锁顺序一致 (Lock Ordering)
- **规则**：所有线程必须按照**相同的顺序**获取锁。
- **实现**：给锁分配全局 ID，始终先锁 ID 小的，后锁 ID 大的。

##### 2. 尝试锁 (Trylock)
- **规则**：不阻塞等待，尝试获取，失败则释放已占锁并重试。
- **API**：`pthread_mutex_trylock()`

```c
if (pthread_mutex_trylock(&lockB) != 0) {
    pthread_mutex_unlock(&lockA);  // 释放已占锁
    usleep(1000);                  // 退避
    continue;                      // 重试
}
```

##### 3. 超时锁 (Timeout Lock)
- **规则**：设置等待超时，超时后释放资源并报错。
- **API**：`pthread_mutex_timedlock()`

```c
struct timespec ts;
clock_gettime(CLOCK_REALTIME, &ts);
ts.tv_sec += 1;  // 超时 1 秒

if (pthread_mutex_timedlock(&lockB, &ts) != 0) {
    // 超时处理：释放 lockA，记录日志，重试或退出
    pthread_mutex_unlock(&lockA);
}
```

##### 4. 减少锁粒度
- **规则**：锁住尽可能小的代码区域，减少持有时间。
- **🟢 进阶**：使用无锁编程（Lock-Free），如原子操作 `__atomic`。

##### 5. 避免嵌套锁
- **规则**：尽量不在持有锁的情况下申请另一把锁。
- **实现**：将需要锁保护的数据拷贝到局部变量，解锁后再处理。

#### 7. 嵌入式/Linux 中的特殊死锁

##### 1. 内核死锁 (Kernel Deadlock)
🔴 **后果**：系统宕机 (Kernel Panic)，看门狗复位。

- **常见场景**：
  - 中断上下文中获取自旋锁，而持有锁的进程被中断。
  - 递归获取非递归锁。
  - 内存分配（kmalloc）时触发页回收，页回收需要获取当前持有的锁。

- **预防**：
  - 中断禁止区不能睡眠（不能用 mutex，只能用 spinlock）。
  - 锁内避免调用可能睡眠的函数（如 `msleep`, `copy_from_user`）。

##### 2. 优先级反转 (Priority Inversion)
💡 *嵌入式实时系统经典问题*

```
场景：
1. 低优先级任务 L 获取锁。
2. 高优先级任务 H 就绪，抢占 L，申请同一锁 → 阻塞。
3. 中优先级任务 M 就绪，抢占 L（因为 L 持锁，H 等 L，M 不等）。
4. 结果：H 被 M 阻塞，尽管 H 优先级最高。

解决方案：
✅ 互斥锁优先级继承 (Priority Inheritance)
   - 当 H 等待 L 持有的锁时，临时提升 L 的优先级到 H 的水平。
   - L 释放锁后，恢复原优先级。
   - Linux: pthread_mutexattr_setprotocol(&attr, PTHREAD_PRIO_INHERIT);
```

##### 3. 自旋锁死锁 (Spinlock Deadlock)
```c
// 🔴 错误：单核 CPU 上自旋锁内调度
spin_lock(&lock);
schedule();  // 切换出去，锁未释放
// 另一个任务想获取锁，无限自旋 → 死锁

// ✅ 正确：自旋锁保护的区域必须短小，禁止睡眠
spin_lock(&lock);
// 临界区操作
spin_unlock(&lock);
```

#### 9. 面试高频考点

##### 💡 Q1：如何预防死锁？
```
✅ 标准回答：
1. 破坏循环等待：规定资源申请顺序（最常用）。
2. 破坏请求与保持：一次性申请所有资源。
3. 使用尝试锁 (trylock) 或超时锁 (timedlock)。
4. 减少锁持有时间，避免嵌套锁。
```

##### 💡 Q2：死锁和饥饿的区别？
```
✅ 区别：
- 死锁：互相等待，资源被占用，进程状态不变。
- 饥饿：资源被高优先级抢占，进程状态可能变（就绪→运行→就绪），但长期得不到资源。
- 解决：死锁靠破坏条件，饥饿靠公平调度（如老化算法）。
```

##### 💡 Q3：嵌入式系统中遇到死锁怎么办？
```
✅ 实战回答：
1. 现象：系统无响应，看门狗复位。
2. 定位：
   - 查看串口打印最后日志。
   - 使用 JTAG 挂起 CPU 查看寄存器/栈。
   - 内核开启 LOCKDEP 检测锁依赖。
3. 预防：
   - 严格遵循中断上下文规则（不睡眠）。
   - 使用优先级继承互斥锁。
   - 代码审查锁顺序。
```

##### 💡 Q4：银行家算法在实际 OS 中用吗？
```
🟡 回答：
- 理论上经典，但实际很少用。
- 原因：需要预先知道最大资源需求（很难预测），开销大，动态调度复杂。
- 现代 OS 更多采用 预防（锁顺序）+ 检测（看门狗）策略。
```

## 10. 总结

| 策略     | 方法            | 优缺点                          |
| -------- | --------------- | ------------------------------- |
| **预防** | 破坏 4 必要条件 | ✅ 简单可靠 ❌ 资源利用率低       |
| **避免** | 银行家算法      | ✅ 动态灵活 ❌ 开销大，需预知需求 |
| **检测** | 资源分配图      | ✅ 允许并发 ❌ 需定期检测，有开销 |
| **解除** | 杀进程/剥夺资源 | ✅ 恢复系统 ❌ 数据丢失，代价大   |

🟢 **嵌入式开发建议**：
```
1. 设计阶段定义锁层级（Lock Hierarchy）。
2. 编码阶段使用静态分析工具。
3. 测试阶段进行压力测试（高并发场景）。
4. 生产环境开启看门狗（最后防线）。
```

> ✨ **一句话总结**：  
> *"死锁是并发编程的噩梦，核心是互斥 + 循环等待；预防优于检测，统一锁顺序是最有效的实践；嵌入式场景需特别关注优先级反转和中断上下文"*
