# SPI协议✅

## 1、什么是SPI？

**SPI** 的全称是 **Serial Peripheral Interface**，即**串行外设接口**。

*   **定义**： `SPI`（Serial Peripheral Interface）: 中文叫**串行外设接口**。是一种**全双工同步串行**通信总线协议，采取**主从模式**，由Motorola公司开发，主要用于`高速设备短距离`通信，如芯片与芯片间，该总线通常采用**一主多从**架构，通过`片选信号`选择特定从机。

*   ![image-20260412211555679](D:/Typroa_notes/99-Store_photo_addr/image-20260412211555679.png)

*   **特点**：
    
    *   **全双工同步串行：**收发同步
    
    *   **四线制**：`时钟SCK/MOSI/MISO/CS`（除去电源地，通常4根线，`多从机时CS线`增加）
    
    *   **一主多从、片选使能**：数据可以在主设备和从设备之间同时进行发送和接收。
    
    *   ✅**高速**：相比`I²C`等协议，`SPI`通常可以运行在更高的时钟频率（`1~50MHZ`甚至更高）。
        *   普通传感器：1~10 MHz
        *   Flash/SD卡：10~50 MHz
        *   高速ADC/DAC：20~80 MHz（配合DMA）
    
    *   **高位先行**：通常`MSB`先行、低位先行`可配置`
    
    *   **主从结构**：通信由一个主设备发起和控制，一个或多个从设备响应。
    
    *   **协议简单**：没有复杂的寻址和应答机制但有（ID、CRC校验），硬件实现成本低、效率高。
    
    *   ✅**边沿采样**
        *   时钟极性`CPOL (Clock Polarity)`: 空闲时SCLK的电平
            *   `CPOL=0`: 空闲时`SCLK`为低电平
            *   `CPOL=1`: 空闲时`SCLK`为高电平
    
        *   时钟相位`PHA (Clock Phase)`: 数据采样时刻
            *    `CPHA=0`: 第一个时钟边沿采样，第二个边沿变化
            *   `CPHA=1`: 第一个时钟边沿变化，第二个边沿采样
    
        *   一般采用 `Mode 0 `模式  `CPOL 0  CPHA 0 `上升沿采样，下降沿变化
    
    *   使用场景：✅**对通信速度要求高、引脚资源充足、点对点或一主多从**
        *   高速`Flash`存储：`W25Q64/W25Q128`
        *   `TFT/OLED`显示屏：`ST7789/ILI9341`
        *   高速传感器：`MPU6050`(SPI模式)、`ADXL345` ADC
        *   `SD/TF`卡通信
        *   `W5500`以太网芯片
        
    *   设备数量：理论无限（通过GPIO扩展CS线），实际受`GPIO数量`和`布线复杂度`限制
    
        - 每个从机需独立`CS`线，或通过`译码器`扩展
        - 总线电容限制：高速时需注意信号完整性
    
    *   **推挽输出 + 独占总线**：
    
        - 推挽：可主动输出高/低电平，驱动能力强，无需上拉电阻
    
        - 独占：同一时刻只有一个从机驱动`MISO`，避免总线冲突
    
          > [!NOTE]
          >
          > *SPI与I2C的"线与"机制对比：*
          >
          > - ***SPI（推挽）：** 像"对讲机"，同一时刻只能一个人说话，说完要释放总线（MISO高阻态），否则多个从机同时驱动MISO会短路！*
          > - ***I2C（开漏）：** 像"会议室灯"，任何人都能关灯（拉低），但开灯靠弹簧（上拉电阻），天然支持多主仲裁。*
          >
          > ⚠️ **注意**：配置从机时，未选中时`MISO`必须为**高阻态**！

## 2、四线SPI通信时需要的信号线数量：

标准的四线SPI通信需要 **4根** 信号线。它们的名称和功能如下：

1.  **SCLK** 或 **SCK**：**串行时钟**，由主设备产生，用于同步数据传输。
2.  **MOSI**：**主设备数据输出，从设备数据输入**，主设备通过这根线向从设备发送数据。
3.  **MISO**：**主设备数据输入，从设备数据输出**，从设备通过这根线向主设备发送数据。
4.  **CS** 或 **SS**（CS - Chip Select，也称为SS-Slave Select ）**：**片选信号，由主设备控制，用于选择要进行通信的特定从设备。在同一时刻，总线上只有一个外设被选择，**通常为低电平有效**。

    | 信号线   | 全称                | 方向  | 功能说明                           |
    | -------- | ------------------- | ----- | ---------------------------------- |
    | `SCK`    | Serial Clock        | 主→从 | 时钟信号，由主机产生               |
    | `MOSI`   | Master Out Slave In | 主→从 | 主机发送，从机接收                 |
    | `MISO`   | Master In Slave Out | 从→主 | 从机发送，主机接收                 |
    | `NSS/CS` | Chip Select         | 主→从 | 片选信号，**低电平有效**，选中从机 |
5.  以上的四线方式构成了SPI全双工串行同步通信方式。需要注意的是，对于MOSI和MISO来说不是必须存在的，可以只有MOSI或者只有MISO。当然这样的话就只能实现单工通信方式了，这样的SPI成为三线SPI。至于到底采用三线方式还是四线方式取决于外设本身。例如，**OLCD只需要主机发送数据而不需要从机发送数据，就可以使用三线SPI的连接方式。**

**重要补充：**

*   **信号线总数**：对于一个**单主单从**系统，总共需要 **4根** 线。
*   对于一个**单主多从**系统，信号线总数是 `3 + N`（N为从设备数量）。即SCLK、MOSI、MISO这3根线是所有从设备共享的，而每个从设备都需要自己独立的CS片选线。主设备通过拉低对应从设备的CS线来激活它并进行通信。

## 3、SPI的通用通信时序

SPI的通信时序围绕着**时钟极性**(Clock Polarity 简称CPOL)和**时钟相位**(Clock Phase简称CPHA) 这两个关键参数来定义，它们共同决定了时钟信号的空闲状态和数据的采样时刻。共有4种模式（Mode 0-3）。

| 模式  | CPOL | CPHA | 时钟空闲状态 | 数据采样时刻（SCLK边沿） | 数据切换时刻（SCLK边沿） | 常见器件        |
| :---- | :--- | :--- | :----------- | :----------------------- | :----------------------- | --------------- |
| **0** | 0    | 0    | Low          | **上升沿**               | 下降沿                   | `MPU6050`       |
| **1** | 0    | 1    | Low          | 下降沿                   | **上升沿**               | 某些ADC         |
| **2** | 1    | 0    | High         | **下降沿**               | 上升沿                   | 少见            |
| **3** | 1    | 1    | High         | 上升沿                   | **下降沿**               | SD卡、TFT显示屏 |

```C
✅以模式0为例：时钟极性(CPOL)决定SPI空闲时为低电平，时钟相位(CPHA)决定第一个边沿采样。
    		即就是数据上升沿采样、下降沿变化；
2.通信开始前，主设备将目标从机的片选CS信号线拉低，选中该从机；其他从机保持高电平
3.SPI数据传输时，分为数据采样时刻和数据切换时刻：
  采样时刻：主从设备同时采样、数据在SCLK的上升沿采样
		主设备在MISO线上采样、从设备在另一根数据线上采样
    	从设备在MOSI线上采样
  切换时刻：主从设备同时切换，准备下1bit的的数据
    	主设备将数据输出在MOSI线上、从设备在另一个线上输出
    	从设备将数据放在MISO线上
4.重复这一过程8次，由于是全双工通信，主机发送8bit，从机返回8bit，成功与否由应用层判断（读取状态寄存器）
5. 通信结束：主机拉高CS信号线，SCLK信号恢复低电平。
```

我们以最常用的 **Mode 0 (CPOL=0, CPHA=0)** 为例来简述通信过程：

**Mode 0 时序特点**：
*   **CPOL = 0**：时钟信号SCLK在空闲状态时为**低电平**。
*   **CPHA = 0**：数据在SCLK的**第一个边沿（即奇数边沿，这里是上升沿）** 被采样，在相反的边沿（下降沿）被切换（输出）。
*   主设备和从设备**必须配置为相同的时序模式**才能正常通信。

**一次8位数据（1个字节）传输的时序步骤**：

1.  **初始化片选**：
    *   主设备将目标从设备的**CS**信号线拉低（有效），通知从设备通信即将开始。

2.  **时钟周期与数据传输（以1bit为例）**：
    *   **时钟上升沿（采样时刻）**：在SCLK从低电平跳到高电平的这个瞬间，**主设备和从设备同时采样（读取）** 各自输入线上的电平。
        *   主设备在**MISO**线上采样，**读取**从设备发来的1bit数据。
        *   从设备在**MOSI**线上采样，**读取**主设备发来的1bit数据。
    *   **时钟下降沿（切换时刻）**：在SCLK从高电平跳回低电平的这个瞬间，**主设备和从设备同时准备（输出）** 下一bit要发送的数据。
        *   主设备将下一bit数据放到**MOSI**线上。
        *   从设备将下一bit数据放到**MISO**线上。

3.  **重复**：
    *   上述过程重复8次，完成一个字节的传输。由于是全双工，这8个时钟周期内，主设备在向从设备发送一个字节的同时，也从从设备那里接收到了一个字节。

4.  **结束通信**：
    *   8位数据全部传输完毕后，主设备将**SCLK**时钟恢复为空闲状态（对于Mode 0是低电平），并将**CS**信号拉高（无效），结束本次通信。

## 6、为什么”发“容易“收”却难？

| 协议       | 你的理解           | **微调/补充细节**                                            |
| ---------- | ------------------ | ------------------------------------------------------------ |
| **SPI**    | 同一时刻一发一收   | **物理上**：若 CS 并联，主机发 (MOSI) 时，**所有从机都能收到**。 **限制**：从机不能同时回 (MISO)，否则短路。所以**逻辑上**当一发一收用。 |
| **I2C**    | 有广播，但一发一收 | **物理上**：天生广播，所有从机都能听到地址和数据。 **限制**：广播写 (Master→Slaves) **可以一发多收**；但只要有**回复 (ACK/Data)**，就必须变成一发一收，否则总线冲突。 |
| **Modbus** | 可以一发多收       | **完全正确**。协议规定广播地址 (0) 时从机**禁止回复**，完美实现一发多收。 |

🎯 终极总结：总线通信的“单行道”法则

你可以用这个模型来记忆：

1. 下行通道（主机→从机）：
   - **SPI/I2C/Modbus** 都**支持**“一发多收”（物理信号所有从机都能听到）。
   - 只要从机不需要回复，就可以广播。
2. 上行通道（从机→主机）：
   - **SPI**：靠 **CS 片选** 物理隔离（一次只选一个说话）。
   - **I2C**：靠 **地址寻址 + 仲裁** 逻辑隔离（一次只让一个说话）。
   - **Modbus**：靠 **协议规定** 时间隔离（广播时不许说话，单播时轮流说话）。

> 💡 **一句话口诀**： **“广播容易回复难，要想不发冲突险，要么闭嘴（Modbus），要么片选（SPI），要么排队（I2C）。”**

> [!IMPORTANT]
>
> 注意不同`IIC`设备操作数据流程有些许不同，但是通用读写时序是相通的。
