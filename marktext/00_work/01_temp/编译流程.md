# Astra Soul0 项目编译原理详解

## 一、整体架构：SDK 模式

这个项目采用 **SDK (Software Development Kit) 架构**，分为两个独立的构建阶段：

```
┌─────────────────────────────────────────────────────────────┐
│  Phase 1: 构建内核库 (libos_kernel.a)                        │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  build_zynq7020.sh → build.sh → cmake configure    │    │
│  │  → 编译所有内核源码 → 生成 starheart.elf           │    │
│  │  → cmake --install → 复制到 out/sdk/               │    │
│  └─────────────────────────────────────────────────────┘    │
│                          ↓                                  │
│  Phase 2: 构建用户应用 (test.elf)                           │
│  ┌─────────────────────────────────────────────────────┐    │
│  │  out/sdk/demo/build.sh → cmake configure           │    │
│  │  → 编译用户代码 → 链接 libos_kernel.a              │    │
│  │  → 生成 test.elf                                   │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

## 二、Phase 1 详细流程

### 入口：`./build_zynq7020.sh`

```bash
#!/bin/bash

if [ "$1" = "-s" ]; then
 ./build.sh -s macro_defconfig
 exit 0
fi

if [ ! $ARM_GCC ]; then
export ARM_GCC=/opt/arm-gcc-15/arm-gnu-toolchain-15.2.rel1-x86_64-arm-none-eabi/bin
fi

if [ -f .config ]; then
./build.sh                          # 无参数 = 直接构建
else
./build.sh -b zynq7020 macro_defconfig  # 首次构建：选择BSP + 加载配置
fi

if [ $? -eq 0 ]; then
cmake --install out/zynq7020_Debug --prefix ./out/sdk    # 安装到SDK目录
fi
```

### 执行步骤：

**步骤 1：选择 BSP 和配置**
```bash
./build.sh -b zynq7020 macro_defconfig
```

这会调用 `cmd_build_select()`，执行以下操作：
1. 创建 `out/platform_config` 文件，记录 `bsp=zynq7020` 和 `build_type=Debug`
2. 从 `bsp/zynq7020/config/macro_defconfig` 加载配置
3. 运行 `defconfig.py` 生成 `.config`
4. 运行 `genconfig.py` 生成 `out/zynq7020_config/srh_config.h`
5. 自动调用 `cmd_build()` 进入下一步

**步骤 2：CMake 配置和构建**
```bash
cmake -S "$ROOT_DIR" -B "$BUILD_DIR" \
    -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \    # ← 生成 compile_commands.json
    -DSELECT_BSP="$BSP_NAME" \
    -DCMAKE_BUILD_TYPE="$BUILD_TYPE" \
    -G "Ninja"

cmake --build "$BUILD_DIR"
```

构建目录：`out/zynq7020_Debug/`

**步骤 3：安装到 SDK 目录**
```bash
cmake --install out/zynq7020_Debug --prefix ./out/sdk
```

根据 `CMakeLists.txt` 中的 `install()` 指令：
- `libos_kernel.a` → `out/sdk/lib/`
- 头文件 → `out/sdk/include/`
- demo 模板 → `out/sdk/demo/`
- 链接脚本和工具链文件 → `out/sdk/demo/`

## 三、Phase 2 详细流程

### 入口：`out/sdk/demo/build.sh`

```bash
#!/bin/bash

SCRIPT_PATH=$(dirname $(realpath $BASH_SOURCE))
export ARM_GCC=/opt/arm-gcc-15/arm-gnu-toolchain-15.2.rel1-x86_64-arm-none-eabi/bin
cmake -S . -B ./build -DCMAKE_BUILD_TYPE=Debug -G "Ninja"
cmake --build build
```

### 执行步骤：

**步骤 1：CMake 配置**
```bash
cmake -S . -B ./build -DCMAKE_BUILD_TYPE=Debug -G "Ninja"
```

`out/sdk/demo/CMakeLists.txt` 的关键内容：
```cmake
set(LD_SCRIPT "${CMAKE_SOURCE_DIR}/link.lds")           # 使用 Phase 1 安装的链接脚本
set(CMAKE_TOOLCHAIN_FILE "${CMAKE_CURRENT_LIST_DIR}/toolchain.cmake")  # 使用 Phase 1 安装的工具链

include_directories(../include ../include/posix/include)  # 引用 Phase 1 安装的头文件
link_directories(../lib)                                   # 引用 Phase 1 安装的库

add_executable(${project_name} ${file_src})

target_link_libraries(${project_name} PRIVATE os_kernel gcov gcc)  # 链接 libos_kernel.a
```

**步骤 2：构建**
```bash
cmake --build build
```

构建目录：`out/sdk/demo/build/`

最终生成：`out/sdk/demo/build/test.elf`

## 四、为什么是两步？

### 设计理念：SDK 分离

这是一个**嵌入式 RTOS 项目**，采用 SDK 架构的原因：

1. **内核与应用分离**
   - Phase 1 编译完整的内核（包含启动代码、调度器、内存管理、驱动等）
   - Phase 2 只编译用户的应用代码

2. **支持多种应用场景**
   - 内核库 `libos_kernel.a` 可以被多个不同的用户应用共享
   - 用户不需要重新编译内核，只需链接库文件

3. **便于分发**
   - SDK 目录 (`out/sdk/`) 可以独立打包分发给开发者
   - 开发者只需要 `out/sdk/` 就可以开发自己的应用

4. **简化用户开发流程**
   - 用户只需关注自己的代码（`out/sdk/demo/src/`）
   - 不需要了解内核的构建细节

## 五、compile_commands.json 详解

### 1. 生成位置

`compile_commands.json` 位于 `out/zynq7020_Debug/`

### 2. 生成原因

在 `build.sh` 的 `cmd_build()` 和 `cmd_build_target()` 函数中：

```bash
cmake -S "$ROOT_DIR" -B "$BUILD_DIR" \
    -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \    # ← 这个标志启用生成
    -DSELECT_BSP="$BSP_NAME" \
    -DCMAKE_BUILD_TYPE="$BUILD_TYPE" \
    -G "Ninja"
```

`-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` 告诉 CMake 在配置阶段生成这个文件。

### 3. 文件内容

这是一个 JSON 数组，包含每个源文件的编译命令：

```json
[
  {
    "directory": "/home/shuqi/repo/astra_soul0/out/zynq7020_Debug",
    "command": "/opt/arm-gcc-15/.../arm-none-eabi-gcc -DZYNC_QEMU -I... -mcpu=cortex-a9 ... -c /home/shuqi/repo/astra_soul0/components/gcov/gcc_base.c",
    "file": "/home/shuqi/repo/astra_soul0/components/gcov/gcc_base.c",
    "output": ".../components/gcov/CMakeFiles/gcov.dir/gcc_base.c.obj"
  },
  ...
]
```

每个条目包含：
- `directory`: 构建目录
- `command`: 完整的编译命令（包括所有 `-I` 头文件路径、`-D` 宏定义、编译选项）
- `file`: 源文件的绝对路径
- `output`: 目标文件的路径

### 4. 作用和用途

**用于 IDE/编辑器的代码智能提示：**

- **VS Code** + C/C++ 扩展 / clangd 扩展
- **CLion** / **Qt Creator**
- **Vim/Neovim** + coc.nvim / LSP 插件
- **Emacs** + lsp-mode

这些工具读取 `compile_commands.json` 来：
1. 提供准确的**代码补全**（知道所有头文件路径）
2. 支持**跳转到定义**（知道宏定义和条件编译）
3. 显示**实时错误和警告**（使用正确的编译选项）
4. 支持**重构和查找引用**

### 5. 为什么只在 `out/zynq7020_Debug/` 有？

因为：
1. Phase 1 的构建目录是 `out/zynq7020_Debug/`，CMake 在这里生成了 `compile_commands.json`
2. Phase 2 的构建目录是 `out/sdk/demo/build/`，但 `out/sdk/demo/build.sh` **没有** 添加 `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` 标志

如果你也想为 Phase 2 生成 `compile_commands.json`，需要修改 `out/sdk/demo/build.sh`：

```bash
cmake -S . -B ./build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -G "Ninja"
```

## 七、常见操作

### 完整构建流程
```bash
# 1. 首次构建（选择BSP + 构建内核 + 安装SDK）
./build_zynq7020.sh

# 2. 构建用户应用
cd out/sdk/demo
./build.sh

# 3. 运行（如果使用 QEMU）
./qemu_srh_zynq7020.sh
```

### 修改配置后重新构建
```bash
# 修改内核配置
./build.sh -m          # 打开 menuconfig
./build_zynq7020.sh    # 重新构建内核

# 重新构建用户应用
cd out/sdk/demo
./build.sh
```

### 清理
```bash
./build.sh -c          # 清理当前构建
./build.sh -c -a       # 清理所有构建
```

## 八、compile_commands.json 的实际使用

### 方法 1：软链接到项目根目录（推荐）

```bash
# 在项目根目录创建软链接
ln -sf out/zynq7020_Debug/compile_commands.json .
```

然后 IDE 会在项目根目录找到这个文件，支持整个项目的代码智能提示。

### 方法 2：配置 IDE 指定路径

在 VS Code 的 `.vscode/settings.json` 中：
```json
{
    "C_Cpp.default.compileCommands": "${workspaceFolder}/out/zynq7020_Debug/compile_commands.json"
}
```

### 方法 3：使用 bear 工具（如果需要 Phase 2 的 compile_commands）

```bash
cd out/sdk/demo
bear -- ./build.sh
# 会在 out/sdk/demo/ 目录生成 compile_commands.json
```

## 九、总结

| 特性 | Phase 1 | Phase 2 |
|------|---------|---------|
| 入口脚本 | `build_zynq7020.sh` | `out/sdk/demo/build.sh` |
| 构建目录 | `out/zynq7020_Debug/` | `out/sdk/demo/build/` |
| 输出产物 | `libos_kernel.a` + `starheart.elf` | `test.elf` |
| compile_commands.json | ✅ 有（`-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`） | ❌ 没有（需手动添加标志） |
| 目的 | 构建完整的内核 SDK | 构建用户应用 |
