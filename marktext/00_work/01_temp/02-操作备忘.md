7.17

./qemu...无法执行的情况

方案 1：给 qemu 二进制永久赋权（推荐，不用新建组、不用 sudo）原理：给 qemu-system-arm 附加 CAP_NET_ADMIN 权限，普通用户可操作 tap/tun，重启、更新 qemu 后需要重新执行一次。bash运行# 赋权
sudo setcap cap_net_admin=eip /usr/bin/qemu-system-arm

# 验证权限是否生效

getcap /usr/bin/qemu-system-arm
输出带 cap_net_admin=eip 就成功，直接正常执行你的 qemu 命令，不会报权限。

# 问题根源

你的当前内核 `6.18.34-1-lts` 对应的内核模块包缺失，`tun` 驱动内置在内核模块包里，没装就找不到模块文件。

## 1. 安装匹配内核的模块包（Arch LTS内核）

```
sudo pacman -S linux-lts linux-lts-headers
```

安装完成后重启系统：

```
reboot
```

## 2. 重启后验证模块

开机重新登录，执行：

```
ls /lib/modules/$(uname -r)/kernel/drivers/net/tun/
```

能看到 `tun.ko.zst` 代表驱动文件存在。
再加载模块：

```
sudo modprobe tun
ls /dev/net/tun
```

此时 `/dev/net/tun` 设备文件会出现。

## 3. 设置开机自动加载tun（永久）

```
echo "tun" | sudo tee /etc/modules-load.d/tun.conf
```

## 4. 确认QEMU权限（你已经配好，不用重复）

```
getcap /usr/bin/qemu-system-arm
# 输出 cap_net_admin=eip 正常
```

之后直接运行脚本：

```
./qemu_srh_zynq7020.sh
```

# 补充排查

1. 如果你同时装了 linux 和 linux-lts，确认 grub 默认启动的是 linux-lts，不要进错内核；
2. 若刚更新内核未重启，`/lib/modules` 目录版本不匹配也会报模块找不到，重启即可修复；
3. 极简总结：内核模块包丢失 → 重装 `linux-lts` + 重启。
