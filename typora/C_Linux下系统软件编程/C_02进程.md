## 1.什么是进程？

- 程序的一次执行过程（正在运行的程序），包括创建、调度、消亡。是动态的。


- 程序：一段数据的集合。静态的。

进程实体 = 栈区（`.stack`）+堆区（`.heap`）+`.BSS`+`.Data`+文本段(`text段`)+  `PCB(Process Control Block)`进程控制块

- 文本段

  - 存储函数、代码和指令

- 数据段

  - 在编译时分配空间，程序运行时，将`a.out`数据段从硬盘加载到内存数据段中
  - 程序结束回收空间
  - **未显式初始化的值为自动初始化为0值**

- 系统数据段

  - 栈区（操作系统自动管理区域）：

    存放局部变量、执行到变量定义时分配空间，超过变量作用域回收变量空间，**未经初始化为随机值**

  - 堆区（程序序员管理的区域）：`malloc`申请、`free`释放

- 内核

  - 操作系统核心区域，用户无法访问。

    负责:

    - 内存管理、
    - 设备管理、
    - 文件系统管理、
    - 进程调度、
    - 进程间通信、

- 物理地址/虚拟地址

  - 物理地址：内存真实的硬件地址，对应RAM的大小，进程无法直接操作。
  - 虚拟地址：进程视角看到的"逻辑地址"，通过（`MMU`+页表）转换后访问物理地址。
  - 优点：
    - 内存隔离：
      - 不同进程之间内存隔离，防止干扰，提高操作系统的稳定性和安全性

    - 内存复用
      - 虚拟地址内存可以大于物理地址内存

    - 共享内存
      - 不同进程的虚拟地址映射到同一块物理地址，实现共享内存

    - 进程调度：

## 3.进程的状态有哪些？

1.  *R    `running or runnable (on run queue)`；就绪态+执行态
2.  *S    `interruptible sleep (waiting for an event to complete)`；可唤醒等待态
3. *D    `uninterruptible sleep (usually IO) `；不可唤醒等待态
4.  *T    `stopped by job control signal`；暂停态
5.  *Z    `defunct ("zombie") process, terminated but not reaped by its parent`  ；僵尸态
6.   X    `dead (should never be seen)`；结束态

##  4.进程的常用命令有哪些？

1. `top`（动态查看系统中进程 --类似 windows下任务管理器）
   - `PPID父进程ID`
   - `PID子进程ID`
   - cpu占用率
   - cpu该进程启动时间
   - 物理内存/虚拟内存
2. `ps -elf | grep a.out `
   - 显示所有进程，侧重进程关系和状态
   
   - `PID/PPID`号
3. `ps -aux | grep a.out`
   - 查看进程状态信息，侧重进程资源占用情况
4. `pstree -sp [pid]`
   - 查看所有进程的关系（进程树）
5. `kill `  发信号
   - `kill -l `  查看可发送的信号
     - `18-SIGCONT `//继续 
       - `19-SIGSTOP` //暂停 
        - `9-SIGKILL `//杀死进程
   - `kill -19 [pid]` //给指定的进程发送 信号

#### 4.`waitpid`函数：

```c
pid_t waitpid(pid_t pid, int *wstatus, int options);	
功能:
	等待子进程状态改变

	 @pid
```

### 5.僵尸进程、孤儿进程为何产生？

```c
人造僵尸态：
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <stdlib.h>

int main(void)
{
	pid_t pid = fork();

	if (pid < 0)
	{
		perror("fork fail");
		return -1;
	}

	if (pid > 0)
	{
		sleep(10);
		printf("---wait----child---\n");
		wait(NULL);

	}else if (pid == 0)
	{
		printf("---child----exit---\n");
		exit(99);
	}

	return 0;
}

```

#### 1.僵尸进程：子进程死了，但父进程还活着，却没去收尸 → 子进程变成僵尸

```
产生：先杀死子进程，观察父进程状态 
1.子进程结束，但父进程，没有对子进程收尸 
	(僵尸态是有危害的，占用PID资源+进程表项+消耗内存 )
2.父进程没有对子进程进行资源回收
避免：
1.父进程先结束，子进程称为孤儿进程，被init进程收养，子进程结束时，init进程回收子进程空间。
2.子进程结束，父进程回收子进程空间（wait或者waitpid回收子进程空间）
```

#### 2.孤儿进程：**父进程先死了，子进程还活着** → 子进程变成**孤儿进程**。

```
变成后台进程，`ctrl + c `这个信号只能发给前台进程，对孤儿进程无效。
```
