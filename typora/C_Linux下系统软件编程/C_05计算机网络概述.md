## 一、国际网络体系结构

### 1.`OSI`七层模型：open system interconnect（理论模型）
```
📅 1977年 | 国际标准化组织(ISO)提出
🎯 目标：实现不同体系结构的计算机在全球范围内互联
```

| 层级 | 名称           | 核心功能                                 | 典型设备/协议            | 数据单位      |
| ---- | -------------- | ---------------------------------------- | ------------------------ | ------------- |
| 7    | **应用层**     | 为用户提供网络服务接口，处理业务数据     | `HTTP/FTP/SMTP/MQTT`     | 报文          |
| 6    | **表示层**     | 数据格式转换、加密/解密、压缩/解压缩     | `SSL/TLS、JPEG、ASCII`   | 报文          |
| 5    | **会话层**     | 建立、管理、终止会话连接                 | `RPC、NFS`               | 报文          |
| 4    | **传输层**     | 端到端传输、流量控制、差错恢复           | `TCP/UDP + 端口号`       | 段/报文       |
| 3    | **网络层**     | 路由选择、逻辑寻址、分组转发             | **`IP`**、路由器、`ICMP` | 数据包        |
| 2    | **数据链路层** | 封装成帧、物理寻址、差错检测、局域网通信 | **交换机**、`ARP`、`MAC` | 帧            |
| 1    | **物理层**     | 定义电气/机械/功能规范，传输原始比特流   | 网线、光纤、集线器       | **比特**(bit) |

> 💡 **记忆口诀**：物数网传会表应（从下到上）

### 1.2 `TCP/IP`模型（工业事实标准）

#### 🔹 四层模型
```C
┌─────────────────┐
│   应用层        	│ ← HTTP/HTTPS/MQTT/FTP/TFTP/DNS
├─────────────────┤
│   传输层       	│ ← TCP / UDP + 端口号
├─────────────────┤
│   网络层       	│ ← IP / ICMP / ARP
├─────────────────┤
│ 	网络接口层     │ ← 物理媒介 + 链路协议 (以太网/WiFi)
└─────────────────┘
```

#### 🔹 五层混合模型（教学常用）
```
┌─────────────────┐
│   应用层        	│ ← HTTP/MQTT
├─────────────────┤
│   传输层        	│ ← TCP/UDP
├─────────────────┤
│   网络层        	│ ← IP
├─────────────────┤
│  	数据链路层      │ ← 帧封装、MAC、交换机
├─────────────────┤
│   物理层         │ ← 比特流传输
└─────────────────┘
```

> ✅ **嵌入式开发重点**：掌握五层模型，理解数据在各层的封装/解封装过程

## 二、核心协议详解

### 2.1 应用层协议
| 协议    | 全称               | 端口      | 功能特点                    | 嵌入式应用场景             |
| ------- | ------------------ | --------- | --------------------------- | -------------------------- |
| `HTTP`  | 超文本传输协议     | 80        | 明文传输、请求/响应模式     | Web服务器、REST API        |
| `HTTPS` | 加密超文本传输协议 | 443       | `SSL/TLS`加密、安全可靠     | 物联网云平台通信           |
| `MQTT`  | 消息队列遥测传输   | 1883/8883 | 发布/订阅、低功耗、弱网友好 | 🎯 物联网设备上报、远程控制 |
| `FTP`   | 文件传输协议       | 20/21     | 双通道、支持断点续传        | 固件升级、日志上传         |
| `TFTP`  | 简单文件传输协议   | 69        | `UDP`基础、无认证、轻量     | U-Boot下载内核、嵌入式引导 |

> 🔥 **`MQTT`优势**（嵌入式首选）
> - 头部开销小（最小2字节）
> - 支持`QoS`质量等级（0/1/2）
> - 保持心跳、断线重连
> - 主题订阅机制，解耦收发双方

---

### 2.2 传输层协议对比

| 特性     | `TCP`                       | `UDP`                           |
| -------- | --------------------------- | ------------------------------- |
| 连接方式 | 面向连接（三次握手）        | 无连接                          |
| 可靠性   | ✅ 保证送达、顺序、重传      | ❌ 尽最大努力交付                |
| 传输效率 | 较低（头部20字节+控制开销） | 高（头部8字节）                 |
| 流量控制 | ✅ 滑动窗口、拥塞控制        | ❌ 无                            |
| 应用场景 | 文件传输、Web、SSH          | 视频流、`DNS`、嵌入式传感器上报 |

```c
// 嵌入式Socket编程选择建议：
// 🔹 要求可靠 → TCP (recv/send + 错误处理)
// 🔹 实时性优先 + 允许丢包 → UDP (sendto/recvfrom)
// 🔹 资源受限设备 → 优先考虑UDP + 应用层重传机制
```

## 三、网络层：`IP`地址与子网划分

### 3.1 `IP`地址基础
```
📌 IPv4：32位 = 4字节 → 点分十进制表示
     例：192.168.1.128
     二进制：11000000.10101000.00000001.10000000

📌 IPv6：128位 → 冒号十六进制（嵌入式逐步支持中）
```

#### 🔹 `IP`地址结构：`网络位 + 主机位`
```
192.168.1.121/24
         │
         └─ /24 表示前24位为网络位，后8位为主机位
```

| 组成部分   | 作用                   | 示例        |
| ---------- | ---------------------- | ----------- |
| **网络位** | 标识所属网段（局域网） | 192.168.1.0 |
| **主机位** | 标识网段内具体设备     | 0.0.0.121   |

---

### 3.2 子网掩码（Subnet Mask）
```
🎯 作用：区分IP地址中的网络位和主机位
🔧 规则：掩码为1 → 对应网络位；掩码为0 → 对应主机位
```

| 表示方式      | 二进制                              | 对应网络位 |
| ------------- | ----------------------------------- | ---------- |
| 255.255.255.0 | 11111111.11111111.11111111.00000000 | /24        |
| 255.255.0.0   | 11111111.11111111.00000000.00000000 | /16        |
| 255.0.0.0     | 11111111.00000000.00000000.00000000 | /8         |

#### 🔹 关键地址计算（以 `192.168.1.121/24` 为例）
```bash
IP地址：   192.168.1.121
子网掩码：  255.255.255.0
--------------------------------
✅ 网段号：  192.168.1.0    ← 主机位全0（网络标识）
✅ 广播地址：192.168.1.255  ← 主机位全1（局域网广播）
✅ 可用主机：192.168.1.1 ~ 192.168.1.254（共254台）
✅ 网关：   通常为 192.168.1.1（路由器接口）
```

> ⚠️ **注意**：网段内主机可直接通信；跨网段通信必须经过**网关**转发

---

### 3.3 `IP`地址分类与私有地址

| 类别    | 地址范围                    | 默认掩码      | 主机数  | 私有地址段       | 应用场景                 |
| ------- | --------------------------- | ------------- | ------- | ---------------- | ------------------------ |
| **A类** | 1.0.0.0 ~ 126.255.255.255   | 255.0.0.0     | 1677万+ | `10.0.0.0/8`     | 大型网络、运营商         |
| **B类** | 128.0.0.0 ~ 191.255.255.255 | 255.255.0.0   | 6.5万+  | `172.16.0.0/12`  | 企业网、校园网           |
| **C类** | 192.0.0.0 ~ 223.255.255.255 | 255.255.255.0 | 254     | `192.168.0.0/16` | 🎯 嵌入式/家庭/小局域网   |
| **D类** | 224.0.0.0 ~ 239.255.255.255 | -             | -       | -                | 组播（视频流、设备发现） |
| **E类** | 240.0.0.0 ~ 255.255.255.254 | -             | -       | -                | 实验保留                 |

#### 🔹 特殊地址
```
🔁 127.0.0.1      → 回环地址（本机测试，不经过物理网卡）
🌐 0.0.0.0        → 默认路由/监听所有接口
📢 255.255.255.255 → 受限广播（仅本网段）
```

#### 🔹 公有`IP` vs 私有`IP`
| 类型     | 特点                       | 能否直连Internet | 嵌入式建议                    |
| -------- | -------------------------- | ---------------- | ----------------------------- |
| 公有`IP` | 全球唯一、运营商分配、付费 | ✅ 能             | 云服务器、公网设备            |
| 私有`IP` | 局域网内唯一、可重复使用   | ❌ 需NAT转换      | 🎯 嵌入式设备首选（安全+节省） |

> 💡 **嵌入式实践**：开发板通常使用 `192.168.1.100/24` 这类C类私有地址，通过路由器NAT访问外网

---

### 3.4 端口号（Port）
```
📏 16位无符号整数 → 范围：0 ~ 65535
🎯 作用：唯一标识主机上的一个应用进程（IP找主机，Port找进程）
```

#### 🔹 端口分类
| 范围            | 名称                     | 说明                     | 示例                      |
| --------------- | ------------------------ | ------------------------ | ------------------------- |
| **0~1023**      | 熟知端口（Well-Known）   | `IANA`分配，系统服务专用 | `HTTP:80, SSH:22, DNS:53` |
| **1024~49151**  | 被注册端口（Registered） | 用户进程注册使用         | `MySQL:3306, Redis:6379`  |
| **49152~65535** | 动态/私有端口            | 临时分配给客户端连接     | Socket编程时OS自动分配    |

```c
// Socket编程关键：
// 服务器：绑定固定端口（如8888）→ bind()
// 客户端：可让系统分配临时端口 → connect()时不指定port
// 通信标识：(源IP:源Port) ↔ (目的IP:目的Port) 四元组唯一确定连接
```

> ✅ **嵌入式端口规划建议**：
> - 自定义服务使用 `5000~6000` 范围，避免冲突
> - `MQTT`用1883，`HTTP`用8080（避免与系统服务冲突）
> - 多实例测试时用不同端口区分

## 四、数据封装与传输流程

![image-20260328214857706](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_01-21_2c669a7bc0d02eaa5d85968a19522c79.png)

### 4.1 `TCP/IP`封包过程（发送方）
```
应用数据 
   ↓
[应用层] + TCP/UDP头部 → 段（Segment）
   ↓
[网络层] + IP头部 → 数据包（Packet） 
   ↓
[数据链路层] + 帧头帧尾 + MAC地址 → 帧（Frame）
   ↓
[物理层] → 比特流（0/1电信号/光信号）→ 网线/无线传输
```

### 4.2 拆包过程（接收方）
```
比特流 → 帧 → 数据包 → 段 → 应用数据
   ↑        ↑         ↑      ↑
校验帧头  查IP目的  查端口  交给对应进程
丢弃非本机  路由判断  分发Socket
```

> 🔍 **嵌入式调试技巧**：
> ```bash
> # 抓包分析各层头部
> sudo tcpdump -i eth0 -nn -X port 8888
> 
> # 查看内核协议栈统计
> netstat -s | grep -E "Tcp|Udp|Ip"
> ```

## 五、嵌入式网络配置实战（Linux）

### 5.1 基础网络调试命令
```bash
# 🔹 1. 连通性测试
ping 192.168.1.1          # 测试网关
ping www.baidu.com        # 测试DNS+外网（域名→IP解析）

# 🔹 2. 查看网卡配置
ifconfig                  # 传统命令（部分系统需net-tools）
ip addr show              # 推荐（iproute2工具包）

# 输出关键字段解读：
# lo 127.0.0.1 				→ 回环地址
# inet 192.168.1.100  → IPv4地址
# netmask 255.255.255.0 → 子网掩码
# broadcast 192.168.1.255 → 广播地址
# ether xx:xx:xx:xx:xx:xx → MAC地址（物理地址，全球唯一）

# 🔹 3. 路由表查看
route -n                  # 或 ip route show
# 关注 default via 192.168.1.1 → 默认网关

# 🔹 4. DNS配置
cat /etc/resolv.conf      # 查看DNS服务器
nameserver 8.8.8.8        # Google公共DNS
```

---

### 5.2 虚拟机网络配置（以VMware+Ubuntu为例）

#### 🔸 步骤1：设置桥接模式
```
虚拟机设置 → 网络适配器 → 桥接模式 → 勾选"复制物理网络连接状态"
```

#### 🔸 步骤2：配置虚拟网络编辑器（关键！）
```
编辑 → 虚拟网络编辑器 → 更改设置（管理员权限）
→ 选择VMnet0（桥接模式） 
→ "桥接到": 选择宿主机实际联网的网卡（⚠️ 无线网卡需特别注意驱动支持）
```

#### 🔸 步骤3：配置静态`IP`（推荐嵌入式开发使用）
```bash
# 编辑网卡配置文件（Ubuntu 16.04及之前）
sudo vi /etc/network/interfaces

# 添加/修改内容：
auto lo
iface lo inet loopback

auto ens33                # 网卡名通过 ifconfig 查看
iface ens33 inet static   # 静态配置（开发调试更稳定）
无=这一部分
=============================   
address 192.168.1.100
netmask 255.255.255.0
gateway 192.168.1.1
dns-nameservers 8.8.8.8 114.114.114.114
========================================
# 或 DHCP自动获取（生产环境常用）：
# iface ens33 inet dhcp

# 重启网络服务
sudo /etc/init.d/networking restart
# 或（新系统）：
sudo systemctl restart networking
```

#### 🔸 步骤4：验证配置
```bash
ifconfig ens33            # 确认IP是否生效
ping 192.168.1.1          # 测试网关
ping 8.8.8.8              # 测试外网IP
ping www.baidu.com        # 测试DNS解析
```

> ⚠️ **常见问题排查**：
> ```
> ❌ ping不通网关 → 检查子网掩码/虚拟机桥接网卡选择
> ❌ 能ping IP但不能ping域名 → 检查 /etc/resolv.conf DNS配置
> ❌ 重启后配置丢失 → 确认是否修改了正确配置文件（Netplan/NetworkManager需单独配置）
> ```

## 六、嵌入式网络开发要点总结

```mermaid
graph LR
A[嵌入式设备] --> B[物理层：网线/WiFi/4G模块]
B --> C[数据链路层：MAC驱动 + ARP]
C --> D[网络层：IP配置 + 路由]
D --> E[传输层：TCP/UDP Socket编程]
E --> F[应用层：MQTT/HTTP/自定义协议]
F --> G[云平台/手机APP/其他设备]
```

### ✅ 关键能力要求
1. **理解分层思想**：能定位问题在哪一层（物理？链路？IP？端口？应用？）
2. **熟练配置网络**：静态IP、网关、DNS、防火墙（iptables）基础
3. **掌握Socket编程**：TCP/UDP服务端/客户端模型、非阻塞IO、多路复用
4. **协议选型能力**：根据场景选MQTT（物联网）/HTTP（Web）/自定义二进制（高效）
5. **调试排查能力**：`tcpdump`/`wireshark`抓包分析、`netstat`连接状态监控

### 🛠️ 推荐工具链
```bash
# 网络诊断
ping / traceroute / netstat / ss / ip / ethtool

# 抓包分析
tcpdump -i any -w capture.pcap    # 命令行抓包
wireshark capture.pcap            # GUI深度分析

# 服务测试
nc -lvvp 8888                     # 简易TCP服务器
echo "hello" | nc -u 192.168.1.100 69  # UDP测试

# 嵌入式交叉编译
arm-linux-gnueabihf-gcc socket_client.c -o client
```
