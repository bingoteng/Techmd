## 一、函数

### 1.1 什么是函数？

- **函数**就是**功能**，每一个函数实现一个特定功能。(Function翻译过来就是函数/功能）
- 作用（为什么需要函数？）：
  - **实现代码复用**：避免重复编写相同逻辑的代码。
  - **实现模块化程序设计**：将复杂问题分解为多个小任务。
  - **提高可读性与可维护性**。
- 每个 C 程序至少包含一个主函数：`main()`。

> 💡 函数在编译后对应一段位于 **代码段（Text Segment）** 的机器指令。

### 1.7 不同类型函数传参

| 递方式       | 传递的内容         | 函数内操作               | 对实参的影响     |
| :----------- | :----------------- | :----------------------- | :--------------- |
| **值传递**   | 变量的**数据副本** | 修改副本                 | ❌ 不影响原变量   |
| **地址传递** | 变量**地址的副本** | 解引用修改地址指向的内容 | ✅ **修改原变量** |

```c
//1.值传递
	1.单向传递(实参->形参)
    2.实参、形参是两个不同的内存单元
    3.形参拿到的是实参的副本
//2.址传递(指针传递)
    同一区域
	本质还是值传递，只不过是这个值是地址副本。
//3.一维数组传参(一维数组+一级指针)
//4.二维数组传参(二维数组+数组指针)
//5.指针数组传参(指针数组+二级指针)
✅❗数组作为函数参数中->退化含义指的是:数组丢失了它的长度信息无法再用sizeof(arr)获得数组的大小，实际得到的是指针的大小，此时数组名是指向首元素的指针&arr/&arr[0]。
✅❗二维数组传参时int arr[3][10]  等价于  int  arr [][10] 第一维度可以省略但是高维省略
```

> [!NOTE]
>
> 1. **第一次退化（数组→指针）**：二维数组名 `a` 本质上是 **“数组的数组”**。作为参数时，它首先退化为一个 **“指向其首元素”** 的指针。而它的首元素是一个 **一维数组** `int [4]`。
> 2. 数组的数组理解->`a`是由三个 `int [4]` 型元素组成的数组。
> 3. 因此，`a` 退化为：**指向一维数组 `int [4]` 的指针**，即 `int (*)[4]` 类型。
> 4. **为什么能省略行数？** 因为编译器此时只关心这个指针**每次走多远**（即一维数组的大小 `4 * sizeof(int)`），而不关心起点到终点一共有多少行。行数信息由你通过其他方式（如额外参数）传递。
> 5. **为什么不能省略列数？** 列数 `4` 决定了指针算术运算的 **步长**。没有它，编译器无法计算出 `a+1` 应该跳过多少字节。

| 特性         | `malloc`                                        | `calloc`                                               | `realloc`                                                   |
| :----------- | :---------------------------------------------- | :----------------------------------------------------- | :---------------------------------------------------------- |
| **函数原型** | `void* malloc(size_t size)`                     | `void* calloc(size_t num, size_t size)`                | `void* realloc(void *ptr, size_t new_size)`                 |
| **功能**     | 分配指定字节数的内存                            | 分配指定数量×大小的内存                                | 调整已分配内存块的大小                                      |
| **初始化**   | ❌ **不初始化**（垃圾值）                        | ✅ **自动清零**（所有位为0）                            | ⚠️ **部分保留**（新内存区域未定义）                          |
| **参数**     | 1个：总字节数                                   | 2个：元素个数 × 元素大小                               | 2个：原指针 + 新字节数                                      |
| **返回值**   | 成功：指向分配内存的指针 失败：NULL             | 同`malloc`                                             | 成功：指向新内存的指针（可能改变） 失败：NULL（原内存不变） |
| **内存内容** | 未定义（随机值）                                | 全0（二进制0）                                         | 原数据保留到min(原大小,新大小) 超出部分未定义               |
| **性能**     | 🚀 较快（不初始化）                              | 🐢 较慢（需要清零）                                     | 🔄 中等（可能需要移动数据）                                  |
| **内存碎片** | 可能产生                                        | 可能产生                                               | 可能减少或增加                                              |
| **适用场景** | 1. 立即填充全部数据 2. 性能敏感 3. 不需要默认值 | 1. 需要零初始化的数组 2. 结构体默认值 3. 布尔/状态标志 | 1. 动态数组扩容/缩容 2. 缓冲池调整 3. 内存重用              |
| **失败处理** | 返回NULL                                        | 返回NULL                                               | 返回NULL，**原指针仍有效**                                  |
| **释放要求** | 必须free                                        | 必须free                                               | 必须free（新指针）                                          |

## 三、变量的相关概念❗

### 3.1 变量的作用域和生存周期

- **作用域**（决定变量能不能**访问**）❗**空间维度**：变量定义后，**可见/可被访问**的区域

- **生命周期**（决定变量**存在**多久）❗**时间维度**：变量从创建（开辟内存空间）到销毁（释放内存空间）的**实际存在**时间段。

### 3.2 变量的存储类型

C 语言提供四种存储类型说明符：

|   关键字   |                     含义                     |     默认位置     | 生命周期 |             作用域             |
| :--------: | :------------------------------------------: | :--------------: | :------: | :----------------------------: |
|   `auto`   |                   自动存储                   |     栈Stack      |   块内   |              块内              |
|  `static`  |                   静态存储                   | 数据段`Data/BSS` | 整个程序 | 文件内（全局）或函数内（局部） |
|  `extern`  |           外部存储（声明外部链接）           |    `Data/BSS`    | 整个程序 |            整个工程            |
| `register` | **建议**寄存器存储（现代编译器几乎完全忽略） | 寄存器（若可用） |   块内   |              块内              |

> ⚠️ 注意：
>
> - 书写格式： 存储类型 数据类型 变量名;  (static  int x;)
>
> - `register` 不能取地址（`&x` 非法）。建议不要使用`register` 
>
> - extern的典型用法：`conifg.h` 里extern外部声明 *`config.c`* 里实际定义
>
>   ```c
>   // config.h - 头文件
>   #ifndef CONFIG_H
>   #define CONFIG_H
>
>   extern int MAX_USERS;			// 声明，不分配内存
>   extern const char* APP_NAME;	// 声明常量
>   extern void Print();			//声明函数，不加extern理论上也可以但是保持代码风格清晰
>
>   #endif
>   ```
>
>   ```c
>    // config.c - 实现文件
>   #include "config.h"
>   int MAX_USERS = 1000;      // 实际定义，分配内存
>   const char* APP_NAME = "MyApp";
>   void print()
>   {
>       print(" GOOD GOOD STUDY DAY DAY UP \n");
>   }
>   ```
>
>   ```c
>     // main.c
>   #include "config.h"
>   #include <stdio.h>
>   int main() {
>       printf("%s supports %d users\n", APP_NAME, MAX_USERS);
>       print();
>       return 0;
>   }
>   ```
>
> - extern的原始用法：表示把外部变量的作用域扩展到此位置：维护性差
>
>   ```
>   如果没有头文件
>   在1.c中定义全局变量，2.c需要访问时
>   加extern声明这是一个外部链接，就能访问1.c的全局变量

>
> - extern只用于声明不用于定义

### 3.3 局部变量和全局(程)变量

> [!NOTE]
>
> 作用域角度
>
> 💡 局部变量形象理解：高一甲班有一个学生叫王建国，高一乙班也有一个学生叫王建国，两者不是同一个人。不同班允许有同名的学生，互不干扰。甲班点名时，只有该班的王建国喊到，乙班的王建国不在甲班活动，不会同时喊到，他们的活动范围局限于本班，或者说这些名字有效的范围是局部的(只在本班有效)；
>
> 💡 全局变量形象理解：国家有统一的法律法规，各省地方也有地方的法律法规。在甲省，甲省的法律和国家法律是有效的；在乙省，乙省的法律和国家法律是有效的。显然甲乙两省的法规互不有效。全局变量是各个函数之间的数据联系渠道。

```c
     return 0;
}
//❗全局变量可以和局部变量重名，局部变量会在作用域内将全局变量屏蔽(隐藏)

✅时间线视角：
程序开始
├─ 全局变量诞生（生命周期开始）
├─ 函数调用
│  ├─ 局部变量诞生
│  ├─ 局部变量作用域内使用
│  └─ 局部变量死亡（函数返回）
├─ 另一个函数调用...
└─ 程序结束 → 全局变量死亡

✅可见性视角（某时刻）：
[全局变量] ← 全局可见
[某个函数]
  └─ [局部变量] ← 仅函数内可见

//3.❗静态局部变量
void counter() {
    static int count = 7;  // 只初始化一次，可以记住上次调用结束的值(仅延长了生命周期)，未初始化，自动初始化为0值
    count++;
    printf("Count: %d\n", count);
}

int main() {
    counter();  // Count: 8
    counter();  // Count: 9
    counter();  // Count: 10
    // count的作用域：仅在counter函数内
    // count的生命周期：整个程序
    // 生命周期 > 作用域  （同一个作用域内，只有一个贯穿始终的生命周期）
    
    return 0;
}
//❗函数调用后不消失，存储单元不释放，下次调用该函数时，该变量已有值(记住上次调用结束的值)，仅延长了生存周期，他的作用域还是在本函数中，不能被其他函数引用。
	⬇️//确实仅限于定义它的那个函数块内部。其他函数（包括 main 函数）无法通过变量名直接访问它。
	//虽然 main 不能通过变量名访问，但如果函数返回了该变量的地址，main 是可以通过指针访问到这块内存的，而且这是安全的。
      //普通局部变量返回地址是危险的，因为它已经被释放内存了，访问一个被释放空间的变量会导致悬空引用。
```

> [!IMPORTANT]
>
> 1. 作用域是编译期概念，生命周期是运行期概念
>    1. 作用域是编译期确定的变量名可见范围（代码位置）,用于编译时语法检查
>    2. 生命周期是运行期变量实际存在的时间段（内存存活期）,用于运行时内存管理
> 
>    2. 作用域决定**可见性**，生命周期决定**存在性**
> 
> 3. 简单记忆
>    1. **作用域** = 身份证上写的"户籍所在地"
>    
>    2. **生命周期** = 人的"出生到死亡"
>
>    3. 你不能说"人的寿命 ≥ 户籍所在地"，但可以说"人在户籍所在地活动时必须是活着的"
> 
>          ```
>       依据这个例子打个比方，理解作用域和生命周期的关系：小明是活着的，但他的活动范围在西安，你不能在北京让他做某件事，你只能让他在西安做事。
>                                        
>       活着：表明生命周期存在
>          做事的位置：表明其中作用域的范围
>       ```
> 
>                                                 ### 🗺️ 用“小明”比喻不同变量的作用域与生命周期
> 
>       | 变量类型            | 比喻场景                            | 生命周期（活着吗？）                 | 作用域（在哪能叫他？）                       | 对应代码行为                                 |
>       | :------------------ | :---------------------------------- | :----------------------------------- | :------------------------------------------- | :------------------------------------------- |
>          | **普通局部变量**    | 小明是**短期游客**，只住西安酒店3天 | ❌ 3天后离开西安，人就没了（栈释放）  | ✅ 只在西安的这3天能叫他做事                  | 函数结束，内存释放，外部访问=悬空            |
>       | **static 局部变量** | 小明是**西安长住居民**，有永久住房  | ✅ 一直活着，直到城市拆除（程序结束） | ❌ 但你**只有西安的联系方式**，北京找不到他   | 内存一直有效，但变量名外部不可见（编译报错） |
>          | **全局变量**        | 小明是**全国知名人物**，户口公开    | ✅ 一直活着                           | ✅ 全国各地都能通过名字叫他做事               | 整个文件（或跨文件 extern）都能访问          |
>       | **动态分配变量**    | 小明**租了个房子**，钥匙在你手里    | ✅ 只要你没退租（free），他就一直活着 | ❌ 没登记户口，只能通过**钥匙（指针）**找到他 | 堆内存，手动管理，指针传递才能访问           |
> 
>       ### 🔍 用比喻解释之前的疑惑
> 
>       > **问题**：`main` 函数想访问 `static` 局部变量，是悬空吗？
> 
>          **用比喻回答**：
> 
>          - `static` 小明一直**活着**（内存没释放）✅
>       - 但 `main` 函数在**北京**，手里**没有小明的西安电话**（变量名不在作用域）❌
>          - 所以北京呼叫小明，不是“人没了”，而是“**查无此人**”（编译器报错：`undefined identifier`）
> 
>          > **对比**：如果是普通局部变量呢？
> 
>       - 普通小明3天后**已经离开西安**（栈内存释放）❌
>       - 北京拿着他以前的地址去找，发现**房子已经住进新人了**（内存被覆盖）
>          - 这才是真正的**悬空引用**（访问已释放内存）

🔍 补充说明

1. **栈 vs 堆**：
   - **栈**：分配快、自动回收，但空间有限（嵌入式常 < 4KB）→ 避免大数组。
   - **堆**：灵活但需手动管理，易泄漏/碎片 → **裸机 MCU 通常禁用 `malloc`**，改用静态池。

2. **static 的双重含义**：
   - 修饰**变量** → 改变生命周期（变长）+改变存放位置（存入数据段）+ 限制作用域。
   - 修饰**函数** → 仅限制链接可见性（内部链接），不影响生命周期。
   - ❗使用风险：占用内存一直不释放，降低了程序可读性(往往弄不清静态变量当前值)

3. **❗全局变量风险**：
   - 破坏模块封装性(模块设计应该高内聚性，低耦合性)
   - 多线程/中断环境下易引发竞态条件
   - **替代方案**：通过函数接口访问状态，或使用 `static` + getter/setter

4. **`const` 修饰变量的内存位置**：
   - **全局` const `变量**：存在 **只读数据段（`.rodata`）**

   - **局部 `const`变量**：存在 **栈（`stack`）**

   - **字符串常量**：存在 **只读数据段（`.rodata`）**

   - **`const`修饰指针**：从右往左看，离哪个块近就修饰谁。

5. **初始化行为**：
   - 栈上局部变量：**不自动初始化**（值随机！）
   - Data/BSS 变量（含 static）：**自动清零**
     - 用户显式初始化为未非0值存放在.data段
     - 用户未初始化则自动初始化为0或者初始化为0，存放在.bss段
6. 作用域的关系：块作用域⊂局部(函数)作用域⊂文件作用域⊂全局作用域

---

✅ **最佳实践总结**：

| 场景              | 推荐做法                                             |
| ----------------- | ---------------------------------------------------- |
| 函数内临时小变量  | 使用普通局部变量（栈）                               |
| 需跨调用保持状态  | 使用 `static` 局部变量                               |
| 模块私有数据/函数 | 使用 `static` 全局变量 / `static` 函数               |
| 全局配置（只读）  | `const` 全局变量（放入 Flash）                       |
| 不定长数据结构    | 若必须用堆，确保配对 `free`；否则用预分配静态缓冲区  |
| 跨文件共享数据    | 尽量避免；若必须，通过头文件声明 `extern` + 单一定义 |

### 3.5两个常用修饰符❗

💡 终极记忆口诀

- **static**："记住我"（变量）/"别找我"（函数）
- **inline**："展开我，别调用"
- **volatile**："别动我，我真的会变！"

#### 3.5.1 inline

> [!NOTE]
>
> (通常修饰函数)建议编译器直接将函数体插入调用处。对代码量小，频繁使用的函数，可以降低cpu开销，提升cpu性能

##### 1.空间换时间：

```c
// 普通函数：调用有开销
int add(int a, int b) {
    return a + b;
}
// 调用时：压栈→跳转→执行→返回→弹栈

// inline函数：像宏一样展开
inline int add_inline(int a, int b) {
    return a + b;
}
// 编译后直接变成：result = 3 + 4;
```

##### **2. 三种使用方式**

###### **方式1：传统inline**

```c
// math.h
inline int square(int x) {
    return x * x;
}

// main.c
#include "math.h"
int main() {
    int result = square(5);  // 可能被展开为：5 * 5
    return 0;
}
```

**方式2：static inline**（最常用）

```c
// utils.h
static inline int max(int a, int b) {
    return (a > b) ? a : b;
}
// 每个包含的文件都有独立副本，不会链接冲突

// main.c
#include "utils.h"
int main() {
    int m = max(10, 20);  // 直接展开，无函数调用
    return 0;
}
```

###### **方式3：extern inline**（C99）

```c
// header.h
extern inline int fast_add(int a, int b);

// source.c
inline int fast_add(int a, int b) {
    return a + b;
}
// 确保只有一个定义
```

##### **3. 编译器实际行为**

```c
// 编译器决定是否真的内联，考虑因素：
// 1. 函数大小（太复杂不会内联）
// 2. 调用频率（频繁调用优先内联）
// 3. 优化级别（-O2, -O3更积极）

inline void small_func() {  // 可能内联
    count++;
}

inline void huge_func() {   // 可能不被内联
    // ... 几百行代码 ...
}
```

##### **4. 与宏的比较**

```c
// 宏的缺点
#define SQUARE(x) ((x) * (x))
int a = 5;
int b = SQUARE(a++);  // ❌ a被增加两次！((5) * (6))

// inline函数的优点
inline int square(int x) {
    return x * x;
}
int b = square(a++);  // ✓ a只增加一次
```

#### 3.5.2 volatile

> [!NOTE]
>
> （通常修饰变量）防止编译器优化掉看似无用实际必要的内存访问，必须每次从内存中读取
>
> - 硬件寄存器操作
> - 多线程访问共享变量
> - 中断与主程序共享变量

#####  **1.为什么需要volatile？**

```c
// 没有volatile的问题
int flag = 0;

void interrupt_handler() {
    flag = 1;  // 中断修改
}

void main_loop() {
    while (flag == 0) {  // 编译器可能优化成：while(true)!
        // 等待中断
    }
    printf("中断发生\n");
}
```

##### **2. volatile的含义**

> "这个变量可能在你不知道的时候被改变，别优化掉对它的访问！"

**告诉编译器**：

1. 不要缓存到寄存器
2. 不要优化掉看似无用的读取
3. 不要重排相关指令

##### **3. 四大应用场景**

###### **场景1：硬件寄存器**

```c
// 硬件映射的内存地址
#define STATUS_REG (*(volatile unsigned int*)0x40021000)

void wait_for_device() {
    while ((STATUS_REG & 0x01) == 0) {
        // 必须每次都读硬件，不能优化！
    }
}
```

###### **场景2：多线程共享变量**

```c
#include <pthread.h>

volatile int shared_counter = 0;  // 多个线程修改

void* thread_func(void* arg) {
    for (int i = 0; i < 1000; i++) {
        shared_counter++;  // 其他线程可能同时修改
    }
    return NULL;
}
// 注意：volatile不保证原子性！仍需要互斥锁
```

###### **场景3：信号处理**

```c
#include <signal.h>
#include <stdio.h>

volatile sig_atomic_t signal_received = 0;

void signal_handler(int sig) {
    signal_received = 1;  // 异步修改
}

int main() {
    signal(SIGINT, signal_handler);
    
    while (!signal_received) {  // 必须每次检查内存
        printf("运行中...\n");
        sleep(1);
    }
    printf("收到信号，退出\n");
    return 0;
}
```

###### **场景4：内存映射I/O**

```c
// 控制LED灯
#define LED_PORT (*(volatile unsigned char*)0x8000)

void blink_led() {
    while (1) {
        LED_PORT = 0xFF;  // 亮
        delay(500);
        LED_PORT = 0x00;  // 灭
        delay(500);
        // 每次赋值必须真正写入硬件
    }
}
```

### 4.2 `#define`宏定义

```c
//1.不带参宏   
#define  PI  3.14
#define  MAX  256   

//1.前者代替后者，不以","分割以"空格"分隔，结尾不带";"。全大写定义
//2.在预处理阶段，宏只是实现代码的替换，中间不进行任何数据计算的操作
//3.宏定义使用时，能加括号就加括号，不要吝啬括号

//2.带参宏(宏函数)
1.eg1(大小比较):#define MAXNUM(x, y)  ((x) > (y) ? (x) : (y))   

//三目运算符(条件运算符)  x > y ? x : y
//条件表达式?表达式1:表达式2
//如果"条件"值为真（true），整个表达式的值就是"表达式1"；否则就是"表达式2"。
    
2.eg2(位操作):
#define SET_BIT(reg, bit)   ((reg) |=  (1U << (bit)))    //置位(设为1)
#define CLEAR_BIT(reg, bit) ((reg) &= ~(1U << (bit)))	//清零(设为0)
#define TOGGLE_BIT(reg, bit)((reg) ^=  (1U << (bit)))	//取反(反转)
#define READ_BIT(reg, bit)  (((reg) >> (bit)) & 1U)		//读取某一位的值

// 使用（假设控制寄存器）
volatile uint32_t *GPIO = (uint32_t*)0x40000000;
SET_BIT(*GPIO, 5);      // 设置第 5 位
if (READ_BIT(*GPIO, 5)) { /* 检查是否为高 */ }
```

以下是 **带参宏（Parameterized Macro）** 与 **函数（Function）** 在 C 语言中的核心区别，以表格形式清晰对比：

| 对比维度     | 带参宏（`#define MACRO(x) ...`）                             | 函数（`int func(int x) { ... }`）                            |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **本质**     | 预处理阶段的**纯文本替换**                                   | 编译后的**可调用、可传参**代码实体                           |
| **处理阶段** | **预处理**阶段（编译前）                                     | **编译、链接**阶段检查,**运行**时调用                        |
| **返回值**   | 通过表达式“模拟”返回（如 `(x) > (y) ? (x) : (y)`）           | 显式 `return` 语句返回                                       |
| **作用域**   | 全局可见（从定义处到文件结束或 `#undef`）                    | 遵循 C 作用域规则（可为 static、extern 等）                  |
| **求值次数** | 参数可能被**多次求值**（如 `MAX(a++, b)` 会导致 `a++` 执行两次） | 参数**只求值一次**                                           |
| **类型检查** | 缺点:❌ 无类型检查，不安全,可读性差                           | 优点:✅ 有严格的参数和返回值类型检查                          |
| **代码体积** | 缺点:❌ 每次使用都展开，可能**增大代码体积**                  | 优点:✅ 代码只存一份，复用性好                                |
| **性能开销** | 优点:✅ 无函数调用开销（直接内联展开）速度快                  | 缺点:⚠️ 有调用开销（压栈、跳转、返回），但现代编译器可内联优化 |
| **使用场景** | 功能**简单、简短**的使用带参宏                               | 功能**复杂**情况                                             |
| **示例**     | `#define SQUARE(x) ((x)*(x))`                                | `int square(int x) { return x * x; }`                        |

📌 关键总结

- **优先使用函数**：除非对性能极度敏感且能确保宏的安全性，否则应优先使用函数（更安全、可维护）。
- **宏的典型适用场景**：
  - 简单常量表达式（如 `#define MAX(a,b) ((a) > (b) ? (a) : (b))`）
  - 条件编译控制（如 `#define DEBUG_PRINT(fmt, ...) printf(fmt, ##__VA_ARGS__)`）
  - 泛型操作（在 C11 之前）
- **宏的陷阱**：
  - 忘记加括号导致运算符优先级错误
  - 参数带副作用（如 `i++`）被多次执行
  - 无法取地址（`&MACRO` 非法）

### 4.3`#ifdef`条件编译

#### 1.✅ C 语言条件编译指令总览

| 指令      | 语法                                                         | 功能说明                                   | 典型用途                       | 示例                                                         |
| --------- | ------------------------------------------------------------ | ------------------------------------------ | ------------------------------ | ------------------------------------------------------------ |
| `#if`     | `#if 常量表达式`<br>`...`<br>`#endif`                        | 若常量表达式为非零（真），则编译其间的代码 | 根据数值开关控制代码           | `#if DEBUG_LEVEL > 2`<br>`printf("Detail log\n");`<br>`#endif` |
| `#ifdef`  | `#ifdef 宏名`<br>`...`<br>`#endif`                           | 若**宏已定义**（无论值为何），则编译       | 检查某个功能/平台是否启用      | `#ifdef _WIN32`<br>`// Windows 特有代码`<br>`#endif`         |
| `#ifndef` | `#ifndef 宏名`<br>`...`<br>`#endif`                          | 若**宏未定义**，则编译                     | 防止头文件重复包含（传统方式） | `#ifndef MY_HEADER_H`<br>`#define MY_HEADER_H`<br>`...`<br>`#endif` |
| `#elif`   | `#if ...`<br>`...`<br>`#elif 常量表达式`<br>`...`<br>`#endif` | “else if”：当前面条件为假时，检查新条件    | 多分支条件编译                 | `#if ARCH == ARM`<br>`...`<br>`#elif ARCH == X86`<br>`...`<br>`#endif` |
| `#else`   | `#if ...`<br>`...`<br>`#else`<br>`...`<br>`#endif`           | 否则编译此段                               | 提供默认/备选实现              | `#ifdef USE_FLOAT`<br>`float x;`<br>`#else`<br>`int x;`<br>`#endif` |
| `#endif`  | `#endif`                                                     | 结束一个条件编译块                         | 所有条件编译必须以它结尾       | —                                                            |

> 💡 **注意**：  
> - 所有指令必须配对使用（`#if`/`#ifdef`/`#ifndef` → `#endif`）。  
> - 可嵌套使用（但需注意可读性）。  
> - 表达式必须是**整型常量表达式**（不能是变量或运行时值）。

---

#### 2.常见使用场景详解

###### 1. ✅**注释大段代码（调试临时禁用）**
```c
#if 0
    printf("This is debug code\n");
    some_old_function();
#endif
```
- ✅ 优点：比 `/* */` 更安全（可嵌套注释）
- 🔄 等价于：`#if 0 ... #endif` ≈ “永久关闭”，`#if 1 ... #endif` ≈ “永久开启”

###### 2.✅**头文件防重入（Include Guard）**

```c
#ifndef SENSOR_DRIVER_H
#define SENSOR_DRIVER_H

// 头文件内容...

#endif
```

###### 3. **功能开关（编译时配置）**
```c
// 编译时通过 -DENABLE_LOG 开启日志
#ifdef ENABLE_LOG
    #define LOG(msg) printf("[LOG] %s\n", msg)
#else
    #define LOG(msg) ((void)0)  // 空操作
#endif
```
- 构建命令：`gcc -DENABLE_LOG main.c`

###### 4. **版本兼容性处理**
```c
#if __STDC_VERSION__ >= 201112L
    // C11 特性
    _Static_assert(sizeof(int) == 4, "int must be 4 bytes");
#else
    // 兼容 C99/C89
    typedef char static_assertion[sizeof(int) == 4 ? 1 : -1];
#endif
```

###### 5. **硬件/架构适配（嵌入式常见）**
```c
#if defined(STM32F4)
    #define UART_BAUD 115200
#elif defined(IMX6ULL)
    #define UART_BAUD 9600
#endif
```

⚠️ 注意事项

| 问题                             | 说明                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| **不能用于运行时判断**           | 条件编译在**预处理阶段**完成，无法根据变量值动态选择         |
| **宏必须是“已定义”状态**         | `#ifdef MACRO` 只关心是否 `#define MACRO` 过，不管值是多少（即使 `#define MACRO 0` 也算“已定义”） |
| **与 `#if defined(MACRO)` 等价** | `#ifdef MACRO` ⇔ `#if defined(MACRO)`，后者可用于 `#elif` 中 |
| **避免过度使用**                 | 过多条件编译会降低代码可读性和可维护性                       |

✅ 最佳实践建议

- 调试时用 `#if 0` 代替注释；
- 功能开关统一用 `-D` 定义（如 Makefile 中 `CFLAGS += -DDEBUG`）；
- 头文件优先用 `#ifndef/#define/#endif`（或 `#pragma once`）；
- 复杂条件优先用 `#if defined(...)` 而非 `#ifdef`，便于组合逻辑（如 `#if defined(A) && !defined(B)`）。

## 五、`GCC`相关

#### 5.1` gcc main.c -> a.out` （编译过程的4个阶段）

​	C语言从源代码(.c文件)到可执行文件（`a.out`）的构建过程，要经历预处理->编译->汇编->链接四个阶段。

1. 预处理（Preprocessing）：预处理是编译过程的第一步，由 C 预处理器（cpp, C Preprocessor） 完成。它不涉及语法或语义分析，仅对源代码进行**文本级别**的处理。（预处理qi）

   ```c
   //1.主要功能
   ✅处理和#号相关的代码(宏定义、头文件，条件编译)，将代码替换。
   	生成.i文件
   //2.命令  gcc -E
   	gcc -E main.c -o main.i   //只预处理，main.i是纯C代码
   //3.详细功能
   1.宏展开：将 #define 定义的宏替换为实际内容。
   2.文件包含：处理 #include 指令，将头文件内容插入到当前文件中。
   3.条件编译：根据 #if、#ifdef、#ifndef 等指令决定是否包含某段代码。
   4.删除注释：移除所有 // 和 /* */ 注释。
   5.添加行号和文件名标识：便于后续编译器报错时定位原始位置
   ```

2. 编译（Compilation）： 将预处理后的 C 代码翻译成 **汇编语言（Assembly）**。这一步由编译器（如 GCC 的 cc1 组件）完成，涉及词法分析、语法分析、语义分析和代码优化。(编译期)

   ```c
   //1.主要功能
   ✅通过语法分析、语义分析、优化等方式将C语言代码编译成汇编代码。
       生成.s文件
   //2.命令  gcc -S
   	gcc -S main.i -o main.s		//从.i生成
   	gcc -S main.c -o main.s 	//直接从.c 生成
   //3.详细功能
   1.语法与语义检查：确保代码符合 C 语言规范。
   2.生成中间表示（IR）：如 GCC 使用 GIMPLE/RTL。
   3.优化：根据 -O0、-O2 等选项进行不同程度的优化（如常量折叠、死代码消除等）。
   4.生成目标平台的汇编代码：与具体 CPU 架构相关（如 x86、ARM）。
   
   ```

3. 汇编（Assembly）：将汇编代码转换为 **机器码（二进制目标代码）**，但尚未形成可执行文件。此步骤由 **汇编器（assembler，如 GNU as）** 完成。

   ```c
   //1.主要功能
   ✅将汇编代码编译成可执行程序 
   	生成.o文件（目标文件）
   //2.命令 gcc -c
   	gcc -c main.s -o main.o		//从.s生成
   	gcc -c main.c -o main.o   	//直接从.c 生成
   //3.详细功能	
   1.将助记符（如 mov, add）翻译为对应的机器指令操作码。
   2.生成符号表（记录函数、全局变量等符号的地址占位符）。
   3.生成重定位信息（供链接器使用）
   ```

4. 链接（Linking）：将一个或多个目标文件（`.o`）以及所需的库（静态库 `.a` 或动态库 `.so`）合并，生成最终的 **可执行文件** 或 **共享库**。由 **链接器（linker，如 GNU ld）** 完成

   ```c
   //1.主要功能
   ✅将多个.o目标文件与库文件链接成可执行程序
   	生成可执行文件a.out
   //2.命令 gcc main.o -o 		注意：-o在main.o后面也有rename的感觉
   	gcc main.o -o myapp
   	gcc file1.o file2.o -lm -o myapp//若使用多个 .o 文件和库：
   //3.详细功能	
   1.符号解析（Symbol Resolution）：将各目标文件中引用的外部符号（如 printf、自定义函数）与定义处关联。
   2.重定位（Relocation）：将各目标文件中的相对地址调整为最终的绝对（或加载时确定的）地址。
   3.合并段（Sections）：将多个 .text、.data 等段合并到可执行文件中。处理库依赖：链接标准库（如 libc）或用户自定义库。总结
   ```

   > [!NOTE]
   >
   > - 静态链接 vs 动态链接
   >   - 静态链接：将库代码直接嵌入可执行文件，体积大但独立。
   >   - 动态链接：运行时加载共享库（如 `.so`），节省内存，便于更新。
   > - **交叉编译**：在一种平台（如 x86 PC）上为另一种平台（如 ARM 嵌入式设备）生成可执行文件，需指定目标架构的工具链（如 `arm-linux-gnueabihf-gcc`）。

   

5. 总结时间流图

   ```c
   main.c
      │
      ▼
   [预处理器] → main.i （展开宏、包含头文件等）
      │
      ▼
   [编译器]   → main.s （C → 汇编）
      │
      ▼
   [汇编器]   → main.o （汇编 → 机器码目标文件）
      │
      ▼
   [链接器]   → myapp  （合并 .o + 库 → 可执行文件）
   ```

#### 5.2 ` ./a.out`后（运行期），操作系统会进行以下操作（简化版）（了解）：

1. 加载（Loading）
   - 内核的**程序加载器（loader）** 将 `a.out` 文件从磁盘读入内存。
   - 解析 ELF 格式（Linux 下可执行文件格式），设置代码段（`.text`）、数据段（`.data`, `.bss`）等。
   - 如果是动态链接程序，加载器还会加载所需的共享库（如 `libc.so.6`）。
2. 初始化（Initialization）
   - 设置栈（stack）和堆（heap）。
   - 执行 C 运行时启动代码（如 `_start`），它会调用全局构造函数（C++）或 `__attribute__((constructor))` 函数。
   - 最终调用 `main()` 函数。
3. 执行（Execution）
   - CPU 从 `main()` 开始逐条执行机器指令。
   - 程序运行逻辑（如变量操作、函数调用、I/O 等）在此阶段发生。
4. 终止（Termination）
   - `main()` 返回或调用 `exit()`。
   - 运行时清理资源（关闭文件、释放内存等）。
   - 操作系统回收进程占用的资源。

#### 5.3`gcc`编译选项

```c
1. -o(小写)	//指定生成代码的文件名
	gcc main.c -o myprogram

	gcc  -E  filename.c  -o  filename.i
3. -S	//将代码执行预处理、编译两个步骤
	gcc  -S  filename.c  -o  filename.s 
4. -c(小写c)	//将代码执行预处理、编译、汇编三个步骤
	gcc -c filename.c -o filename.o
5. -l	//指定链接库的名称
    gcc main.o  -lm
    gcc main.o 	-lpthread
6. -I   //指定头文件的路径
	gcc main.c -I./include -I/usr/local/include 
7. -L	//指定库文件的路径-L./lib：
    gcc main.c -L./lib -lmylib	
    a.在 ./lib 目录下查找库文件（如 libmylib.so）。
    b.必须配合 -l 使用：-lmylib 表示链接名为 mylib 的库。
	c.完整流程：先 -L 指定路径，再 -l 指定库名。
8. -g     //运行gdb调试
9. -Wall  //启用常见警告->显示所有的告警信息-O2
    gcc -Wall main.c
    gcc -Wall -Wextra main.c
编译器优化等级
    gcc -O2 main.c -o myapp   # ✅ 先指定优化，再用 -o 指定输出名
-O0：无优化（默认，便于调试） //这里-O(大写O不是0)
-O1：轻度优化
-O3：激进优化（可能增大代码）
-Os：优化体积
//✅gcc [编译选项] [源文件/目标文件] [链接选项] -o 输出
```
