

## 一、❗`valgrind`排查内存泄漏

### 1.1 什么是内存泄漏？

​	内存泄漏（Memory Leak）是指程序在运行过程中动态申请了堆内存（如使用`malloc`、`calloc`、`realloc`后）没有及时释放内存`free`，导致这部分内存无法被再次使用，且在进程生命周期内持续占用系统资源。（❗`申请`和`释放`一定要一一对应）

- 在**一次**进程中（程序不结束）长时间申请不释放导致内存耗尽
- 当进程结束后，操作系统会强制回收所有该进程所占的资源。

> [!NOTE]
>
> ***内存碎片**:是指在反复的内存分配和释放过程中，堆产生了许多无法使用的小内存块，导致无法满足大块内存的分配请求。*

### 1.2 使用方法

```c
//安装 valgrind 工具
sudo apt-get install valgrind 
//检测是否安装成功(查看valgrind版本)
valgrind --version 
//查看可执行程序的内存泄漏
valgrind ./a.out
//查看详细信息
valgrind --tool=memcheck --leak-check=full ./a.out
```

### 1.3、内存池

```c
内存池:是一种用户态内存管理策略：预先向操作系统申请一大块内存，由程序自行划分、分配和回收(通常:8字节/16字节/32字节或按页大小:4KB/4MB/1GB),而非每次需要内存时都调用 malloc/free。核心思想:用空间换时间。
优点:分配速度快,可复用,有效避免外部内存碎片
缺点:预分配可能浪费内存,设计起来比较复杂
```

### 1.3 ❗排查段错误

#### 1.3.1 什么是段错误？

​	**段错误**（`Segmentation Fault`，简称`Segfault`）是程序试图**访问它没有权限访问的内存区域**时操作系统发出的信号。这是一种硬件层面的内存保护机制。

1. 访问**空指针**/**野(无效地址)**指针（未初始化的指针/释放内存后的指针/超出(栈)变量作用域的指针）

   ```c
   1.空指针 ：明确指向地址0（或NULL）的指针，表示不指向任何有效内存	
   ✅ 明确表示"不指向任何地方"
   ✅ 可以安全检查（if (ptr != NULL)）
   ✅ 解引用会崩溃（容易发现错误）
   ❌解引用会导致段错误
       
   2.野指针  ：指向"随机"内存地址
   ❌ 未初始化的
   ❌ 值是随机的（栈上的遗留数据）
   ❌ 指向未知的内存区域
   🤦‍最难调试，问题随机出现
       
   3.释放内存后的指针也是野指针，准确来讲是"悬空指针"
   ✅ 曾经指向有效内存
   ❌ 内存已被释放/销毁
   ❌ 指针本身还有值（不是NULL）
   ❌ 使用时会引发未定义行为
   ```

2. 内存越界访问

   1. 读越界 ：读到垃圾值
   2. 写越界：破坏其他正常的变量

      - 内存溢出：特殊的写越界：缓冲区溢出

      **内存的越界访问是因，段错误是果。**

3. 修改只读内存

   - 写越界

4. 无限递归？

   - 栈溢出


#### 1.3.2 使用方法

```c
1.gcc -g *.c
2.gdb a.out
3.r直接运行(往往不知道段错误位置不用加断点)
```

## 三、Makefile工程管理工具

通过构建目标(`target`)、依赖项(`dependencies`)、规则（`commands`）三者之间关系，可以实现代码的自动化编译、链接等任务，提升编译的效率。

- 自定义变量和自动变量

  - `$@`：❗当前目标名称
  - `$^`：❗所有依赖文件（去重）
  - `$<`：第一个依赖文件
  - `$?`：比目标新的依赖文件列表
  - 自定义变量如 `CC = gcc`或`INCLUED_PATH = ../include`

- 赋值语句

  -   `=`直接赋值
  -   `:=` 覆盖赋值（原来有值覆盖为新值）
  -   `+=`在原来的内容后面拼接新的内容
  -   `?=`若原来没值，就赋新值，若原来有值保留原来的值

- 模板

  ```makefile
  TARGET=app #1.要生成的二进制可执行程序文件名
  SRC_PATH:=./src	#2.依赖文件路径
  SRCS+=${SRC_PATH}/main.c #所有依赖文件
  INCLUDE_PATH:=./include	#3.头文件路径 
  BUILD_PATH:=./build	#4.生成目标文件路径
  RESOURCE_PATH:=./resources #5.资源文件路径
  LIB_PATH:=./lib	#6.库文件路径
  CC?=gcc	#7.编译器
  CFLAGS+=-wall -g #编译选项
  LDLIBS=-lpthread -lm #链接
  #8.编译规则
  $(BUILD_PATH)/$(TARGET):$(SRCS)	#./build/app : ./src
  	${CC} $^ -o $@ -I${INCLUDE_PATH}	#gcc main.c 1.c 2.c -o app -I ./include 
  	
  #9.伪目标
  .PHONY: clean memcheck 
  clean:
  	rm -rf ${BUILD_PATH}/${TARGET}
  memcheck:
  	cd ${BUILD_PATH} && valgrind --leak-check=full ./${TARGET}
  
  ```
