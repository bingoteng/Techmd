

# `CAN`协议✅

## 1. 什么是`CAN`？

`CAN`（Controller Area Network）: 中文叫**控制器局域网**。是一种**多主、广播型、差分同步串行**通信总线协议，由德国BOSCH公司开发，ISO标准化为`ISO 11898`。主要用于**高可靠性、强抗干扰、中长距离**的工业与车载通信，如汽车`ECU`互联、工业控制、机器人节点通信。该总线允许多个节点同时挂载，无绝对主从限制，依靠**报文ID优先级**进行总线仲裁。

![image-20260412195049594](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-00_1f518401b9dd2d762dc2d55fac0508e4.png)

**特点： 参考文档：[CAN.pdf](..\77-辅助文档\CAN.pdf) **

- **半双工异步通信+广播+差分**
- **压差为2v：逻辑0；压差为0：逻辑1**
- **无固定主从、优先级仲裁**（谁发ID小谁先发）
- **差分信号传输**：`CAN_H / CAN_L`（抗共模干扰能力极强）
- **显性/隐性逻辑**：`显性=0`，`隐性=1`（线“与”逻辑，显性覆盖隐性）
- **通信速率：**

  - ISO-11898（高速，通信速率为`125kps到1Mbps`）最快可达到`1Mbps`，传输距离`<=40m`
  - ISO-11519（低速，通信速率低于`10k到125kbps`）
  - 当信号传输距离达到`10Km`时，CAN 仍可提供高达`50Kbit/s `的数据传输速率。

- **终端匹配电阻**：总线两端各接`120Ω`电阻，抑制信号反射，总线特征阻抗≈`60Ω`
- ✅**位填充机制（Bit Stuffing）**：确保边沿跳变用于同步
  - 连续发送5个相同电平后，自动插入1个相反电平
  - 接收端检测到第6个填充位会自动剥离，恢复原始数据
- ✅**自同步机制**：无独立时钟线，依靠帧起始位（`SOF`）硬同步 + 边沿重同步维持时序

  - 硬同步：每隔固定时间采样（但两个设备时钟不可能完全相同，时间久误差积聚会数据错位）
  - 再同步：每当采样到的是跳变沿的时候，将采样位置位校准到数据位的中心，不是跳变则按硬同步采样
  -  对于一段完全没有跳变的数据，**位填充强制反转**

- 适用场景：✅**强电磁干扰环境、多节点实时控制、需高可靠性的工业/车载网络**
  - 汽车动力/底盘/车身控制（`ECU、BCM、ESP`）
  - 工业`PLC`节点、伺服驱动器
  - 农业机械、船舶、轨道交通

- 节点数量：理论`2000+`，实际受**终端电阻匹配、波特率、线缆长度**限制
  - 经典建议：≤`64~112`个节点（取决于收发器驱动能力与总线电容）
  - 拓扑：线性总线为主（不支持星型/环型，除非加中继器）

- **差分电平 + 线与逻辑**：`(线与：CAN 仲裁与错误检测的物理基础)`

  - 有压差`≈2.0V`：显性（逻辑0）：`CAN_H ≈ 3.5V`，`CAN_L ≈ 1.5V`，
  - 无压差：隐性（逻辑1）：`CAN_H ≈ CAN_L ≈ 2.5V`，压差`0V`
  - 线与：只要有一个节点发送显性（0），总线即呈现显性状态；所有节点发隐性（1）时总线才恢复隐性

  > [!NOTE]
  >
  > *想象一条双向单车道（总线），默认是**畅通状态**（隐性/1）。 路上有很多车（节点），每辆车都有喇叭，但这个喇叭**只能按“禁行”信号（显性/0），不能按“通行”信号**。*
  >
  > - ***线与逻辑：** 只要**任何一辆车**按下禁行（输出 0），整条路就变成禁行状态。*
  > - ***恢复隐性：** 只有当**所有车都松开**禁行（输出 1），路才会恢复默认的畅通状态。*
  > - ***仲裁基础：** 两辆车同时想上路，按“车牌号”（ID）比大小。先发出禁行信号（0）的车赢，另一辆听到禁行但自己本想发通行（1），立刻知道自己输了，主动让路并转为接收模式。*

## 2.`CAN`核心特性与物理层

1. `CAN`总线在空闲时，`CAN_H`与`CAN_L`电压均为`~2.5V`（隐性状态），压差为`0V`。为保证隐性电平稳定，需在总线**两端**各并联一个`120Ω`终端电阻。
2. 任何节点均可主动发起通信。发送前，节点会监听总线是否空闲（连续11个隐性位）。若空闲，则发送**帧起始位（`SOF`）**：一个显性位（0），标记通信开始。
3. `CAN`采用**不归零（`NRZ`）编码**，无独立时钟线。接收节点通过SOF硬同步建立初始相位，后续依靠位填充产生的电平跳沿进行**重同步（Resynchronization）**，补偿波特率偏差与传播延迟。
4. 每个数据位的时间被划分为`TQ（Time Quantum）`，典型采样点设置在位周期的`75%~87.5%`处。节点在采样点读取`CAN_H-CAN_L`压差，判断显性/隐性。
5. 发送节点在发送数据的同时会**回读总线电平**。若发送显性但回读为隐性，说明发生位错误；若发送隐性但回读为显性，说明仲裁失败或总线故障。

```c
✅总之
1.CAN总线空闲时：CAN_H≈2.5V, CAN_L≈2.5V (隐性/1)
2.特殊信号：
   起始信号(SOF)：1位显性(0)，宣告通信开始；
   结束信号(EOF)：7位隐性(1) + 帧间空间(IFS)，标志当前帧结束。
3.在数据发送时：
   显性(0)覆盖隐性(1)；总线状态由所有发送节点“线与”决定；
   节点在发送同时回读总线，实现自同步与错误检测。
4.位填充规则：
   连续5个相同位后，自动插入1个相反位；接收端自动剥离，确保边沿密度满足同步需求。
```

## 3. `CAN`数据帧结构与通信时序

![image-20260412194433715](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-00_b85dbfabcc4d813411b41918684a702b.png)

- 节点监听总线空闲后，发送`SOF（显性）`
- 发送**仲裁码**（11位标准ID 或 29位扩展ID + 1位`RTR` + 1位`IDE` + 1位`r0`）
- 发送**控制码**（4位`DLC`数据长度 ）
- 发送**数据码**（0~8字节，经典`CAN`）
- 发送**CRC码**（15位`CRC` +1位 `CRC`界定符隐性1位）
- 发送**ACK场**（1位`ACK`槽 + 1位`ACK`界定符）：发送方发隐性，任一正确接收节点回显性确认
- 发送`EOF（7位隐性）` + `IFS（3位隐性）`，结束通信

```c
1.帧起始(SOF)：1位显性，同步所有节点；
2.仲裁码：标准帧11位ID(优先级核心) + RTR(0数据帧/1远程帧) + IDE(0标准/1扩展) + 预留位r0；
3.控制码：DLC:Data Link Control(4位，表示数据字节数0~8)；
4.数据码：0~8字节实际数据(高位先行 MSB first)；
5.CRC码：15位CRC校验 + 1位隐性界定符；
6.ACK码：2位 
  第一位(ACK确认槽：发送节点发'逻辑1隐性'，接收节点若校验正确则拉低即'逻辑0显性'(ACK)，否则保持隐性(NACK))；
  第二位(ACK界定位：一定是逻辑1，作用是把后面数据隔开)
7.帧结束(EOF)：7位隐性，标志当前报文传输完毕，随后进入3位隐性帧间空间(IFS)。
```

## 4. `CAN`仲裁与错误处理机制

- **仲裁机制（非破坏性）**：
  - 多个节点同时发送时，在**仲裁场ID位**逐位比较。
  - `显性(0)` 覆盖 `隐性(1)`。节点发送隐性但回读显性 → 仲裁失败 → 立即停止发送，转为接收模式。
  - `ID值越小 → 优先级越高`（因为高位先发，先发0者赢）。
  - 仲裁过程不丢失数据，胜者继续发送，败者等待总线空闲后重试。

- **错误检测与状态机**：
  - 5种错误：`位错误`、`填充错误`、`格式错误`、`ACK错误`、`CRC错误`。
  - 错误计数器：`TEC`（发送错误计数器）、`REC`（接收错误计数器）。
  - 三种状态：
    - ✅`错误主动(Error Active)`：正常发送，出错发主动错误帧（6显性+8隐性）。
    - ⚠️`错误被动(Error Passive)`：TEC/REC>127，发送被动错误帧（8隐性+8隐性），降低干扰。
    - ❌`总线关闭(Bus Off)`：TEC>255，节点被切断总线连接，需软件复位或自动恢复。

```c
1. 仲裁原则：ID小者优先，逐位比较，显性(0)覆盖隐性(1)；
2. 仲裁结果：胜者继续发，败者立即退让并监听，不破坏总线数据；
3. 错误帧：检测到错误时，节点发送6位显性(主动)或8位隐性(被动)破坏当前帧；
4. 状态迁移：
   TEC/REC < 127 → 错误主动 (正常通信)
   127 < TEC/REC ≤ 255 → 错误被动 (限制发送)
   TEC > 255 → Bus-Off (脱离总线，需复位)
5. 主机/从机概念弱化：CAN是“对等网络”，应用层通过ID过滤决定处理哪些报文。
```

> [!IMPORTANT]
>
> *不同`CAN`收发器与控制器（如`SJA1000, MCP2515, STM32 bxCAN`）寄存器配置差异较大，但底层时序与仲裁逻辑完全遵循ISO 11898标准。实际开发需注意：*
> - 终端电阻必须**仅加在总线物理两端**，中间节点严禁并联120Ω。
> - 波特率与采样点需根据线缆长度与节点数计算，典型值：`125k/250k/500k`，采样点`75%~87.5%`。
> - `CAN FD`扩展了数据段速率与长度（0~64字节），但仲裁段仍保持经典CAN速率与格式。
