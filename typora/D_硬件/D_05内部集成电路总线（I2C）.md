# `I2C`协议✅

## 1. 什么是`I2C`？

​	`I2C`（Inter-Integrated Circuit）:是`IICBUS`的简称，中文应叫**内部集成电路总线**。是一种**半双工同步串行**通信总线协议，采取主从应答通信方式，由飞利浦公司开发，主要用于`低速设备短距离`通信，如芯片与芯片间，该总线允许同时挂载多个设备（芯片），每个芯片有特定的地址。

![image-20260412210944537](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-01_69c4fc84fffb59aafc786a607e6d971c.png)

**特点：**

- **半双工同步串行**

- 仅需**两根线**：`SDA/SCL`（除去电源线和接地线，仅需两根线）

- **多主多从、主从应答**（一主多从常见）

- **高位先行：**`MSB`先行

- **通信速率：`100K/400K/1MHZ`**

- **上拉电阻**保证两根线都为高电平 

  - `100kHz `常用 `4.7k~10k`；
  - `400kHz` 常用 `2.2k~4.7k`；
  - `1MHz `可能需要 `1k `左右。

- ✅**起始/停止信号**：

  - 起始：`SCL 高`时 `SDA `拉低（1->0）
  - 停止：`SCL 高`时 `SDA` 拉高（0->1）

- ✅**数据传输时**：

  - `SCL高`电平采样（`SCL 高`  `SDA`稳定）
  - `SCL低`电平变化（`SCL 低`  `SDA`变化）

- ✅**应答信号**：在时钟脉冲9时，数据发送方释放总线，数据接受方控制总线并
                     回复`ACK`或`NACK`。

  ```c
   ACK:接受方拉低SDA表示ACK;
  NACK:接收方保持SDA为高电平表示NACK；
  (相当于接收设备未将总线拉低即就是未回复ACK)
  ```

- 适用场景：✅**对通信速度要求不高：中低速设备、引脚紧张但是想挂载多个设备**

  - 小容量`EEPROM`

  - 中低速传感器：`BH1750`光照、`LM75`温湿度、`MPU6050`加速度计

  - `LCD1602\0LED`显示屏

- 设备数量（7位地址/10位地址）：总线的最大容性负载通常为 **`400 pF`**

  - 7位：
    - 理论： 112个（128-16保留） 
    - 实际：10-20个----*寄生电容上升导致上拉能力下降*

  - 10位：1004个（1024-16）

- **开漏输出 + 线与逻辑**：`（线与：I2C 仲裁机制（Arbitration）的物理基础`

  - 开漏：只能输出低电平或⾼阻态，需要外部上拉电阻，才能输出⾼电平。

  - 线与：任何一个设备拉低总线，都会使得总线为低电平

    > [!NOTE]
    >
    > *想象一个会议室里有一盏灯（总线），灯默认是**亮**的（上拉电阻）。 会议室里有好几个人（设备），每个人手里都有一个开关，但这个开关**只能关灯，不能开灯**。*
    >
    > - ***线与逻辑：** 只要**任何一个人**按下开关（输出 0），灯就会灭。*
    > - ***恢复高电平：** 只有当**所有人都松开**开关（输出 1/高阻态），灯才会因为默认设置而变亮。*

## 2.`I2C`通用通信时序

1. `IIC`总线规定，设备在空闲时，两根总线都处于高电平状态。为保证这种状态，数据线`SDA`和时钟线`SCL`都要外接上拉电阻。
2. `IIC`总线上连接的若干设备中，每次通信前，发送方首先发送一个“起始”信号，起始信号就是在`SCL`为高电平时，`SDA`发送一个低电平。当其它设备接收到这个其实信号后，将进行一次“总线仲裁”。意思就是设备(除发送起始信号的那个设备以外的)都将处于聆听状态
3. `IIC`总线进行数据传送时，时钟线(`SCL`)上的信号为高电平期间，数据线(`SDA`)上的数据必须保持稳定。只有在 时钟线(`SCL`)上的信号为低电平期间，数据线(`SCL`)上的高电平或低电平状态才允许变化。同时，`SCL`信号由数据启动发送的设备提供。输出到数据线(`SDA`)上的每个字节必须是8位。数据传送时，先传送最高位(`MSB`)， 后传送最低位(`LSB`)。
4. 发送器每发送一个字节（8个bit），就在时钟脉冲 `9 期间`释放数据线，接收器反馈一个应答信号。 主机 `SCL`拉高，读取从机`SDA`的电平。对于反馈有效应答位`ACK`的要求是：从机在第9个时钟脉冲之前的低电平期间将数据线`SDA`拉低，并且确保在该时钟的高电平期间为稳定的低电平。
   ➢ 数据线(`SDA`)为低电平时，规定为有效应答位（`ACK`，简称应答位），表示接收器已经成功地接收了该字节。 
   ➢ 数据线(`SDA`)为高电平时，规定为非应答位（`NACK`），表示接收器没有成功接收该字节。
5. 当发送方发送完最后一个bit后，需要发送一个结束标志来终止整个通信过程。当时钟线`SCL`为高电平时，
   数据线`SDA` 由低电平向高电平跳变。

![image-20250815215052511](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-02_5a0df160583b74b72c31769a649ade0f.png)

```c
✅总之
1.I2C总线在空闲时，数据线SDA和时钟线SCL两线均为'高电平。
2.特殊信号：
	起始信号：在`SCL`为高时，当`SDA`'从高到低'跳变时表明是起始信号；
	结束信号：在`SCL`为高时，当`SDA`'从低到高'跳变时表明是终止信号。
3.在数据发送时：
	`时钟SCL`高电平时，`数据线SDA`信号'保持稳定'，主机采样；
	`时钟SCL`低电平时，允许`SDA`电平发生变化,为下一bit准备。
4.在时钟脉冲9时，数据发送方释放总线，数据接受方控制总线并回复ACK或NACK。
	 ACK:接受方拉低SDA表示ACK;
	NACK:接收方保持SDA为高电平表示NACK；(相当于接收设备未将总线拉低即就是未回复ACK)
```

## 3. 通过`I2C`写`AT24C02`的时序

![image-20250815211554629](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-02_c778c81abd1923666bfc051a8a16dc7f.png)

![image-20260318204023032](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-02_c488d02d04403672ca67c3bff78796a4.png)

- 主机发送起始信号，所有从机处于聆听状态
- 主机再发送7位从机地址+写命令（0）
- 等待从机回复`ACK`
- 主机发送寄存器地址
- 等待从机回复`ACK`
- 主机连续写入数据，写N字节,从机回复N次`ACK`
- 主机发送停止信号

```c
1. 起始条件：发送起始信号：`SCL`为高时，主设备拉低`SDA`。其他设备接收到起始信号后，从设备都处于聆听状态；
2. 发送从设备地址：发送从设备地址（7位地址 + 写标志位`0`）`0x50<<1`表示 写=======(`0xA0`)；
    写操作'(0x50 << 1) | 0 = 0xA0
    读操作'(0x50 << 1) | 1 = 0xA1
3. 等待应答（`ACK`）：等待从设备应答`ACK：从设备将SDA`拉低；
4. 发送要写入的寄存器的地址：指定写入的`EEPROM`寄存器地址；
5. 等待应答`ACK`：等待从设备应答`ACK：从设备将SDA`拉低；
6. 主设备发送数据：写入1个字节数据，页写可发送多字节数据，但一页大小为8个字节；
7. 等待应答`ACK`:写n个字节应答n次；
8. 停止条件：`SCL`为高时，主设备`SDA`由低到高；
```

## 4. 通过`I2C`读`AT24C02`的时序

![image-20260318204338542](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-02_31cd1e0cabd92efbdfd9ceec60e1dfc8.png)

![image-20260318211023169](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-02_e85b18f2a15bcd1f8c9e1f1a2fdfdfc3.png)

- 主机发送起始信号，所有从机处于聆听状态
- 主机再发送7位从机地址+写命令（0）
- 等待从机回复`ACK`
- 主机发送寄存器地址
- 等待从机回复`ACK`
- 主机重新发送起始信号
- 再发送7位从机地址+读命令（1）
- 等待从机回复`ACK`
- 主机连续读取数据，主机连续读取并回复ACK，在读到最后一字节时回复NACK
- 主机发送`NACK`表示停止读取
- 主机发送终止信号

```c
1. 起始条件：`SCL`为高时，主设备拉低`SDA`。其他设备接收到起始信号后，从设备均处于聆听状态
2. 发送从设备地址标记写：发送从设备地址（7位地址 + 写标志位`0`）0x50<<1 表示  写 ====(`0xA0`)+等待`ACK`
3. 发送寄存器（要读取的内存）地址：指定读取的`EEPROM`寄存器地址 + 等待 `ACK`
4. 重新发送起始信号：SCL为高时，SDA由高到低（关键：前面没有STOP信号）
5. 发送从设备地址标记读：发送从设备地址（7位地址 + 读标志位`1`)0x50<<1 | 1表示  读 ====(`0xA1`)+等待`ACK`
6. 主设备读取数据：从设备返回数据+ 主设备回复`ACK`：主设备拉低SDA
7. 主设备终止读取：读取最后一字节，主设备发送`NACK` （`SCL`为高，`SDA保持高`）表示停止读取
8. 终止条件：`SCL`为高时，`SDA`由低到高
  
    
主机如何知道是最后一个字节？ 
C代码层面，主机的驱动程序内部会维护一个计数器。
对于主机读（Master Receiver）：
主机在接收前 8 个 bit 后，拉低 SDA 发送 ACK，告诉从机“我收到了，请发下一个”。
主机在接收最后一个字节后，拉高 SDA 发送 NACK，告诉从机“我不要了，准备停止”。
```
