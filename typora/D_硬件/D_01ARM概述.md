# ARM

## 1.**什么是RISC、CISC？**

*   **CISC (Complex Instruction Set Computer - 复杂指令集计算机):**
    *   **核心思想：** 设计丰富的、功能强大的指令集，尽可能让单条指令完成复杂的操作（如计算、访存组合），减少程序所需的指令条数。
    *   **特点：**
        *   指令长度不固定，格式多样。
        *   指令执行周期数差异大，复杂指令可能需要多个时钟周期。
        *   硬件复杂度高。
        *   目标：优化编译器的负担，减少程序代码量。
    *   **典型代表：** Intel x86, Motorola 68k。
*   **RISC (Reduced Instruction Set Computer - 精简指令集计算机):**
    *   **核心思想：** 精简指令集，只保留最常用、执行效率最高的简单指令。复杂操作通过组合多条简单指令完成。
    *   **特点：**
        *   指令长度固定，格式规整（利于流水线和译码）。
        *   绝大多数指令在单时钟周期内完成。
        *   采用**加载/存储架构**：运算指令只能操作寄存器中的数据，访存（内存读写）由专门的加载(`LDR`)和存储(`STR`)指令完成。
        *   大量的通用寄存器。
        *   硬连线控制：简单指令通常直接由硬件电路执行，速度快。
        *   目标：提高单条指令的执行速度，优化指令流水线效率。
    *   **典型代表：** ARM, MIPS, RISC-V, PowerPC (早期)

## 2.**冯.诺伊曼架构和哈佛架构有何区别？ARM内核属于哪一种？**

*   **冯·诺伊曼架构 (Von Neumann Architecture):**
    *   **核心特点：** **指令和数据共享同一存储空间（内存）和同一条总线**。
    *   **优点：** 结构简单，设计灵活，成本较低。程序可以作为数据处理（自修改代码）。
    *   **缺点：** **“冯·诺伊曼瓶颈”**：指令和数据争用同一条总线，在需要同时获取指令和数据时（如流水线操作），性能可能受限。
*   **哈佛架构 (Harvard Architecture):**
    *   **核心特点：** **指令和数据存储在两个物理上相互独立的存储空间中（指令存储器、数据存储器），使用两条独立的总线（指令总线、数据总线）进行访问**。
    *   **优点：** 可以同时访问指令和数据，消除了“冯·诺伊曼瓶颈”，**提高了指令吞吐率（尤其是流水线效率）**。更适合实时处理。指令和数据存储器可以有不同的位宽和访问速度。
    *   **缺点：** 结构更复杂，成本更高。程序不能直接修改指令存储器的内容（自修改代码困难）。
*   **ARM内核属于哪一种？**
    *   答案：绝大多数现代ARM内核在核心内部采用改进的哈佛架构，但在芯片外部连接上通常表现为冯·诺伊曼架构。
    *   **具体解释：**
        *   **内部（核心层面）：** ARM处理器核心内部拥有**独立的指令缓存(I-Cache)和数据缓存(D-Cache)**。指令总线和数据总线在核心内部是分离的，允许核心同时从I-Cache取指和向D-Cache读写数据。这是哈佛架构的关键特征，极大地提升了流水线效率。
        *   **外部（系统层面）：** 当访问需要穿透缓存到达主存时，指令和数据最终会通过**同一条系统总线**访问共享的主存空间（DRAM, Flash等）。在这个层次上，它看起来像冯·诺伊曼架构。
    *   因此，ARM内核通常被描述为采用 **“改进的哈佛架构”** 或 **“哈佛总线架构”**，以强调其内部总线分离的特性。

## 3.**ARM内核中都有什么？**

一个典型的ARM处理器内核包含以下关键组件：

* **寄存器组(Register File)：** 包含通用寄存器(R0-R15/部分模式下的影子寄存器)和程序状态寄存器(CPSR/SPSR)。是数据操作和状态存储的核心。

* **算术逻辑单元(ALU - Arithmetic Logic Unit)：** 执行算术运算(加、减等)和逻辑运算(与、或、异或等)。

* **内存管理单元(MMU - Memory Management Unit) / 内存保护单元(MPU - Memory Protection Unit)：** (可选，但现代应用处理器基本都有)

  *   MMU：提供虚拟地址到物理地址的转换（支持虚拟内存）、内存访问权限检查、缓存控制。
  *   MPU：提供内存区域（如代码区、数据区、外设区）的访问权限保护，比MMU简单，无地址转换功能。常用于实时操作系统(RTOS)的微控制器。

* **缓存(Cache)：** 高速小容量存储器，位于核心和主存之间，存放最近访问过的指令和数据副本，显著减少访问主存的延迟。通常分为指令缓存(I-Cache)和数据缓存(D-Cache)。

* **控制单元(Control Unit)：** 指令解码和时序控制的核心。它解析当前指令，产生控制信号来协调寄存器、ALU、移位器、内存接口等部件的工作。

- **PC(**program counter)：程序计数器；**SP**(Stack Pointer)：堆栈指针；**LR**(Link Register):链接寄存器，链接返回，保存当前pc的值或地址。

*   **流水线(Pipeline)：** 将指令执行过程分解为多个阶段（如取指、译码、执行、访存、写回），允许多条指令的不同阶段同时执行，大幅提高吞吐率。ARM7是3级流水线，ARM9是5级，Cortex-A系列可能多达15级甚至更多。
*   **桶形移位器(Barrel Shifter)：** 集成在数据路径中，能高效地执行移位和循环操作（左移、右移、算术/逻辑移位、循环移位），通常可以与ALU操作在一个周期内完成。
*   **协处理器接口(Coprocessor Interface)：** 允许连接专用的硬件协处理器（如浮点运算单元FPU, NEON SIMD单元）来加速特定任务。
*   **总线接口单元(BIU - Bus Interface Unit)：** 负责内核与外部系统总线（如AHB, AXI）的通信，处理内核的取指和访存请求。
*   **调试和跟踪单元(Debug and Trace Unit)：** 提供硬件断点、观察点、指令/数据跟踪等功能，用于软件开发调试和性能分析。
*   **中断控制器接口(GIC Interface)：** 用于连接通用中断控制器(GIC)，处理外部和内部中断信号。

## 4.**ARM有几种工作模式？**

ARM处理器通常有**7种**工作模式：

*   **用户模式(User - usr)：** (1种)
    *   正常程序执行的模式。
    *   权限最低，不能直接访问某些受保护的资源或执行某些特权指令。
*   **特权模式(Privileged Modes)：** (6种)
    *   **系统模式(System - sys)：**
        *   与用户模式使用相同的寄存器组。
        *   具有完全的特权，可以访问所有资源。
        *   供需要特权访问的操作系统任务使用，避免使用其他异常模式。
    *   **异常模式(Exception Modes)：** (5种) 在特定异常事件发生时自动进入。
        *   **快速中断模式(FIQ - fiq)：**
            *   处理高优先级、要求快速响应的中断。
            *   有专用的影子寄存器(R8_fiq-R14_fiq)，加速现场保存/恢复。
        *   **中断模式(IRQ - irq)：**
            *   处理普通优先级的中断。
        *   **管理模式(Supervisor - svc)：**
            *   处理器复位或执行软件中断指令(`SWI`/`SVC`)时进入。
            *   操作系统的保护模式，运行内核代码和系统调用。
        *   **中止模式(Abort - abt)：**
            *   发生内存访问失败（预取指中止或数据中止）时进入。
        *   **未定义模式(Undefined - und)：**
            *   处理器遇到无法识别的指令时进入。
*   ![image-20260314204200359](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_01-54_c94cf1cd27b7c444b8db3af97d1aaec6.png)
*   **为什么需要多种模式？** 主要是为了提供**硬件级别的特权级隔离和异常处理支持**。用户程序在受限的用户模式下运行，操作系统内核或异常处理程序在特权模式下运行，拥有更高的权限访问硬件和关键资源。

## 5.**什么是异常向量表？**

*   **定义：** 异常向量表(Exception Vector Table, EVT)是内存中一块**固定的、连续的、低地址区域**。其中每个位置（称为一个“向量”）存放着一条**跳转指令**（通常是`LDR PC, [PC, #offset]`或`B <handler_address>`）或者直接就是**异常处理程序的入口地址**。
*   **作用**：当特定的**异常事件**（如复位、中断、未定义指令、内存访问错误、软件中断等）发生时，ARM处理器会**硬件自动**执行以下操作：
    
    1.  将当前程序计数器(`PC`)的值（或返回地址）保存到相应异常模式的链接寄存器(`LR`)中。
    2.  将当前程序状态寄存器(`CPSR`)复制到相应异常模式的保存程序状态寄存器(`SPSR_<mode>`)中。
    3.  切换到对应的**异常工作模式**（如IRQ模式、FIQ模式、SVC模式等）。
    4.  根据发生的异常类型，**硬件自动将程序计数器(`PC`)强制跳转到异常向量表中对应的固定地址**（称为“向量地址”）。
    5.  处理器从该向量地址处取出指令开始执行。这条指令通常是跳转到该异常对应的具体处理程序(`Exception Handler`)。
*   **标准向量地址 (ARMv7-A/R 典型情况)：**
    
    *   `0x00000000`: **复位 (Reset)** - 系统上电或复位时跳转到这里。
    *   `0x00000004`: **未定义指令 (Undefined Instruction)**
    *   `0x00000008`: **软件中断 (Software Interrupt / SVC)**
    *   `0x0000000C`: **预取指中止 (Prefetch Abort)** - 取指令时发生内存错误。
    *   `0x00000010`: **数据中止 (Data Abort)** - 访问数据时发生内存错误。
    *   `0x00000014`: **保留 (Reserved)**
    *   `0x00000018`: **IRQ (普通中断)**
    *   `0x0000001C`: **FIQ (快速中断)**

*   **关键点：** 向量表的位置通常是固定的（低地址），但现代ARM处理器（如Cortex-A）通常可以通过配置系统控制寄存器(`SCTLR.V`)将其重定位到其他地址（如`0xFFFF0000`，高地址向量表）。向量表中的条目包含了处理异常的“第一跳”指令或地址。

**当异常发生时，ARM内核会做哪些操作？**
当检测到一个异常事件时，ARM处理器会**完全由硬件自动**执行以下标准操作序列：

1.  **保存返回地址：** 将**当前指令的下一条指令的地址**（即正确返回后应继续执行的指令地址）保存到**新异常模式的链接寄存器(`LR_<mode>`)中**。具体保存的值会根据异常类型和ARM架构版本略有调整（例如，对于IRQ/FIQ，通常是`PC+4`或`PC+8`，确保返回时能正确执行下一条指令）。
2.  **保存处理器状态：** 将**当前程序状态寄存器(`CPSR`)** 的内容复制到**新异常模式的保存程序状态寄存器(`SPSR_<mode>`)中**。这保存了异常发生前的处理器状态（包括条件标志、中断使能位、处理器模式等）。
3.  **切换处理器模式：** 根据发生的异常类型，**硬件自动将`CPSR`中的模式位(M[4:0])设置为对应的异常模式**（如IRQ模式=0x12, FIQ模式=0x11, SVC模式=0x13等）。
4.  **禁用中断 (可选但常见)：**
    *   进入**IRQ模式**时，硬件通常**自动禁用IRQ中断**（设置`CPSR.I = 1`）。
    *   进入**FIQ模式**时，硬件通常**自动禁用FIQ中断**（设置`CPSR.F = 1`）*可能也禁用IRQ*。
    *   进入其他异常模式（如SVC, Abort, Undef）时，硬件**不会自动禁用中断**。通常需要软件处理程序在必要时手动禁用。
5.  **强制跳转到异常向量：** 硬件**强制将程序计数器(`PC`)** 设置为**该异常对应的异常向量地址**（如IRQ异常对应`0x00000018`）。
6.  **执行向量表指令：** 处理器开始从新的PC地址（向量地址）取指并执行。这里存放的指令（跳转指令或地址）会将程序引导到该异常的具体**软件异常处理程序(Exception Handler)**。

*   **软件处理程序的责任：** 硬件完成上述步骤后，控制权就交给了软件编写的异常处理程序。处理程序通常需要：
    *   **保存现场：** 将可能被破坏的**通用寄存器**(R0-R12)压入**新异常模式下的栈**中。注意，异常模式有自己的`SP`(R13)。
    *   **处理异常：** 执行该异常事件需要的具体操作（如读取中断源、处理未定义指令、修复内存错误、执行系统调用服务等）。
    *   **恢复现场：** 从栈中弹出保存的通用寄存器。
    *   **恢复状态并返回：** 使用一条特殊的指令（通常是`SUBS PC, LR, #<offset>`或`MOVS PC, LR`）同时完成：
        *   将保存在`LR_<mode>`中的**返回地址**载入`PC`。
        *   将保存在`SPSR_<mode>`中的**原处理器状态**复制回`CPSR`。这一步**自动将处理器模式切换回异常发生前的模式**。
    *   **重新使能中断 (如果之前被禁用)：** 通常在恢复状态后自动完成（因为`SPSR`恢复了原来的中断使能位）。但有时需要在返回前手动操作。

## 6.什么是立即数？如何判断某数是非法是12位立即数？

1. 直接嵌入在指令中的常量数值（如mov r0，#21中的#21就是立即数）
2. 12位立即数需要满足以下条件：
   1. 如果某个数的数值范围是0~0xFF之间，那么这个数一定是立即数；
   2. 把某个数展开成2进制，这个数的最高位1至最低位1之间的二进制数序列的位数不能超过8位，这个数的二进制序列凑够8位之后的的右边必须为偶数个连续的 0

## 7.b,bl,bx指令的区别是什么？

1. b类似goto，无条件跳转目标地址,不返回。
2. bl，会在LR寄存器中保存回来的地址，多用于`函数调用`
3. bx，常用于函数返回到寄存器（bx LR），且切换状态

```
lable
	mov r1，#20
	bl func
	bx lr
	b finish
	
mov r0，#10
	b  lable

finish
	b finish
```

## 8.ARM内核采用的栈是哪种栈？

​	满减栈，sp栈指针先指向最后一个入栈元素的上一地址，先减指针再填数据。

## 9.arm汇编调用c语言函数以及c语言函数调用汇编编写的函数，函数参数和返回值如何处理？

- ARM汇编调用C语言函数传参：前4个参数依次可用R0，R1，R2，R3寄存器传递R4及其以后需要通过栈指针传递，返回值返回到R0中。

- C语言调用ARM汇编函数传参：汇编函数从R0，R1，R2，R3寄存器中一次读取后续参数需要通过栈中读取，返回值返回到R0中

  注意：汇编调c ，汇编中import声明且保护现场；c调汇编，汇编中export申声明，现场由c保护。两者都需要c中extern。

## 11.什么是编译器、连接器、格式转换器和反汇编器？

```c
1.编译器：将高级语言源代码编译为汇编语言
	arm-linux-gnueabihf-gcc -g -c start.S-o start_.o
	其中“-g”选项是产生调试信息，GDB 能够使用这些调试信息进行代码调试。“-c”选项是编译源 
	文件，但是不链接。“-o”选项是指定编译产生的文件名字
    
2.链接器：将多个目标文件（.o）和库文件合并，生成可执行文件
	arm-linux-gnueabihf-ld -Ttext 0x87800000 start.o -ostart.elf
    -Ttext：指定链接地址
	-o：指定链接生成的文件名

3.格式转换器：转换目标文件的格式，将.elf转换为.bin文件
	arm-linux-gnueabihf-objcopy -O binary -S -g strat.elf start.bin
	-O：指定格式输出
	Binary：表示以二进制格式输出
	-S：表示不复制源文件中的重定位信息和符号信息
	-g：表示不复制源文件中的调试信息

4.反汇编器：将机器码转换成汇编代码
	arm-linux-gnueabihf-objdump -D start.elf > start.dis
	-D：表示反汇编所有的段
```
