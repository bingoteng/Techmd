# 串口通信✅

## 一、基本概念

### 1.**单工、半双工、全双工通信**  

- **单工（Simplex）**：通过一根总线实现数据通信，数据只能实现单向传输不能反向传输，主从固定（如`广播、电视`）。  
- **半双工（Half-Duplex）**：数据可以双向传输，但不能同时进行（如`对讲机`）。  
- **全双工（Full-Duplex）**：数据可以双向同时传输（如`电话、网络通信`）。  

### 2.**串行通信与并行通信**  

- **串行通信**：数据`以比特流形式逐位顺序传输`（如`USB、RS-232`），适合远距离通信，节省线路。 

- **并行通信**：数据多位同时传输，速度快但易受干扰，适合短距离。（RAM--CPU多是并行通信）

### 3.**异步通信与同步通信**

- **异步通信**：无共用时钟，依赖`波特率约定`和`起始位`硬同步，故称为**异步通信**（如`UART`），简单但效率低。  

- **同步通信**：共用时钟信号（如`SPI、I2C`），速率高但需时钟线。  

## 二、`UART`与`TTL/RS232/RS485`与`modbus`之间的关系

### 1、核心概念辨析

```c
1.初级理解：
    ┌─────────────────────────────────────────────────────────────────┐
    │                        串口通信层次架构                           │
    ├─────────────────────────────────────────────────────────────────┤
    │  应用层  │  数据内容 (Modbus/自定义协议等)                          │ ← 定义"说什么"
    ├─────────────────────────────────────────────────────────────────┤
    │  数据链路层  │  UART (数据帧格式：起始位、数据位、校验位、停止位)        │← 定义"用什么传"
    ├─────────────────────────────────────────────────────────────────┤
    │  物理硬件层  │  TTL / RS232 / RS485 (电平标准、传输介质、驱动能力)     │← 定义"怎么传"
    └─────────────────────────────────────────────────────────────────┘
    UART 实际上是横跨物理层和数据链路层的
    与RS232/RS485做对比 ->数据链路层
    与iic和spi对比 ->物理层
2.进一步理解
    ┌─────────────────────────────────────────────────────────────────┐
    │  应用层 (Application)   │  Modbus 协议 / 自定义协议               │ ← 定义"业务含义" (读/写/控制)
    ├─────────────────────────────────────────────────────────────────┤
    │  数据链路层 (Data Link) │  Modbus 帧封装 (地址+功能码+CRC+ 帧间隔)  │ ← 定义"数据包结构" (确保完整消息)
    ├─────────────────────────────────────────────────────────────────┤
    │  物理层 - 逻辑子层      │  UART 外设 (起始位+8数据+停止位+波特率)    │ ← 定义"字节传输规则" (异步成帧)
    ├─────────────────────────────────────────────────────────────────┤
    │  物理层 - 电气子层      │  RS485/RS232/TTL (电气标准/驱动能力/传输介质)│ ← 定义"信号物理形态" (0/1 的电压)
    └─────────────────────────────────────────────────────────────────┘
	
    UART 的核心职责就是定义"一个字节如何拆成位、一位一位地传、再组装回字节"。它是串行通信中最基础、最底层的"搬运工"
```

> [!IMPORTANT]
>
> *理解 UART 的“双重性”，能帮你避开很多坑：*
>
> 1. *调试方向明确：*
>    - *如果 **波形乱了**（电压不对、干扰大）：查 **RS485/电气层**（终端电阻、接地、收发器）。*
>    - *如果 **字节错了**（乱码、错位）：查 **UART/逻辑层**（波特率误差、起始位检测）。*
>    - *如果 **消息断了**（丢包、粘包）：查 **Modbus/链路层**（帧间隔判断、CRC 校验、缓冲区处理）。*
> 2. *代码分层设计：*
>    - *不要在中断里解析 Modbus 协议！*
>    - ***UART 中断**：只负责收字节，放入环形缓冲区 (Ring Buffer)。*
>    - ***主循环/任务**：从缓冲区取数据，根据 **Modbus 帧规则** (如 3.5 字符空闲) 进行解析。*
>    - *理由：UART 是“流式”的，Modbus 是“包式”的。利用 UART 的“物理/链路”双重性，将 **字节接收** 与 **业务解析** 解耦。*
> 3. *硬件选型：*
>    - *板内通信 (MCU↔Flash)：选 **SPI/I2C** (快、无需波特率匹配)。*
>    - *板间短距离 (MCU↔蓝牙)：选 **UART-TTL** (简单、3 根线)。*
>    - *工业长距离 (PLC↔仪表)：选 **UART + RS485 + Modbus** (抗干扰、标准统一)。*

### 2、电平标准：`TTL`

**特点：**

1. 全双工异步串行通信 /低位先行（`LSB`先行）

2. 电气属性：`0v`为逻辑0；`3.3v/5v`为逻辑1

3. 完整帧结构： `96008N1`的一帧数据大小`10bit/字符帧`

   ``` c
   以9600 8 N 1 为例
   
   1.起始位：1位起始位 -'固定'
   2.波特率：9600 bps（bit per second）
   3.数据位：8位数据位
   4.校验位：N (None)无校验
   5.停止位: 1位停止位	
   
       
   N (None)无校验
   'O (Odd) 奇校验：数据位的1加上校验位的1总数是奇数'
   'E (Even)偶校验：数据位的1加上校验位的1总数是偶数'
   
       
   一帧数据：10bit/帧 = 10bit/符
   ┌──────┬────────────────┬────────┬───────┐
   │起始位 │    数据位      │ 校验位 │ 停止位 │
   │  1   │       8        │   0    │   1   │
   └──────┴────────────────┴────────┴───────┘
      ↑          ↑            ↑        ↑
   固定        有效载荷      N=无     可配置
    1位          5-9位      N/O/E      1/2
   ```

4. 理论字节速率：每秒最多传输 **960 个字符（帧）** 的有效数据
   $$
   \frac{9600 \text{ (bits/s)}}{10 \text{ (bits/帧)}} = 960 \text{ 字符帧/s}
   $$

5. 通信理论：

   ```c
   UART中，波特率等于比特率，9600 Baud即9600 bps
   比特率 = 波特率（码元速率，符号率） × 每个符号的比特数
   比特率bps = 波特率Baud  * 每个符号比特数log₂(M)
   M = 调制电平数
   2-PAM---2进制调制---2个电平 M=2  log₂(2) = 1 bit
   4-PAM---4进制调制---4个电平 M=4  log₂(4) = 2 bit
   ```

6. 适用场景:

   1. 点对点 ：(板级通信)
   2. 传输距离：< 1米 
   3. 抗干扰能力弱
   4. 通信速率：2400-115200

## 四、协议层:`Modbus` 协议

### 1. 核心概念
*   **定义**：`Modbus` 是一种应用于电子控制器上的**应用层报文传输协议**。最初由 `Modicon`（现为施耐德电气 Schneider  Electric） 于 1979 年 为其 `PLC`（可编程逻辑控制器）设备开发，是一种`开源、免费`的串行通信 协议，广泛用于工业自动化领域。
*   **地位**：它位于 `OSI `模型的**应用层**，独立于底层物理层。
    *   它可以运行在串行链路（`Modbus RTU,` `Modbus ASCII`）上。
    *   也可以运行在以太网上（`Modbus TCP/IP`）。
*   **架构**：典型的 **主从架构 (Master-Slave)** 或 **客户端/服务器 (Client/Server)**。
    *   **主站 (Master)**：发起请求，同一时刻总线上只能有一个主站。
    *   **从站 (Slave)**：响应请求，**拥有唯一的地址（1-247**）。
*   **广泛应用**：工业自动化、智能仪表、能源管理、楼宇自控等领域

### 2. 三种主要模式对比 

| 特性         | **`Modbus RTU`** (常用)                            | **`Modbus ASCII`** (较少用)                        | `Modbus TCP`(常用)                                          |
| :----------- | :------------------------------------------------- | :------------------------------------------------- | ----------------------------------------------------------- |
| **数据编码** | **二进制** (紧凑，效率高)                          | **ASCII 字符** (人类可读，效率低)                  | 在 `Modbus RTU `基础 上增加了一个 `MBAP `头（7字节）        |
| **帧间隔**   | 依靠**时间间隔** (3.5个字符时间) 判断帧结束        | 依靠**换行符** (`CR`+`LF`) 判断帧结束              | **依靠 `TCP` 报文长度字段界定帧边界**，无需特殊时间间隔     |
| **校验方式** | **`CRC-16`** (循环冗余校验，2字节)                 | **`LRC`** (纵向冗余校验，1字节)                    | 无应用层校验（依赖 TCP 校验和及重传机制保证可靠性）         |
| **传输效率** | 高 (相同数据量字节数少)                            | 低 (约是`RTU`的一半效率)                           | **高**（以太网带宽大，虽有 `MBAP` 头7字节开销但影响可忽略） |
| 通信介质     | `RS485`(半双工、一主多从)或`RS232`(全双工、点对点) | `RS485`(半双工、一主多从)或`RS232`(全双工、点对点) | **以太网**（双绞线/光纤）默认使用 `TCP 502 端 口`           |
| **应用场景** | 工业现场主流，实时性要求高                         | 早期调试，对工具要求低 (可直接看文本)              | 工厂信息化、跨网段/远程监控                                 |

### 3. Modbus RTU 帧结构详解

![image-20260320165708301](https://cdn.jsdelivr.net/gh/bingoteng/Photos/Typora/20260718_02-03_30defda1d81036a0b80992e6bf0e6e41.png)

#### 关键字段解析：

1.  **从机地址 (Address)**：
    *   `1 ~ 247`：有效从站地址。
    *   `0`：广播地址（从站不回复）。
    *   `248 ~ 255`：保留。
2.  **功能码 (Function Code)**：
    *   `01/02`：读线圈/离散输入 (开关量)。
    *   `03/04`：读保持寄存器/输入寄存器 (模拟量，最常用)。
    *   `05/06`：写单个线圈/寄存器。
    *   `15/16`：写多个线圈/寄存器。
    *   `0x80 + 原功能码`：异常响应 (例如：非法地址、非法功能)。
3.  **数据域 (Data)**：
    *   包含起始地址、寄存器数量、写入的数据字节数及具体数据。
    *   **注意字节序**：Modbus 标准是大端模式 (Big-Endian)，但部分传感器内部可能是小端，需在应用层做转换（如 `uint16_t` 高低字节交换）。
4.  **CRC 校验 (Cyclic Redundancy Check)**：
    *   多项式：$X^{16} + X^{15} + X^2 + 1$ (0xA001)。
    *   计算范围：从“从机地址”到“数据域”结束。
    *   **传输顺序**：**低字节先发，高字节后发** (这与通常的大端传输不同，需特别注意)。

### 4. 时序关键：3.5 字符静默时间
*   **机制**：RTU 模式没有起始位和停止位来标记帧的开始和结束，而是依靠**时间间隔**。
*   **规则**：
    *   帧开始前：总线需静默至少 **3.5 个字符时间**。
    *   帧结束后：总线需静默至少 **3.5 个字符时间**，主站才认为下一帧开始。
*   **计算示例** (波特率 9600, 8N1)：
    *   1个字符时间 = 10 bits / 9600 bps ≈ 1.04 ms
    *   3.5 字符时间 ≈ **3.64 ms**
    *   **工程实现提示**：在 STM32 等 MCU 开发中，通常使用定时器或 IDLE 中断来检测这个时间间隔，以判定一帧数据接收完毕。

### 5. 常见寄存器类型 (针对嵌入式开发)

| 类型                               | 地址范围 (协议) | 属性          | 典型应用                          |
| :--------------------------------- | :-------------- | :------------ | :-------------------------------- |
| **线圈 (Coils)**                   | 0xxxx           | 读写 (位)     | 控制继电器开关、LED状态           |
| **离散输入 (Discrete Inputs)**     | 1xxxx           | 只读 (位)     | 读取按钮状态、限位开关            |
| **保持寄存器 (Holding Registers)** | 4xxxx           | 读写 (16-bit) | 设置阈值、配置参数、读取温度/电压 |
| **输入寄存器 (Input Registers)**   | 3xxxx           | 只读 (16-bit) | 读取传感器原始数据、固件版本      |

### 6. 开发中的常见坑点 (基于你的经验关注点)
1.  **响应超时**：从站处理数据慢，主站超时重发导致总线拥堵。需合理设置主站超时时间（通常 > 从站最大处理时间 + 传输时间）。
2.  **字节序问题**：
    *   寄存器是 16 位，但有些传感器传输 32 位浮点数（如温度），涉及 **ABCD, CDAB, BADC, DCBA** 四种字节排列顺序，需根据设备手册调整。
3.  **485 方向控制**：
    *   在发送数据前拉高 DE/RE 引脚，发送完后**不能立即拉低**。
    *   必须等待最后一个字节的**停止位**完全发送完毕后（可通过发送完成中断 TXC 标志），再延时一小段时间（确保总线波形恢复），才能切换为接收模式，否则最后几个字节会丢失或产生噪声。
4.  **广播地址**：发送给地址 `0` 的指令，从站**严禁回复**，否则会导致总线冲突。
