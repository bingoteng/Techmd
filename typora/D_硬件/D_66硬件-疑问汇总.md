# 上下求索

------

## 1.在寄存器配置中**直接赋值（=）**与**指定位置一（|=）**的区别？

- 直接赋值会覆盖原始值，没置1的位置会直接为零
- 指定位置一，其他位不变。原始值会被保留

```
设原始0x00010001
// 直接赋值 (=)
LCDIF->CTRL = (1<<19) | (1<<17) | (3<<10) | (3<<8) | (1<<5);  
// 结果：0x000A0CC0（bit0 和 bit16 被意外清除！）


// 按位或 (|=)
LCDIF->CTRL |= (1<<19) | (1<<17) | (3<<10) | (3<<8) | (1<<5);  
// 结果：0x000B0CC1（保留 bit0 和 bit16）
```

**花括号 `{}` 是 C 语言中用于“初始化结构体”的语法。**

- 第一行 `{.compatible = "pute,puteds18b20"}` 是 **初始化一个 `struct of_device_id` 结构体实例**。
- 第二行 `{}` 是 **一个全零的结构体，作为数组的终止哨兵（sentinel）**，告诉内核匹配表到这里结束。

## 2.结构体变量成员定义{}格式

### 1. `struct of_device_id` 的定义（内核源码中）：

```c
struct of_device_id {
    char    name[32];
    char    type[32];
    char    compatible[128];
    const void *data;
};
```

这是一个用于设备树匹配的结构体，最关键的字段是 `.compatible`。

---

### 2. 数组初始化语法（C99 指定初始化器）

```c
{.compatible = "pute,puteds18b20"}
```

这是 **C99 标准引入的“指定初始化器（designated initializer）”语法**，允许你只初始化结构体中的特定成员，其余成员自动清零。

等价于（旧式写法）：

```c
{"", "", "pute,puteds18b20", NULL}
```

但指定初始化器更清晰、安全、可读性高。

---

### 3. 为什么最后要加 `{}`？

```c
static struct of_device_id ds18b20_of_match_table[] = {
    {.compatible = "pute,puteds18b20"},
    {},  // ← 关键！
};
```

- 这个空 `{}` 表示一个**所有成员都为 0 的 `struct of_device_id`**。
- 在 Linux 内核中，设备树匹配表 **必须以一个全零的条目结尾**，作为“结束标记”。
- 内核函数（如 `of_match_device()`）会遍历这个数组，直到遇到 `.compatible[0] == '\0'`（即空字符串），也就是 `{}` 初始化的那个结构体。

> 📌 类似于 C 字符串以 `\0` 结尾，或 `argv` 以 `NULL` 结尾 —— 这是一种“哨兵模式”。
