# 二、写不出来代码

```
我有一个疑问：我现在完全能看懂别人的代码，但是如果从未思考过这些问题，自己短时间从头写一点思路都没有！往往是使用别人的算法编程思想，如何解决?
```

这是一个**极其普遍且正常**的学习瓶颈，几乎每个程序员（包括资深工程师）都经历过。你并不孤单，这也不是能力问题，而是**认知阶段**的自然表现。

> 🎯 核心原因一句话总结：**看懂是「识别模式」，写出是「构建模式」——两者需要的认知负荷完全不同。**

下面我结合你的嵌入式/C语言背景，给出可落地的解决方案。

---

## 🔍 一、为什么「看得懂」却「写不出」？

| 认知阶段     | 看懂代码                                         | 写出代码                                      |
| ------------ | ------------------------------------------------ | --------------------------------------------- |
| **思维方向** | 顺向推理：已知代码 → 理解意图                    | 逆向构建：已知问题 → 设计代码                 |
| **信息量**   | 作者已帮你做了所有决策（变量名、结构、边界处理） | 你需要从零做出所有决策                        |
| **认知负荷** | 低：只需跟踪执行流                               | 高：需同时考虑算法、语法、边界、内存、效率... |
| **类比**     | 看地图找路 🗺️                                     | 在陌生城市画地图 🗺️✍️                           |

**关键洞察**：你看懂的是「结果」，但写出需要的是「过程」——而过程恰恰是最难迁移的隐性知识。

---

## 🛠️ 二、破局方案：4 步训练法（附嵌入式实例）

### ✅ 第 1 步：「伪代码先行」—— 降低启动门槛
不要一上来就写 C 代码！先用中文/伪代码描述逻辑。

**示例：实现 `mystrlen`**
```text
// ❌ 错误做法：直接敲 code
int mystrlen(char *s) {
    // ...脑子空白...
}

// ✅ 正确做法：先写伪代码
1. 准备一个计数器 count = 0
2. 从字符串第一个字符开始遍历
3. 每遇到一个非'\0'字符，count++
4. 遇到'\0'就停止
5. 返回 count

// 再翻译成 C（此时思路清晰）：
int mystrlen(const char *s) {
    int count = 0;
    while (*s++ != '\0') {  // 或 while (*s) { count++; s++; }
        count++;
    }
    return count;
}
```

> 💡 **技巧**：强迫自己写伪代码时**不用任何语法**，只用「动作 + 条件」描述。这能帮你聚焦算法本质，而非被 `*p++` 这类语法细节卡住。

---

### ✅ 第 2 步：「模板拆解 + 重组」—— 建立代码积木库
你提到「使用别人的算法思想」，这其实是优势！关键是要**主动拆解模板**，而非被动复制。

**以你刚分析的 `mymemmove` 为例：**
```c
// 🧱 拆解出可复用的「思维模板」：
模板1：指针类型转换
   void* → char* 以便按字节操作

模板2：重叠检测逻辑
   if (dest > src && dest < src + n)  // 目标在源之后且重叠

模板3：方向决策
   重叠且目标在后 → 从后向前拷贝
   其他情况 → 从前向后拷贝

模板4：拷贝循环
   while (n--) { *d++ = *s++; }  // 正向
   while (n--) { *d-- = *s--; }  // 反向

// 🎯 下次遇到类似问题（比如字符串插入、数组移位），直接调用模板：
// "这个场景有内存重叠吗？→ 有 → 用 memmove 的方向判断逻辑"
```

> 📌 **行动建议**：每学一个函数，用纸笔或笔记软件整理出它的「决策树」和「代码模板」，形成你的个人算法卡片库。

---

### ✅ 第 3 步：「约束式练习」—— 从小场景刻意训练
不要一上来就挑战「写一个完整驱动」，而是**给自己加约束条件**，降低复杂度：

| 练习类型   | 示例任务                                                     | 训练目标         |
| ---------- | ------------------------------------------------------------ | ---------------- |
| **填空式** | 给出 `mystrcmp` 框架，只让你写循环条件或返回值               | 聚焦关键逻辑点   |
| **改错式** | 故意写一个有 bug 的 `mymemcpy`（如忘记强转 unsigned），让你调试 | 培养边界意识     |
| **变种式** | "如果 `mystrcat` 要求不能覆盖 dest 原有内容，怎么改？"       | 锻炼需求分析能力 |
| **口述式** | 不写代码，口头描述「如何实现环形缓冲区的数据拷贝」           | 强化逻辑表达     |

> 🎯 **嵌入式特供练习**：
> - 用 `memcpy`/`memmove` 思想，实现「串口接收缓冲区的环形移动」
> - 用 `strcmp` 思想，实现「Modbus 寄存器地址的字符串解析匹配」
> - 用指针操作，实现「结构体成员偏移量的手动计算」（理解内存布局）

---

### ✅ 第 4 步：「复盘追问」—— 把别人的思路内化成自己的
看完一段优秀代码后，**强制自己回答 3 个问题**：

```text
1️⃣ 如果让我重命名所有变量，我会怎么起？为什么？
   → 训练「意图表达」能力（变量名是设计的一部分）

2️⃣ 如果需求变化（比如要支持宽字符/线程安全），哪几行代码要改？
   → 训练「扩展性思维」

3️⃣ 这段代码最巧妙的 1 个设计是什么？最脆弱的 1 个假设是什么？
   → 训练「抽象提炼」和「风险意识」
```

**示例：复盘 `mystrcmp` 的 unsigned char 强转**
```text
Q: 为什么不用 (int)*str1 - (int)*str2？
A: 因为 char 可能是 signed，扩展字符会被解释为负数，导致比较错误。

Q: 如果平台 char 默认就是 unsigned，这个强转还有必要吗？
A: 有！为了代码可移植性，不能依赖编译器默认行为。

→ 内化认知：「涉及字节级比较时，永远显式转为 unsigned char」
```
