哈希表（Hash Table），又称散列表，是一种**通过哈希函数将键（Key）值直接映射到存储位置**以实现**平均时间复杂度为O(1)的插入、删除和查找**操作的高效数据结构。其核心思想是**用空间换时间**，通过牺牲一定的内存空间来换取极致的访问速度。

## 一、基本组成  

哈希表的实现主要由两部分构成：**哈希函数（Hash Function）** 和 **冲突解决策略（Collision Resolution）**。

1. **哈希函数（H(key)）**：一个确定性函数，将任意大小的输入（键）映射到固定范围的整数（哈希值/索引）。理想情况下，它应具备**确定性、均匀分布、高效计算**三大特性。
2. **存储桶（Buckets/Slots）**：一个数组，用于存放数据。数组的每个元素称为一个“桶”。
3. **哈希冲突/碰撞（Collision）**：当两个不同的键 `key1` 和 `key2` 经过哈希函数计算后得到相同的哈希值（即 `H(key1) == H(key2)`）时，就会发生冲突。这是哈希表设计中必须解决的核心问题。

```c
1. 键（Key）：用于唯一标识数据的标识符。
2. 值（Value）：与键关联的实际数据。
3. 哈希函数（Hash Function）：将键转换为数组索引的函数。
4. 负载因子（Load Factor, α）：α = 已存储元素数量 / 桶的总数量。它是衡量哈希表填充程度的关键指标，直接影响性能。
5. 冲突（Collision）：不同键映射到同一桶的情况。
```

### 1.1 哈希函数的选择

哈希函数的质量直接决定了哈希表的性能。常见的哈希函数有：

*   ✅**直接定地址**：人口统计0-100岁，将年龄数字作为地址
*   ✅**除留余数法**：`H(key) = key % p` (p通常取小于或等于表长的质数)。
*   **乘法哈希**：`H(key) = floor(M * (A * key mod 1))` (A是一个常数，如 `(sqrt(5)-1)/2`)。
*   **字符串哈希**：如BKDRHash、DJBHash等，专门用于处理字符串键。

在嵌入式系统中，通常选择**计算简单、速度快**的哈希函数，如除留余数法或简单的位运算组合，避免使用MD5、SHA等计算开销大的加密哈希函数。

### 1.2 ✅冲突解决策略

主要有两大类：**链地址法（Separate Chaining）** 和 **开放寻址法（Open Addressing）**。

#### 链地址法（拉链法）

将所有哈希地址相同的元素（即发生冲突的元素）用**单链表**链接起来。哈希表的每个桶不再直接存储数据，而是存储一个指向链表头节点的指针。

*   **优点**：实现简单，对负载因子容忍度高，删除操作方便。
*   **缺点**：需要额外的指针开销，内存不连续，Cache性能较差。

##### 用`list.h`实现链地址哈希表

```c
#ifndef   _HASH_H_
#define   _HASH_H_

#include"list.h"
typedef struct HashNode
{   
    struct list_head phead ;
    int num;
}HashNode_t;


#define  MAXNUM  10


extern struct list_head *create_hashtable(void);
extern  int insert_hashtable(struct list_head *pheadlist, int tmpdata);
extern  int print_hashtable(struct list_head *pheadlist);
extern  void destroy_hashtable(struct list_head *list);

#endif

#include "hash.h"
#include "list.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>



/**
 * @brief Create a hashtable object
 *         1.动态分配一个大小为 MAXNUM（10）的 struct list_head 数组
 *         2.每个元素作为 一个桶的头节点（哨兵）
 *         3.调用 INIT_LIST_HEAD 初始化为 空双向循环链表
 *
 *
 * @return struct list_head* 返回哈希桶数组首地址
 */
struct list_head*create_hashtable()
{
    int i = 0;

    struct list_head *list = (struct list_head *)malloc(MAXNUM * sizeof(struct list_head));
    if (list == NULL)
    {
        return NULL;
    }

    for (i = 0; i < MAXNUM; i++)
    {
        INIT_LIST_HEAD(&list[i]);
    }

    return list;
}

/**
 * @brief   比较两个节点中的num的大小
 *
 * @param pnew      新节点
 * @param pnode     旧结点
 * @return int
 */

static int asc_compare(struct list_head *pnew, struct list_head *pnode)
{
    int new_val = list_entry(pnew, HashNode_t, phead)->num;
    int old_val = list_entry(pnode, HashNode_t, phead)->num;
    if (new_val > old_val)
        return 1;
    else if (new_val < old_val)
        return -1;
    else
        return 0;
}

/**
 * @brief   插入数据
 *
 * @param list  目标哈希数组
 * @param data  数据
 * @return int
 */
int insert_hashtable(struct list_head *list, int data)
{
    int key = data % MAXNUM; // 计算哈希值
    HashNode_t *node = (HashNode_t *)malloc(sizeof(HashNode_t));
    if (NULL == node)
    {
        return -1;
    }
    node->num = data;
    INIT_LIST_HEAD(&node->phead);
    list_add_order(&node->phead, &list[key],asc_compare); // 保证同一桶内数据 从小到大排列

    return 0;
}

/**
 * @brief   打印每个桶的数据
 *
 * @param list
 * @return int
 */
int print_hashtable(struct list_head *list)
{
    int i = 0;
    struct list_head *node = NULL;

    for (i = 0; i < MAXNUM; i++)
    {
        printf("%d:", i);
        list_for_each(node, &list[i])
        {
            printf("%d ", list_entry(node, HashNode_t, phead)->num);
        }
        printf("\n");
    }

    return 0;
}

void destroy_hashtable(struct list_head *list)
{
    for (int i = 0; i < MAXNUM; i++)
    {
        HashNode_t *pos, *tmp;
        // 使用 safe 版本，防止迭代时释放导致悬空
        list_for_each_entry_safe(pos, tmp, &list[i], phead)
        {
            list_del(&pos->phead);
            free(pos);
        }
    }
    free(list);
}
```

#### 开放寻址法（大话ds.p361）

当发生冲突时，**在哈希表的空闲桶中寻找下一个可用位置**来存放新元素。探测序列的生成方式决定了具体的开放寻址法：
*   **线性探测（Linear Probing）**：`H_i = (H(key) + i) % table_size`
*   **二次探测（Quadratic Probing）**：`H_i = (H(key) + c1*i + c2*i²) % table_size`
*   **双重哈希（Double Hashing）**：`H_i = (H1(key) + i * H2(key)) % table_size`

*   **优点**：所有数据都存储在哈希表数组内，内存连续，Cache友好。
*   **缺点**：容易产生“聚集”现象，删除操作复杂（需懒惰删除），对负载因子敏感，通常要求负载因子远低于1。

## 二、✅核心特点  

1. **平均O(1)时间复杂度**：在哈希函数均匀分布且负载因子合理的情况下，插入、删除、查找的平均时间复杂度均为O(1)。
2. **最坏情况O(n)**：当所有键都映射到同一个桶（链地址法）或探测序列很长（开放寻址法）时，退化为线性查找。
3. **空间换时间**：通过预分配较大的存储空间来换取快速的访问速度。
4. **无序性**：哈希表中的元素是无序的，不能像数组或链表那样按插入顺序遍历。
5. **负载因子是关键**：
    - **链地址法**：负载因子可以大于1，但过大会导致链表过长，性能下降。
    - **开放寻址法**：负载因子必须严格小于1（通常建议低于0.75），否则冲突概率剧增，性能急剧恶化。

> [!NOTE]
>
> **关键注意事项**
>
> - **哈希函数设计**：糟糕的哈希函数会导致大量冲突，使哈希表退化为链表，完全丧失性能优势。
> - **动态扩容（Rehashing）**：当负载因子超过阈值时，需要创建一个更大的新哈希表，并将所有旧元素重新哈希（Rehash）到新表中。这是一个**O(n)的昂贵操作**，但能保证后续操作的平均O(1)性能。
> - **内存安全**：
>   - **链地址法**：销毁时必须遍历并释放所有链表节点，防止内存泄漏。
>   - **开放寻址法**：删除操作不能简单置空，否则会破坏探测序列，通常采用“懒惰删除”（标记为已删除状态）。
> - **典型应用场景**：
>   - ✅数据库索引、目录索引
>   - 缓存（如Redis）
>   - 符号表（编译器）
>   - 去重（Set）
>   - ✅快速查找（字典、配置项）

## 三、❌哈希表的分类与实现`❗伪代码`

### 3.1 链地址法（拉链法）C代码实现

链地址法是最常用、最直观的实现方式，尤其适合无法预估数据量的场景。

#### 1. `hashtable.h`

```c
#ifndef __HASHTABLE_H__
#define __HASHTABLE_H__

#include <stdint.h>

// 键值对结构体
typedef struct HashNode {
    char *key;          // 键（字符串）
    int value;          // 值（整数，可替换为void*以支持任意类型）
    struct HashNode *next;
} HashNode_t;

// 哈希表结构体
#define DEFAULT_TABLE_SIZE 16
typedef struct HashTable {
    HashNode_t **buckets; // 指向桶数组的指针（每个桶是一个链表头）
    uint32_t size;        // 当前元素数量
    uint32_t bucket_count; // 桶的总数量
} HashTable_t;

// 辅助函数
extern uint32_t hash(const char *key, uint32_t bucket_count);
extern float getLoadFactor(HashTable_t *ht);

// 核心操作
extern HashTable_t *createHashTable(uint32_t initial_size);
extern int destroyHashTable(HashTable_t **ppht);
extern int put(HashTable_t *ht, const char *key, int value);
extern int get(HashTable_t *ht, const char *key, int *value);
extern int removeKey(HashTable_t *ht, const char *key);

#endif
```

#### 2. `hashtable.c`

```c
#include "hashtable.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/**
 * @brief 简单的字符串哈希函数（BKDRHash变种）
 */
uint32_t hash(const char *key, uint32_t bucket_count)
{
    if (!key) return 0;
    uint32_t hash_val = 0;
    while (*key) {
        hash_val = (hash_val * 31) + *key++;
    }
    return hash_val % bucket_count;
}

float getLoadFactor(HashTable_t *ht)
{
    if (!ht || ht->bucket_count == 0) return -1.0f;
    return (float)ht->size / ht->bucket_count;
}

/**
 * @brief 创建哈希表
 */
HashTable_t *createHashTable(uint32_t initial_size)
{
    if (initial_size == 0) initial_size = DEFAULT_TABLE_SIZE;
    
    HashTable_t *ht = (HashTable_t *)malloc(sizeof(HashTable_t));
    if (!ht) return NULL;
    
    ht->buckets = (HashNode_t **)calloc(initial_size, sizeof(HashNode_t *));
    if (!ht->buckets) {
        free(ht);
        return NULL;
    }
    
    ht->size = 0;
    ht->bucket_count = initial_size;
    return ht;
}

/**
 * @brief 销毁哈希表（必须释放所有节点和桶数组）
 */
int destroyHashTable(HashTable_t **ppht)
{
    if (!ppht || !*ppht) return -1;
    
    HashTable_t *ht = *ppht;
    for (uint32_t i = 0; i < ht->bucket_count; i++) {
        HashNode_t *node = ht->buckets[i];
        while (node) {
            HashNode_t *tmp = node;
            node = node->next;
            free(tmp->key); // 释放key的内存
            free(tmp);
        }
    }
    free(ht->buckets);
    free(ht);
    *ppht = NULL;
    return 0;
}

/**
 * @brief 动态扩容（Rehashing）
 */
static int _rehash(HashTable_t *ht)
{
    uint32_t old_bucket_count = ht->bucket_count;
    HashNode_t **old_buckets = ht->buckets;
    
    // 新桶数量翻倍
    uint32_t new_bucket_count = old_bucket_count * 2;
    HashNode_t **new_buckets = (HashNode_t **)calloc(new_bucket_count, sizeof(HashNode_t *));
    if (!new_buckets) return -1;
    
    // 将旧表中的所有元素重新哈希到新表
    for (uint32_t i = 0; i < old_bucket_count; i++) {
        HashNode_t *node = old_buckets[i];
        while (node) {
            HashNode_t *next = node->next;
            uint32_t new_index = hash(node->key, new_bucket_count);
            node->next = new_buckets[new_index];
            new_buckets[new_index] = node;
            node = next;
        }
    }
    
    ht->buckets = new_buckets;
    ht->bucket_count = new_bucket_count;
    free(old_buckets);
    return 0;
}

/**
 * @brief 插入/更新键值对
 */
int put(HashTable_t *ht, const char *key, int value)
{
    if (!ht || !key) return -1;
    
    // 检查是否需要扩容（负载因子 > 0.75）
    if (getLoadFactor(ht) > 0.75f) {
        if (_rehash(ht) != 0) {
            return -1; // 扩容失败
        }
    }
    
    uint32_t index = hash(key, ht->bucket_count);
    
    // 查找是否已存在该键
    HashNode_t *current = ht->buckets[index];
    while (current) {
        if (strcmp(current->key, key) == 0) {
            current->value = value; // 更新值
            return 0;
        }
        current = current->next;
    }
    
    // 键不存在，创建新节点（头插法）
    HashNode_t *new_node = (HashNode_t *)malloc(sizeof(HashNode_t));
    if (!new_node) return -1;
    
    new_node->key = strdup(key); // 复制key
    if (!new_node->key) {
        free(new_node);
        return -1;
    }
    new_node->value = value;
    new_node->next = ht->buckets[index];
    ht->buckets[index] = new_node;
    ht->size++;
    
    return 0;
}

/**
 * @brief 根据键获取值
 */
int get(HashTable_t *ht, const char *key, int *value)
{
    if (!ht || !key || !value) return -1;
    
    uint32_t index = hash(key, ht->bucket_count);
    HashNode_t *current = ht->buckets[index];
    
    while (current) {
        if (strcmp(current->key, key) == 0) {
            *value = current->value;
            return 0; // 找到
        }
        current = current->next;
    }
    
    return -1; // 未找到
}

/**
 * @brief 删除键值对
 */
int removeKey(HashTable_t *ht, const char *key)
{
    if (!ht || !key) return -1;
    
    uint32_t index = hash(key, ht->bucket_count);
    HashNode_t *current = ht->buckets[index];
    HashNode_t *prev = NULL;
    
    while (current) {
        if (strcmp(current->key, key) == 0) {
            if (prev) {
                prev->next = current->next;
            } else {
                ht->buckets[index] = current->next; // 删除头节点
            }
            free(current->key);
            free(current);
            ht->size--;
            return 0;
        }
        prev = current;
        current = current->next;
    }
    
    return -1; // 未找到
}

```

> 💡 **链地址法设计要点**：
>
> - **头插法 vs 尾插法**：头插法插入更快（O(1)），但会改变链表顺序；尾插法保持插入顺序，但需要遍历到尾部（O(n)）。
> - **动态扩容**：`_rehash`函数是性能关键，虽然单次操作是O(n)，但分摊到每次插入后，平均成本仍是O(1)。
> - **内存管理**：`strdup`用于复制键，确保哈希表拥有键的独立副本，避免外部修改影响内部数据。

### 3.2 开放寻址法（线性探测）C代码实现

开放寻址法将所有数据都存储在连续的数组中，非常适合对Cache性能要求高的场景。



#### 1. `hashtable_open.h`

```c
#ifndef __HASHTABLE_OPEN_H__
#define __HASHTABLE_OPEN_H__

#include <stdint.h>

// 节点状态
typedef enum {
    EMPTY,      // 空桶
    OCCUPIED,   // 已占用
    DELETED     // 已删除（懒惰删除）
} EntryState;

// 哈希表节点
typedef struct HashEntry {
    char *key;
    int value;
    EntryState state;
} HashEntry_t;

// 哈希表结构体
#define DEFAULT_TABLE_SIZE 16
typedef struct HashTableOpen {
    HashEntry_t *entries;   // 连续的存储数组
    uint32_t size;          // 当前元素数量
    uint32_t capacity;      // 数组总容量
} HashTableOpen_t;

// 辅助函数
extern uint32_t hash_open(const char *key, uint32_t capacity);
extern float getLoadFactorOpen(HashTableOpen_t *ht);

// 核心操作
extern HashTableOpen_t *createHashTableOpen(uint32_t initial_capacity);
extern int destroyHashTableOpen(HashTableOpen_t **ppht);
extern int putOpen(HashTableOpen_t *ht, const char *key, int value);
extern int getOpen(HashTableOpen_t *ht, const char *key, int *value);
extern int removeOpen(HashTableOpen_t *ht, const char *key);

#endif
```

#### 2. `hashtable_open.c`

```c
#include "hashtable_open.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

uint32_t hash_open(const char *key, uint32_t capacity)
{
    if (!key) return 0;
    uint32_t hash_val = 0;
    while (*key) {
        hash_val = (hash_val * 31) + *key++;
    }
    return hash_val % capacity;
}

float getLoadFactorOpen(HashTableOpen_t *ht)
{
    if (!ht || ht->capacity == 0) return -1.0f;
    return (float)ht->size / ht->capacity;
}

HashTableOpen_t *createHashTableOpen(uint32_t initial_capacity)
{
    if (initial_capacity == 0) initial_capacity = DEFAULT_TABLE_SIZE;
    
    HashTableOpen_t *ht = (HashTableOpen_t *)malloc(sizeof(HashTableOpen_t));
    if (!ht) return NULL;
    
    ht->entries = (HashEntry_t *)calloc(initial_capacity, sizeof(HashEntry_t));
    if (!ht->entries) {
        free(ht);
        return NULL;
    }
    
    ht->size = 0;
    ht->capacity = initial_capacity;
    return ht;
}

int destroyHashTableOpen(HashTableOpen_t **ppht)
{
    if (!ppht || !*ppht) return -1;
    
    HashTableOpen_t *ht = *ppht;
    for (uint32_t i = 0; i < ht->capacity; i++) {
        if (ht->entries[i].state == OCCUPIED) {
            free(ht->entries[i].key);
        }
    }
    free(ht->entries);
    free(ht);
    *ppht = NULL;
    return 0;
}

/**
 * @brief 查找键的位置（用于put和get）
 * @return 找到返回索引，未找到返回一个可用于插入的空位或DELETED位索引
 */
static int64_t _find_slot(HashTableOpen_t *ht, const char *key)
{
    uint32_t index = hash_open(key, ht->capacity);
    uint32_t start_index = index;
    
    do {
        if (ht->entries[index].state == EMPTY) {
            return (int64_t)index; // 找到空位
        }
        if (ht->entries[index].state == OCCUPIED && 
            strcmp(ht->entries[index].key, key) == 0) {
            return (int64_t)index; // 找到键
        }
        // 线性探测
        index = (index + 1) % ht->capacity;
    } while (index != start_index);
    
    // 表已满
    return -1;
}

/**
 * @brief 动态扩容（Rehashing）
 */
static int _rehash_open(HashTableOpen_t *ht)
{
    uint32_t old_capacity = ht->capacity;
    HashEntry_t *old_entries = ht->entries;
    
    uint32_t new_capacity = old_capacity * 2;
    HashEntry_t *new_entries = (HashEntry_t *)calloc(new_capacity, sizeof(HashEntry_t));
    if (!new_entries) return -1;
    
    // 重建新表
    ht->entries = new_entries;
    ht->capacity = new_capacity;
    ht->size = 0;
    
    for (uint32_t i = 0; i < old_capacity; i++) {
        if (old_entries[i].state == OCCUPIED) {
            putOpen(ht, old_entries[i].key, old_entries[i].value);
            free(old_entries[i].key); // putOpen会复制key
        }
    }
    
    free(old_entries);
    return 0;
}

int putOpen(HashTableOpen_t *ht, const char *key, int value)
{
    if (!ht || !key) return -1;
    
    if (getLoadFactorOpen(ht) > 0.75f) {
        if (_rehash_open(ht) != 0) {
            return -1;
        }
    }
    
    int64_t slot = _find_slot(ht, key);
    if (slot == -1) return -1; // 表已满且扩容失败
    
    uint32_t index = (uint32_t)slot;
    
    // 如果是新插入
    if (ht->entries[index].state != OCCUPIED) {
        ht->entries[index].key = strdup(key);
        if (!ht->entries[index].key) return -1;
        ht->entries[index].state = OCCUPIED;
        ht->size++;
    }
    
    ht->entries[index].value = value;
    return 0;
}

int getOpen(HashTableOpen_t *ht, const char *key, int *value)
{
    if (!ht || !key || !value) return -1;
    
    int64_t slot = _find_slot(ht, key);
    if (slot == -1 || ht->entries[slot].state != OCCUPIED) {
        return -1; // 未找到
    }
    
    *value = ht->entries[slot].value;
    return 0;
}

int removeOpen(HashTableOpen_t *ht, const char *key)
{
    if (!ht || !key) return -1;
    
    int64_t slot = _find_slot(ht, key);
    if (slot == -1 || ht->entries[slot].state != OCCUPIED) {
        return -1; // 未找到
    }
    
    free(ht->entries[slot].key);
    ht->entries[slot].state = DELETED; // 懒惰删除
    ht->size--;
    return 0;
}
```

> 💡 **开放寻址法设计要点**：
>
> - **懒惰删除（Lazy Deletion）**：将删除的桶标记为`DELETED`，而不是`EMPTY`。这样在查找时，遇到`DELETED`会继续探测，而遇到`EMPTY`则停止，保证了探测序列的完整性。
> - **探测循环**：`_find_slot`函数必须处理探测一圈后回到起点的情况，以判断表是否已满。
> - **扩容触发**：由于开放寻址法对负载因子更敏感，通常在负载因子达到0.7左右就应考虑扩容。

## 四、哈希表类型对比与选型指南

### 4.1 链地址法 vs 开放寻址法

| 特性           | 链地址法（拉链法）            | 开放寻址法（线性探测）          |
| -------------- | ----------------------------- | ------------------------------- |
| **内存布局**   | 离散（指针跳转，Cache不友好） | 连续（Cache友好，访问快）       |
| **空间利用率** | 可以 > 1                      | 必须 < 1                        |
| **扩容能力**   | 动态，对负载因子容忍度高      | 对负载因子敏感，需频繁扩容      |
| **操作开销**   | 有指针开销，malloc/free       | 无额外指针，但可能有聚集        |
| **删除操作**   | 简单直接                      | 复杂，需懒惰删除                |
| **嵌入式适用** | ✅ 通用，尤其适合不确定数据量  | ✅ 适合对Cache性能要求极高的场景 |
| **典型场景**   | 通用哈希表、STL unordered_map | Java HashMap (早期)、数据库索引 |

### 4.2 哈希表 vs 其他数据结构

| 特性               | 哈希表（Hash Table）     | 平衡二叉搜索树（如AVL, Red-Black） | 有序数组                    |
| ------------------ | ------------------------ | ---------------------------------- | --------------------------- |
| **查找/插入/删除** | 平均O(1)，最坏O(n)       | O(log n)                           | 查找O(log n)，插入/删除O(n) |
| **内存开销**       | 中等（可能有指针或空桶） | 高（每个节点有多个指针）           | 低（仅数据）                |
| **有序性**         | ❌ 无序                   | ✅ 有序                             | ✅ 有序                      |
| **范围查询**       | ❌ 不支持                 | ✅ 支持                             | ✅ 支持                      |
| **适用场景**       | 快速单点查找、去重       | 需要有序、范围查询                 | 静态数据、只读查找          |

## 五、嵌入式系统中的哈希表实践

### 5.1 静态哈希表（无动态分配）

在资源极度受限的嵌入式环境中，应避免使用`malloc`和`free`。可以预先定义一个固定大小的静态哈希表。

```c
// 静态哈希表（链地址法）
#define STATIC_HT_SIZE 32
static HashNode_t *static_buckets[STATIC_HT_SIZE] = {NULL};

// 所有操作都基于这个静态数组，不进行动态扩容
// 节点可以从一个预分配的内存池中获取
```

### 5.2 面试高频考点

1. **什么是哈希冲突？如何解决？**（必问）
   - **冲突**：不同键映射到同一桶。
   - **解决**：链地址法、开放寻址法（线性/二次/双重哈希）。

2. **负载因子是什么？为什么重要？**
   - **定义**：α = 元素数量 / 桶数量。
   - **重要性**：直接决定冲突概率和性能。开放寻址法通常要求α < 0.75。

3. **链地址法和开放寻址法的优缺点？**
   - **链地址法**：简单，容忍高负载，但有指针开销。
   - **开放寻址法**：内存连续，Cache友好，但对负载敏感，删除复杂。

4. **如何实现动态扩容（Rehashing）？**
   - 创建一个更大的新表。
   - 遍历旧表，将每个元素重新哈希到新表。
   - 释放旧表。

5. **为什么开放寻址法删除要用“懒惰删除”？**
   - 直接置空会破坏探测序列，导致后续查找失败。标记为`DELETED`可以让查找操作正确地越过它继续探测。

6. **一个好的哈希函数应该具备什么特性？**
   - **确定性**：相同输入总是产生相同输出。
   - **均匀分布**：尽可能将键均匀地分散到所有桶中。
   - **高效计算**：计算速度快，开销小。

---

> 💎 **总结**：哈希表是追求极致查找性能的首选数据结构。在嵌入式开发中，**链地址法因其简单性和对负载因子的高容忍度而被广泛采用**。若对Cache性能有极致要求且能精确控制数据量，则可考虑开放寻址法。无论哪种实现，**精心设计的哈希函数、合理的负载因子控制以及健壮的内存管理**都是构建一个高效、可靠哈希表的关键。掌握其核心原理和两种主流实现方式，是应对系统设计和算法面试的必备技能。
