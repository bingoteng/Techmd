## 一、顺序表

### 1.1 基本概念

顺序表（Sequential List）是线性表的一种**基于数组的存储实现方式**，其核心特点是**所有元素在内存中连续存放**，通过物理位置直接反映逻辑顺序。

#### 1.基本组成  
顺序表通常由以下两部分构成：  
1. **存储空间**：一块连续的内存区域（通常用一维数组实现），用于存放数据元素。  
2. **长度信息**：记录当前表中实际存储的元素个数（`length`），以便区分有效数据与未使用空间。
3. 顺序表 = 数组 + 长度管理 + 操作算法

```c
    char sex[6];

      ...           //...缺啥补啥
}Seqlist_t;    //构建通用数据类型结构体--数据容器

Seqlist_t (顺序表对象)
│
├── head ──► [ Datatype ][ Datatype ][ Datatype ] ... [ Datatype ]   ← 连续内存块（数组）
│             (person)    (person)    (person)        (person)
│                ↑          ↑          ↑               ↑
│               下标0      下标1      下标2          下标(tlen-1)
│
├── tlen = 10   // 总容量（最多可存10个元素）
│
└── clen = 2    // 当前已存2个有效元素（占用下标0~1，下标2~9为空但已分配）
```

#### 2.特点  
- **随机访问高效**：可通过下标直接访问任意位置元素，时间复杂度为 **O(1)**。  
- **存储密度高**：仅存储数据本身，无额外指针开销（相比链表更节省空间）。  
- **插入/删除效率低**：在非尾部位置插入或删除元素时，需移动大量元素，平均时间复杂度为 **O(n)**。  
- **容量固定（静态实现）**：若使用静态数组，最大长度需预先定义，可能造成空间浪费或溢出。

### 1.3 优缺点总结

以下是线性表顺序存储（即顺序表）的优缺点总结

| **类别**          | **优点**                                                     | **缺点**                                                     |
| ----------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **存储效率**      | 无需为元素间的逻辑关系（如指针）额外分配存储空间，存储密度高，**内存利用率高**。 | 预先分配固定大小的连续内存空间，若实际元素远少于容量，会造成**空间浪费**；若超过容量，则无法自动扩展（除非手动重新分配）。 |
| **访问性能**      | 支持**随机访问**，通过下标可在 **O(1)** 时间内直接访问任意位置元素（如 `head[i]` 等价于 `*(head + i)`）。 | —                                                            |
| **插入/删除效率** | —                                                            | 插入或删除元素时，通常需要**移动大量元素**以保持连续性，平均时间复杂度为 **O(n)**，在频繁修改的场景下效率低。 |
| **内存管理**      | 内存布局紧凑，对 CPU 缓存友好，遍历性能高。                  | **无法动态调整容量**：初始容量需在程序运行时确定，若需扩容，必须申请新内存、复制旧数据、释放原内存，操作复杂且开销大。 |
| **适用场景**      | 适用于**查询频繁、修改较少**且**数据规模可预估**的场景（如静态配置表、只读缓存）。 | 不适用于**频繁插入/删除**、**数据量波动大**或**无法预知最大规模**的场景。 |

> 💡 **补充说明**：
> - “无法动态存储”更准确的说法是：**容量固定，不支持自动扩容**（不像 C++ `std::vector` 或 Python `list` 那样透明地动态增长）。
> - 虽然可通过 `realloc` 实现“动态顺序表”，但标准顺序表实现通常不包含此功能，且 `realloc` 可能触发整块内存拷贝，仍存在性能代价。

## 二、链表

### 2.1 单向链表

#### 2.1.1 基本概念

单向链表（Singly Linked List）是链表中最基本的一种数据结构，其核心特点是**每个节点只包含一个指向下一个节点的指针**。解决顺序存储的缺点：插入、删除和动态存储问题。 

##### 1.基本组成
一个单向链表由若干个**节点（Node）**组成，每个节点通常包含两个部分：
1. **数据域（data）**：存储实际的数据（可以是任意类型）。
2. **指针域（next）**：指向下一个节点的指针；若为最后一个节点，则该指针为 `NULL`，表示链表结束。

```c
//数据容器
typedef struct person{
    char name[32];
    char sex[6];
    int age;
    float score;
}Datatype; 
//链表节点结构体类型
typedef struct Link_node{
    Datatype data;				//数据域
    struct Link_node *next;		//指针域
}Link_node_t;
//链表结构体类型
typedef struct Link_list{
    Link_node_t *head;			//链表头
    //Link_list_t *tail
    int clen;					//当前链表节点个数
}Linklist_t;

Linklist_t (链表对象)
│
├── head ──► Linknode_t ──► Linknode_t ──► ... ──► NULL
│            │              │
│            ▼              ▼
│         Datatype       Datatype
│         (person)       (person)
│
└── clen = 2   // 表示当前有2个节点
```

##### 2.特点
- **动态性**：链表长度可动态增长或缩减，无需预先分配固定大小的内存。
- **非连续存储**：节点在内存中不要求连续，通过指针链接逻辑顺序。
- **插入/删除高效**：在已知位置插入或删除节点的时间复杂度为 O(1)（前提是已定位到前驱节点）。
- **访问效率低**：不支持随机访问，访问第 k 个元素需从头遍历，时间复杂度为 O(k)。

```c
{
    // 1.参数检测
    if (plist == NULL)
    {
        return -1;
    }
    // 2.初始化双指针和计数器

    Linknode_t *pnext = NULL;
```

#### 2.1.3 顺序表VS单向链表

以下是 **数组（顺序表）** 与 **单向链表** 在数据结构层面的核心区别：

| **特性**              | **数组（顺序表）**<br>`Seqlist_t`（动态数组）                | **单向链表**<br>`Linklist_t`                                 |
| --------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **内存布局**          | **连续内存块**<br>（`malloc` 一次分配一大块）                | **非连续内存**<br>（每个节点独立 `malloc`）                  |
| **空间开销**          | ✅ 低<br>仅存储数据（无额外指针）                             | ❌ 高<br>每个节点需额外 `next` 指针（32位系统多4字节/节点）   |
| **随机访问**          | ✅ **O(1)**<br>`data[i]` 直接计算地址                         | ❌ **O(n)**<br>必须从头遍历                                   |
| **插入/删除（头部）** | ❌ **O(n)**<br>需移动后续所有元素                             | ✅ **O(1)**<br>修改头指针即可                                 |
| **插入/删除（尾部）** | ✅ **O(1)**（若已知长度）<br>但可能需扩容                     | ⚠️ **O(n)**<br>需遍历到尾部（除非维护尾指针）                 |
| **插入/删除（中间）** | ❌ **O(n)**<br>平均移动 n/2 个元素                            | ✅ **O(1)**（已知前驱节点）<br>但查找位置仍需 O(n)            |
| **内存分配**          | - 初始化时预分配固定容量<br>- 扩容需 `realloc`（可能复制全部数据） | - 按需分配节点<br>- 无扩容开销，但频繁 `malloc/free` 可能碎片化 |
| **缓存友好性**        | ✅ **高**<br>连续内存，CPU 缓存命中率高                       | ❌ **低**<br>节点分散，缓存未命中频繁                         |
| **实时性**            | ⚠️ 插入/删除最坏情况耗时长（移动大量数据）                    | ✅ 插入/删除操作时间确定（O(1) 指针操作）                     |
| **适用场景**          | - 数据量固定或变化小<br>- 频繁随机访问<br>- 内存受限且需高效利用（如传感器数据缓冲区） | - 频繁插入/删除（尤其头部）<br>- 数据量动态变化大<br>- 不需要随机访问（如任务队列、日志链） |
| **嵌入式系统考量**    | ✅ 适合资源受限环境：<br>- 无碎片风险<br>- 访问快<br>- 可静态分配（避免堆操作） | ⚠️ 需谨慎使用：<br>- 频繁 `malloc` 可能导致堆碎片<br>- 节点指针增加内存开销<br>- 但适合不确定大小的动态数据 |

### 2.2 双向链表

#### 2.2.2基本概念

​	双向链表（`Doubly Linked List`）是链表的一种增强型线性结构，其核心特点是每个节点包含两个指针：一个指向前驱节点，一个指向后继节点，从而支持双向遍历和更高效的某些操作。

##### 1.基本组成

双向链表由若干个**节点（Node）**组成，每个节点通常包含三个部分：  
1. **数据域（data）**：存储实际数据（类型任意）。  
2. **前驱指针（prev）**：指向当前节点的前一个节点；若为头节点，则为 `NULL`。  
3. **后继指针（next）**：指向当前节点的后一个节点；若为尾节点，则为 `NULL`。

```c
    struct DLink_node *prev;//指针域-前驱
    struct DLink_node *next;//指针域-后驱

```

##### 2.特点

- **双向遍历**：可从前向后（通过 `next`）或从后向前（通过 `prev`）遍历，时间复杂度均为 O(n)。  
- **插入/删除更高效**：若已知目标节点地址，插入或删除操作仅需修改相邻节点的指针，**无需查找前驱**，时间复杂度为 **O(1)**。  
- **内存开销更大**：每个节点多一个指针（相比单向链表增加约 50%~100% 内存，取决于指针与数据比例）。  
- **逻辑更复杂**：指针维护需同时处理 `prev` 和 `next`，易出错（如漏更新、悬空指针）。

```c
{
```

```c
 *

int Insert_pos_DLinklist(DLinknode_t *sentry, Datatype *data, int pos)
{
    if (sentry == NULL || data == NULL || pos <= 0)
    {
        return -1;
    }
    DLinknode_t *p = sentry->next;
    int count = 1;
    while (p != sentry && count < pos)
    {
        p = p->next;
        count++;
    }
    if (pos > count)
    {
        return Insert_tail_DLinklist(sentry, data);//实际位置大于链表长度直接调用尾插
    }
    DLinknode_t *node = (DLinknode_t *)malloc(sizeof(DLinknode_t));
    if (node == NULL)
    {
        return -1;
    }
    memcpy(&node->data, data, sizeof(Datatype));
    //这里是头插的逻辑
    node->next = p;
    node->prev = p->prev;
    p->prev->next = node;
    p->prev = node;
    return 0;
}

 * @return int      成功返回　0 失败返回 -1
 */

{

    {
        return -1;
    }
    DLinknode_t *ptmp = sentry->next;
    while (ptmp != sentry)
    {
        if (fun(&ptmp->data, arg))

            ptmp->prev->next = ptmp->next;
            ptmp->next->prev = ptmp->prev;
            free(ptmp);
```

#### 2.2.4 单向链表VS双向链表

双向有哨兵头节点循环链表 vs 单向无头链表 对比总结

| **特性**       | **双向有哨兵头节点循环链表**<br>`DLinknode_t *sentry`（哨兵自环） | **单向无头链表**<br>`Linklist_t`（head 指向第一个有效节点）  |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **内存结构**   | 每个节点含 `prev` + `next` 两个指针，哨兵节点不存有效数据，构成环形结构 | 每个节点仅含 `next` 指针，`head == NULL` 表示空链表          |
| **是否带哨兵** | ✅ 有哨兵（dummy node），简化边界操作                         | ❌ 无哨兵，插入/删除需特殊处理头节点                          |
| **是否循环**   | ✅ 是（哨兵的 `next` 指向首有效节点，`prev` 指向尾有效节点）  | ❌ 否（尾节点 `next == NULL`）                                |
| **遍历方向**   | ✅ 支持正向（`next`）和反向（`prev`）遍历                     | ❌ 仅支持正向遍历                                             |
| **插入效率**   | - 头插/尾插：**O(1)**（哨兵直接定位）<br>- 任意位置：**O(1)**（若已知目标节点） | - 头插：**O(1)**<br>- 尾插：**O(n)**（需遍历）<br>- 中间：**O(n)**（需找前驱） |
| **删除效率**   | ✅ **O(1)**（已知目标节点时，无需找前驱）                     | ⚠️ **O(n)**（必须通过前驱指针修改链接，需遍历找前驱）         |
| **空链表判断** | `sentry->next == sentry`                                     | `head == NULL` 或 `clen == 0`                                |
| **适用场景**   | - 需频繁在任意位置插入/删除<br>- 需反向遍历（如浏览器历史、LRU缓存）<br>- Linux 内核链表风格 | - 插入/删除集中在头部<br>- 内存敏感或嵌入式环境<br>- 实现栈、队列等简单结构 |

---

💡 补充说明（按你笔记风格）：

- **哨兵节点作用**：消除“空链表”与“非空链表”的逻辑差异，使插入/删除无需特判头节点，提升代码健壮性。
- **循环结构优势**：统一尾部与头部操作逻辑，例如尾插 = “在哨兵前插入”，头插 = “在哨兵后插入”。
- **双向 vs 单向本质区别**：  
  - 单向链表删除必须依赖**前驱指针** → 需遍历；  
  - 双向链表可通过**当前节点自身**完成前后链接 → O(1) 删除。

### 2.3 内核链表(`struct list_head`)

#### 2.3.1 基本概念

内核链表（`struct list_head`）是 Linux 内核中广泛使用的**带哨兵头的双向循环链表**，其核心特点是：  
- **每个节点包含两个指针（`prev` 和 `next`）**，形成双向链接；  
- **链表头（哨兵节点）不存储业务数据**，仅作为入口；  
- **空链表时，头节点的 `next` 和 `prev` 均指向自身**，形成**自环**。  

该设计解决了传统链表在插入/删除时需特殊处理头尾节点的问题，同时支持高效、统一的操作接口，适用于高性能、高可靠性的内核与嵌入式场景。

---

##### 1. 基本组成

内核链表由若干**嵌入式节点**组成，其结构分为两层：

1. **链表节点结构体（`struct list_head`）**：仅包含指针，**不包含数据域**。
2. **宿主结构体（Host Structure）**：**将 `list_head` 作为成员嵌入**，承载实际数据。

```c
// 链表节点结构体（内核定义）
struct list_head {
    struct list_head *next;  // 指向前一个节点
    struct list_head *prev;  // 指向后一个节点
};

// 宿主结构体（用户定义）
typedef struct task {
    int id;
    char name[32];
    struct list_head node;   // 嵌入链表节点
} task_t;

// 链表对象（通常直接使用 list_head 作为头）
struct list_head task_list;  // 哨兵节点，即链表头
```

**逻辑结构图示**：

```
task_list (哨兵节点，链表头)
│
├── next ──► node (task1) ──► node (task2) ──► ... ──┐
│            ▲              │                       │
│            │              ▼                       │
└── prev ◄───┴────────── node (last) ◄──────────────┘

// 空链表时：
task_list.next == &task_list
task_list.prev == &task_list
```

> ✅ **关键区别**：  
> - 传统链表：节点 = 数据 + 指针；  
> - 内核链表：**指针独立存在，数据通过 `container_of` 反向获取**。

---

##### 2. 特点

- **哨兵机制（Sentinel）**：  
  链表头始终存在，无需判断空链表，所有操作（插入/删除）逻辑统一。

- **双向循环**：  
  支持从前向后或从后向前遍历；尾节点的 `next` 指向头，头节点的 `prev` 指向尾。

- **嵌入式设计（Intrusive）**：  
  `list_head` 作为成员嵌入任意结构体，**零内存冗余**，避免额外指针开销。

- **高效操作**：  
  - 插入/删除：**O(1)**（已知相邻节点）；  
  - 遍历：**O(n)**，但支持正向/反向；  
  - 不支持随机访问（需遍历）。

- ❌**高度安全**：  
  - 删除后毒化指针（`LIST_POISON1/2`）防止误用；  
  - 启用 `CONFIG_LIST_HARDENED` 时，运行时校验链表完整性；  
  - 使用 `WRITE_ONCE`/`READ_ONCE` 保证 SMP 内存序。

- **通用性**：  
  同一套 `list_head` 可用于管理任意类型的数据结构（如进程、文件、设备等）。

> [!NOTE]
>
> ***“链表不是容器，而是粘合剂。”**  
> —— `list_head` 不拥有数据，而是将数据结构“串”起来，实现**解耦、复用、高效**。*

##### 2.基础操作（基于简单用户态`list.h`）

```c
LIST_HEAD_INIT(&head);

    **********************************************************
    2.增(头插，尾插)
    1.头插调用(将new插入到哨兵头之后)

    static inline void __list_add(struct list_head *new,
                                  struct list_head *prev,
                                  struct list_head *next)
{
    if (!__list_add_valid(new, prev, next))
        return;

    next->prev = new;//接纳：后节点的前驱更新为新节点
    new->next = next;//加入：新节点后驱更新为后节点
    new->prev = prev;//加入：新节点前驱更新为前节点
    WRITE_ONCE(prev->next, new);//接纳：前节点的后驱更新为新节点
}

     * list_add - add a new entry
     * @new: new entry to be added
     * @head: list head to add it after
     *
     * Insert a new entry after the specified head.
     * This is good for implementing stacks.

static inline void list_add(struct list_head *new, struct list_head *head)
{
    __list_add(new, head, head->next);//新节点插入到head的next
}
*****************************************************************

    list_add_tail(new, head)

    /**
     * list_add_tail - add a new entry
     * @new: new entry to be added
     * @head: list head to add it before

     * Insert a new entry before the specified head.
     * This is useful for implementing queues.

    static inline void list_add_tail(struct list_head *new, struct list_head *head)

}
```
