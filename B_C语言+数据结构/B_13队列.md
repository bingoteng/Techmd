# 队列

[TOC]

------

队列（Queue）是一种**先进先出（FIFO, First In First Out）** 的线性数据结构（*`双端受限的线性表`*），其核心特点是**插入（入队）操作限定在队尾（Rear）进行，删除（出队）操作限定在队头（Front）进行**，形成单向数据流动通道。

> [!CAUTION]
>
> 要求：大量练习深入了解

## 一、基本组成  

队列的实现主要有三种方式：**顺序队列（`基于数组`）**、**循环队列（`顺序队列优化`）** 和 **链式队列（`基于链表`）**。逻辑上均包含：

1. **存储空间**：存放队列元素（数组或链表节点）。
2. **队头指针（Front）**：指向队列首元素位置，出队操作从此端进行。
3. **队尾指针（Rear）**：指向队列尾元素的**下一个空位置**，入队操作从此端进行。

```c
1. 队头（Front）：允许出队操作的一端
2. 队尾（Rear） ：允许入队操作的一端
3. 入队（Enqueue）：在队尾插入新元素
4. 出队（Dequeue）：在队头移除元素
5. 空队列：front == rear（具体条件取决于实现方式）
```

### 1.1 顺序队列定义（C）

```c
typedef struct Person
{
    char name[32];
    char sex[6];
    int age;
    float score;
} DataType;

// 顺序队列结构体（存在假溢出问题）
#define MAX_SIZE 100
typedef struct SeqQueue
{
    DataType data[MAX_SIZE];  // 存储元素的数组
    int front;                // 队头指针：指向首元素
    int rear;                 // 队尾指针：指向尾元素的下一个空位置
} SeqQueue_t;
```

*顺序队列：rear向右移动，front向右移动，产生"假溢出"（rear=MAX_SIZE但front>0)*

## 二、核心特点  

1. **操作受限**：**双端单向操作** — 入队仅在队尾，出队仅在队头，不支持中间插入/删除。
2. **先进先出（FIFO）**：最早入队的元素最先被移除。
3. **顺序队列缺陷**：
   - ❌**假溢出（False Overflow）**：rear到达数组末尾时，即使front前方有空位也无法继续入队。
   - ❌**空间浪费**：需频繁整体迁移数据（时间复杂度O(n)），不适合嵌入式实时场景。
4. ✅**循环队列优势**：
   - 通过取模运算实现逻辑循环，彻底解决假溢出。
   - 空间利用率100%，操作时间复杂度O(1)。
5. ✅**链式队列优势**：
   - 动态扩容，无容量限制。
   - 缺点：每个节点需额外指针开销，频繁malloc/free影响实时性。

> [!NOTE]
>
> **关键注意事项**
>
> - **循环队列判空/判满**：需特殊设计（见3.2节），否则`front==rear`无法区分空/满状态。
> - **取模运算优化**：嵌入式中`%`运算较慢，当`MAX_SIZE`为2的幂时，可用`& (MAX_SIZE-1)`替代（如`rear = (rear + 1) & 0x3F`代替`%64`）。
> - **内存安全**：
>   - 顺序队列：入队前必须判满，避免数组越界（嵌入式致命错误）。
>   - 链式队列：销毁时必须遍历释放所有节点，防止内存泄漏。
> - **典型应用场景**：缓冲机制、速度不匹配
>   - 消息队列（RTOS任务间通信）
>   - 环形缓冲区（串口DMA接收）
>   - 任务调度（时间片轮转）
>   - 广度优先搜索（BFS）

## 三、队列的分类与实现

### 3.1 顺序队列的缺陷：假溢出

```c
DataType a[5] ---下标0 - 4
初始状态: front=0, rear=0 → 空队列
    					 front0	rear3
    					  ↓		↓
入队3次: front=0, rear=3 → [A,B,C,_,_]
    			              f2r3
    					      ↓	↓
出队2次: front=2, rear=3 → [_,_,C,_,_]
    
再入队2次: 当rear=5(MAX_SIZE)溢出 → 拒绝入队（*假溢出*！实际有数组中还有2个空位，rear指针无法回退）
```

> 💡 **根本原因**：线性存储无法利用front前方的空闲空间  
> ✅ **解决方案**：循环队列（逻辑上将数组首尾相连）

---

### 3.2 循环队列的三种判满方案

| 方案            | 判空条件                 | 判满条件                 | 空间利用率  | 优缺点                 |
| --------------- | ------------------------ | ------------------------ | ----------- | ---------------------- |
| ✅**预留空间法** | `front == rear`          | `(rear+1)%MAX == front`  | (MAX-1)/MAX | ✅ 逻辑简洁，无额外开销 |
| **计数器法**    | `count == 0`             | `count == MAX`           | 100%        | ⚠️ 需维护额外计数器     |
| **标志位法**    | `flag==0 && front==rear` | `flag==1 && front==rear` | 100%        | ⚠️ 需维护额外标志位     |

> ✅ **推荐预留空间法理由**：
>
> - 无需额外变量，节省RAM（嵌入式关键资源）
> - 逻辑清晰，边界条件明确
> - 与Linux内核环形缓冲区（kfifo）设计思想一致
> - 面试官期望看到的"生产级"实现

#### 预留空间法状态机

```c
// MAX_SIZE = 5 时的状态转换,下标维护，最后一处空间为保留位。
空队列:  front=0, rear=0          → 元素数=0
入队A:   rear=(0+1)%5=1           → [A,_,_,_,_]
入队B:   rear=(1+1)%5=2           → [A,B,_,_,_]
入队C:   rear=(2+1)%5=3           → [A,B,C,_,_]
出队A:   front=(0+1)%5=1          → [_,B,C,_,_]
入队D:   rear=(3+1)%5=4           → [_,B,C,D,_]
    
入队E:   rear=(4+1)%5=0 → 满队！   → [E,B,C,D,_]  (rear+1)%5=1 == front=1
```

> ⚠️ **关键点**：牺牲1个存储单元区分空/满状态，`MAX_SIZE`实际可用容量为`MAX_SIZE-1`

#### 循环队列（预留空间法）C代码实现

##### 1. `circlequeue.h`

```c
#ifndef __CIRCLEQUEUE_H__
#define __CIRCLEQUEUE_H__

typedef struct Person
{
    char name[32];
    char sex[6];
    int age;
    float score;
} DataType;

#define MAX_SIZE 100  // 实际可用容量: MAX_SIZE-1

// 循环队列结构体（预留空间法）
typedef struct CircleQueue
{
    DataType data[MAX_SIZE];//静态数组
    int front;  // 队头：指向首元素
    int rear;   // 队尾：指向尾元素的下一个空位置
} CircleQueue_t;

// 辅助函数
extern int getSizeCircleQueue(CircleQueue_t *cq);
extern int isEmptyCircleQueue(CircleQueue_t *cq);
extern int isFullCircleQueue(CircleQueue_t *cq);
extern DataType *getFrontCircleQueue(CircleQueue_t *cq);

// 核心操作（闭眼必会）
extern CircleQueue_t *createCircleQueue();
extern int destroyCircleQueue(CircleQueue_t **ppcq);
extern int enqueueCircleQueue(CircleQueue_t *cq, DataType *data);
extern int dequeueCircleQueue(CircleQueue_t *cq);
extern void showCircleQueueFront(CircleQueue_t *cq);

#endif

```

> [!NOTE]
>
> 注意另一种表头设计
>
> ```c
> typedef struct CircleQueue
> {
>     DataType *data;//数组首元素地址
>     int front;  // 队头：指向首元素
>     int rear;   // 队尾：指向尾元素的下一个空位置
>     int tlen //数组大小
> } CircleQueue_t;
> 此种循环队列的表头结构
> ```
>
> **两种表头结构差异：**
> *第一种只需 `free(queue)` 一次；第二种需要先 `free(queue->data)` 再 `free(queue)`，共两次。*
>
> **依据：**
>
> - *结构1：`data` 是内联数组，与结构体共享同一块堆内存。*
> - *结构2：`data` 是指针，指向另一块独立的堆内存*。
>
> *你能对比两种设计的销毁差异，说明你已触及**内存所有权**和**资源管理**的核心问题！第一种是**单一所有权**，结构体持有全部数据，释放简单；第二种是**分层所有权**，结构体与数据缓冲区分离，释放需按申请逆序进行。*

##### 2. `circlequeue.c`

```c
#include "CircleQueue.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/**✅
 * @brief 获取队列当前元素数量（关键公式）
 * 公式: (rear - front + MAX_SIZE) % MAX_SIZE
 * 说明: 
 *   - 当rear >= front: rear - front
 *   - 当rear < front:  rear - front + MAX_SIZE（跨过数组末尾）
 */
int getSizeCircleQueue(CircleQueue_t *cq)
{
    if (!cq) return -1;
    return (cq->rear - cq->front + MAX_SIZE) % MAX_SIZE;
}

/**✅
 * @brief 判空：front == rear 时空队列
 */
int isEmptyCircleQueue(CircleQueue_t *cq)
{
    if (!cq) return -1;
    return cq && (cq->front == cq->rear);
}

/**✅
 * @brief 判满：(rear+1)%MAX_SIZE == front 时满队列（预留1个空间）
 */
int isFullCircleQueue(CircleQueue_t *cq)
{
    if (!cq) return -1;
    return (cq->rear + 1) % MAX_SIZE == cq->front;
}

/**
 * @brief 1. 创建空队列（初始化：front=rear=0）
 * 
 * */
CircleQueue_t *createCircleQueue()
{
    CircleQueue_t *cq = (CircleQueue_t *)malloc(sizeof(CircleQueue_t));
    if (!cq) {
        printf("createCircleQueue malloc failed\n");
        return NULL;
    }
    cq->front = 0;
    cq->rear = 0;
    return cq;
}

/**
 * @brief 2. 销毁队列（仅释放控制结构，静态数组无需逐元素free）
 * 
 * @param ppcq 二级指针　循环队列表头(本身是地址)的地址
 * @return int 
 */
int destroyCircleQueue(CircleQueue_t **ppcq)
{
    if (!ppcq || !*ppcq) return -1;
    free(*ppcq);
    *ppcq = NULL;
    return 0;
}

/**
 * @brief 3. 入队（Enqueue）- 预留空间法操作逻辑：
 *          1. 检查是否满队
 *          2. 将数据存入rear位置
 *          3. rear = (rear + 1) % MAX_SIZE
 * @param cq    目标队列
 * @param data  插入数据元素
 * @return int 
 */
int enqueueCircleQueue(CircleQueue_t *cq, DataType *data)
{
    if (!cq || !data || isFullCircleQueue(cq)) {
        return -1;
    }
    cq->data[cq->rear] = *data;               // 存入当前rear位置
    cq->rear = (cq->rear + 1) % MAX_SIZE;     // 移动到下一个空位
    return 0;
}

/**
 * @brief 4. 出队（Dequeue）- 操作逻辑：
 *          1. 检查是否空队
 *          2. front = (front + 1) % MAX_SIZE（逻辑删除，无需物理清除）
 */
int dequeueCircleQueue(CircleQueue_t *cq)
{
    if (!cq || isEmptyCircleQueue(cq)) {
        return -1;
    }
    cq->front = (cq->front + 1) % MAX_SIZE;   // 丢弃front位置数据
    return 0;
}

/**
 * @brief 5. 读取队头元素（不删除）
 */
DataType *getFrontCircleQueue(CircleQueue_t *cq)
{
    if (!cq || isEmptyCircleQueue(cq)) {
        return NULL;
    }
    return &(cq->data[cq->front]);  // 队头元素在front位置
}

/**
 * @brief 打印队头元素
 */
void showCircleQueueFront(CircleQueue_t *cq)
{
    DataType *front = getFrontCircleQueue(cq);
    if (!front) return;
    printf("name: %-10s sex: %-6s age: %-3d score: %.2f\n",
           front->name, front->sex, front->age, front->score);
}
```

> 💡 **嵌入式优化技巧**：  
> 当`MAX_SIZE`为2的幂（如64、128）时，将取模运算替换为位运算：  
>
> ```c
> // 原始: rear = (rear + 1) % 64;
> // 优化: rear = (rear + 1) & 0x3F;  // 0x3F = 63 = 64-1
> ```
> 位运算速度比`%`快5-10倍（ARM Cortex-M实测），适用于高频中断场景。

### 3.3 链式队列C代码实现

#### 1. `linkqueue.h`

```c
#ifndef __LINKQUEUE_H__
#define __LINKQUEUE_H__

typedef struct Person
{
    char name[32];
    char sex[6];
    int age;
    float score;
} DataType;

// 链式队列节点
typedef struct LinkQueueNode
{
    DataType data;
    struct LinkQueueNode *next;
} LinkQueueNode_t;

// 链式队列控制结构（带头尾双指针）
typedef struct LinkQueue
{
    LinkQueueNode_t *front;  // 队头：指向首节点（实际数据节点）
    LinkQueueNode_t *rear;   // 队尾：指向尾节点
    int size;                // 元素计数（可选，用于O(1)获取大小）
} LinkQueue_t;


// 辅助函数

extern int getSizeLinkQueue(LinkQueue_t *lq);
extern int isEmptyLinkQueue(LinkQueue_t *lq);
extern DataType *getFrontLinkQueue(LinkQueue_t *lq);

// 核心操作（闭眼必会）

extern LinkQueue_t *createLinkQueue();
extern int destroyLinkQueue(LinkQueue_t **pplq);
extern int enqueueLinkQueue(LinkQueue_t *lq, DataType *data);
extern int dequeueLinkQueue(LinkQueue_t *lq);
extern void showLinkQueueFront(LinkQueue_t *lq);

#endif
```

#### 2. `linkqueue.c`

```c
#include "LinkQueue.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int getSizeLinkQueue(LinkQueue_t *lq)
{
    return lq ? lq->size : -1;
}

int isEmptyLinkQueue(LinkQueue_t *lq)
{
    return lq && (lq->size == 0);
}

✅单向（有哨兵头）节点链式队列
/**
 * @brief 1. 创建空队列（带哨兵节点简化边界处理）
 *          哨兵节点：front指向空节点，rear初始指向该节点
 *          优点：入队/出队无需特殊处理空队列情况
 */
LinkQueue_t *createLinkQueue()
{
    LinkQueue_t *lq = (LinkQueue_t *)malloc(sizeof(LinkQueue_t));
    if (!lq) {
        printf("createLinkQueue malloc failed\n");
        return NULL;
    }
    
    // 创建哨兵节点（不存储有效数据）
    LinkQueueNode_t *dummy = (LinkQueueNode_t *)malloc(sizeof(LinkQueueNode_t));
    if (!dummy) {
        free(lq);
        return NULL;
    }
    dummy->next = NULL;
    
    lq->front = dummy;  // front始终指向哨兵节点
    lq->rear = dummy;   // rear初始指向哨兵节点
    lq->size = 0;
    return lq;
}

/**
 * @brief 2. 销毁队列（必须遍历释放所有节点，含哨兵节点）
 * 
 * @param pplq  二级指针
 * @return int 
 */
int destroyLinkQueue(LinkQueue_t **pplq)
{
    if (!pplq || !*pplq) return -1;
    
    LinkQueue_t *lq = *pplq;
    LinkQueueNode_t *cur = lq->front;  // 从哨兵节点开始
    
    while (cur) {
        LinkQueueNode_t *tmp = cur;
        cur = cur->next;
        free(tmp);
    }
    
    free(lq);
    *pplq = NULL;
    return 0;
}

/**
 * @brief 3. 入队（尾插）- 哨兵节点简化逻辑：
 *          1. 创建新节点
 *          2. rear->next = newnode
 *          3. rear = newnode 
 **/
int enqueueLinkQueue(LinkQueue_t *lq, DataType *data)
{
    if (!lq || !data) return -1;
    
    LinkQueueNode_t *newnode = (LinkQueueNode_t *)malloc(sizeof(LinkQueueNode_t));
    if (!newnode) {
        printf("enqueueLinkQueue malloc failed\n");
        return -1;
    }
    newnode->data = *data;
    newnode->next = NULL;
    
    lq->rear->next = newnode;  // 当前尾节点指向新节点
    lq->rear = newnode;        // 新节点更新为新的尾节点rear
    lq->size++;
    return 0;
}

/**
 * @brief 4. 出队（头删）- 哨兵节点保证front->next始终有效：
 *          1. 检查是否空队（size==0）
 *          2. 保存front->next（首数据节点）
 *          3. front->next = front->next->next
 *          4. 若队列变空，rear回退到哨兵节点
 *          5. 释放原首节点
 */
int dequeueLinkQueue(LinkQueue_t *lq)
{
    if (isEmptyLinkQueue(lq)) return -1;
    
    LinkQueueNode_t *delnode = lq->front->next;  // 首数据节点
    lq->front->next = delnode->next;             // 哨兵节点指向下一节点
    
    // 特殊情况：出队后队列变空，rear需回退到哨兵节点
    if (lq->front->next == NULL) {
        lq->rear = lq->front;
    }
    
    free(delnode);
    lq->size--;
    return 0;
}

/**
 * @brief 5. 读取队头元素（不删除）
 */
DataType *getFrontLinkQueue(LinkQueue_t *lq)
{
    if (isEmptyLinkQueue(lq)) return NULL;
    return &(lq->front->next->data);  // 哨兵节点的next即首数据节点
}

/**
 * @brief 打印队头元素
 */
void showLinkQueueFront(LinkQueue_t *lq)
{
    DataType *front = getFrontLinkQueue(lq);
    if (!front) return;
    printf("name: %-10s sex: %-6s age: %-3d score: %.2f\n",
           front->name, front->sex, front->age, front->score);
}
```

> 💡 **哨兵节点设计价值**：  
> - 消除空队列特殊判断（`front`和`rear`永不为NULL）  
> - 入队/出队逻辑统一，代码更健壮  
> - 与Linux内核链表（list_head）设计思想一致，适合系统级编程

## 四、队列类型对比与选型指南

### 4.1 顺序循环队列 vs 链式队列

| 特性           | 顺序循环队列（预留空间法）      | 链式队列（带哨兵）            |
| -------------- | ------------------------------- | ----------------------------- |
| **内存布局**   | 连续（Cache友好，访问快）       | 离散（指针跳转，Cache不友好） |
| **空间利用率** | (MAX-1)/MAX（牺牲1单元）        | 100%                          |
| **扩容能力**   | 固定容量（需预估MAX_SIZE）      | 动态扩容                      |
| **操作开销**   | 无malloc/free（实时性极高）     | 频繁malloc/free（碎片风险）   |
| **嵌入式适用** | ✅✅ **强烈推荐**（RTOS消息队列） | ⚠️ 仅用于不定长数据流          |
| **典型场景**   | 串口DMA环形缓冲、任务消息队列   | 网络数据包队列（长度不定）    |

### 4.2 栈 vs 队列 核心对比

| 特性           | 栈（Stack）                    | 队列（Queue）              |
| -------------- | ------------------------------ | -------------------------- |
| **操作原则**   | LIFO（后进先出）               | FIFO（先进先出）           |
| **操作端**     | 单端（仅栈顶）                 | 双端受限（队头出，队尾入） |
| **指针数量**   | 1个（top）                     | 2个（front + rear）        |
| **典型应用**   | 函数调用、括号匹配、表达式求值 | 任务调度、消息传递、BFS    |
| **嵌入式场景** | 中断上下文保存、递归模拟       | 串口缓冲、RTOS消息队列     |

## 五、嵌入式系统中的队列实践

### 5.1 环形缓冲区（Ring Buffer）设计要点

```c
// STM32串口DMA接收环形缓冲区（简化版）
#define RX_BUF_SIZE 256  // 必须为2的幂

volatile uint8_t rx_buf[RX_BUF_SIZE];
volatile uint16_t rx_head = 0;  // DMA写入位置（相当于rear）
volatile uint16_t rx_tail = 0;  // 应用读取位置（相当于front）

// DMA传输完成中断中更新head
void DMA1_Channel5_IRQHandler(void) {
    if (DMA_GetITStatus(DMA1_IT_TC5)) {
        rx_head = (rx_head + DMA_GetCurrDataCounter(DMA1_Channel5)) & (RX_BUF_SIZE-1);
        DMA_ClearITPendingBit(DMA1_IT_TC5);
    }
}

// 应用层读取数据（非阻塞）
int32_t read_uart_data(uint8_t *buf, uint16_t len) {
    uint16_t available = (rx_head - rx_tail + RX_BUF_SIZE) & (RX_BUF_SIZE-1);
    uint16_t to_read = (len < available) ? len : available;
    
    for (uint16_t i = 0; i < to_read; i++) {
        buf[i] = rx_buf[(rx_tail + i) & (RX_BUF_SIZE-1)];
    }
    rx_tail = (rx_tail + to_read) & (RX_BUF_SIZE-1);
    return to_read;
}
```

> ⚠️ **关键安全设计**：
> 1. `rx_head`由DMA硬件更新，必须声明为`volatile`
> 2. 读写操作需考虑中断竞争，关键段应关闭中断（`__disable_irq()` / `__enable_irq()`）
> 3. `RX_BUF_SIZE`必须为2的幂，确保位运算正确性
> 4. 避免在中断中执行复杂逻辑，仅更新指针

### 5.2 面试高频考点

1. **循环队列判空/判满条件**（必问）：
   - 预留空间法：空=`front==rear`，满=`(rear+1)%MAX==front`
   - 为什么牺牲1个空间？→ 区分空/满的二义性

2. **循环队列元素数量计算**：
   - 公式：`(rear - front + MAX_SIZE) % MAX_SIZE`
   - 为什么加`MAX_SIZE`？→ 处理`rear < front`的跨边界情况

3. **链式队列为何用哨兵节点**？
   - 消除空队列特殊判断，简化边界逻辑
   - 与Linux内核链表设计思想一致

4. **嵌入式为何优先选循环队列**？
   - 无动态内存分配，避免堆碎片
   - 连续内存，Cache命中率高
   - 操作确定性（O(1)），满足实时性要求

5. **环形缓冲区与循环队列的关系**？
   - 环形缓冲区是循环队列在嵌入式中的具体应用
   - 通常结合DMA/中断实现零拷贝数据流

---

> 💎 **总结**：在嵌入式开发中，**循环队列（预留空间法）是队列实现的黄金标准**。它以极小的空间代价（1个单元）换取了确定性的O(1)操作、零动态内存分配、以及与硬件DMA的天然契合性，完美契合资源受限、实时性要求高的嵌入式场景。掌握其判空/判满条件、元素计数公式及位运算优化，是嵌入式工程师的必备技能。
