## 一、如何理解程序 = 算法 + 数据结构

### 1.1 算法(algorithm)

```c
1.广义：对解决特定问题的求解方法/步骤的描述就称为 "算法"。
	1.做任何事都有一定的步骤，要求计算机进行操作的步骤。
	2.算法是解决"做什么"和"怎么做"的问题,算法是程序的"灵魂"。
2.特征:
	1，输入/输出特性，输入是可选的，输出是必须的。没有输出的算法没有意义。
	2，有穷性，执行的步骤会自动结束，不能是死循环，并且每一步是在可以接受的时间内完成。 
	3，确定性，同一个输入，会得到唯一的输出。
	4，可行性，每一个步骤都是可以实现的。
```

### 1.2 数据结构(Data Structure)

```c
1.数据：可输入/输出，计算机可操作的对象 //任意变量
2.数据项：若干数据项组成一个数据元素	 //结构体成员
3.数据元素：组成数据、有意义的基本单位//struct结构体
4.数据对象：性质相同的数据元素的集合
5.数据结构：相互之间存在一种或多种特定关系的数据元素的集合。
```

## 二、为什么需要数据结构？

```c
// ✅ 定义商品数据结构
typedef struct Product {
    int id;
    char name[50];
    float price;
    int stock;
    struct Product *next;  // 指向下一个商品
} Product_t;
```

📊好处对比表

| 需求             | 无数据结构（原始变量）                   | 使用数据结构（链表为例）                   |
| ---------------- | ---------------------------------------- | ------------------------------------------ |
| **遍历所有商品** | 需要硬编码所有变量名，扩展性差           | 统一遍历接口                               |
| **添加商品**     | 声明新变量，无法动态添加                 | O(1)时间插入新节点                         |
| **删除商品**     | 无法真正删除，只能标记为空               | O(1)/O(n)时间移除节点（已知位置/需要查找） |
| **查找商品**     | O(n)线性查找所有变量，需要知道每个变量名 | O(n)但代码简洁统一，使用循环遍历           |
| **排序商品**     | 几乎不可实现，需要手动维护               | 可用各种排序算法（快速排序、归并排序等）   |
| **内存使用**     | 静态分配，编译时确定大小，可能浪费或不足 | 动态分配，按需使用，灵活扩展               |
| **代码复用**     | 每个操作都要重新编写                     | 封装操作，一次编写多次使用                 |
| **扩展性**       | 增加新属性需要修改大量代码               | 修改结构体定义即可，操作函数通用           |
| **错误处理**     | 分散在各处，难以统一管理                 | 集中处理，提供统一的错误码/异常机制        |
| **并发访问**     | 几乎无法实现安全的并发访问               | 可设计线程安全的数据结构和操作             |
| **持久化存储**   | 需要为每个变量单独处理                   | 可序列化整个数据结构，统一存储加载         |

## 三、什么是数据结构？

### 3.1定义角度

```c
1. 广义：如何把数据高效储存在计算机的内存中，方便后续使用（增，删，改，查）。
1. 定义：相互之间存在一种或多种特定关系的数据元素的集合。
```

### 3.2结构角度

1. 逻辑结构

   ```c
   //从人的思维角度分析数据间的关系
   1.集合关系			//元素间没有特别关系
   {A, B, C, D} 
   2.线性/序列关系		//1对1像单列排队
   A → B → C → D
   3.树型				//1对多像目录结构/族谱/企业管理组织图
   ┌─树形结构───────┐
   │       A       │ ← 根节点
   │      / \      │
   │     B   C     │ ← 子节点  
   │    / \   \    │
   │   D   E   F   │ ← 叶节点
   └────────────────┘
    4.图				//多对多(路径不一)像地图/网络结构
   ┌─图状结构───────┐
   │     A────B     │
   │    / \  / \    │
   │   C──D  E─F    │ ← 任意两节点间可能有连接
   └────────────────┘ 
   ```

2. 物理结构

   ```c
   //把逻辑结构按照某种方式存储计算机的内存中
   1.线性存储	//在内存中连续存储，数据存放在连续的存储单位中。逻辑关系和物理关系一致	
   2.链式存储	//malloc，在内存中，不一定连续存储。数据存放的存储单位是随机或任意的，可以连续也可以不连续
   3.索引存储
   4.散列存储
   ```

## 四、必须掌握的数据结构有哪些？

### 4.1学习路线图

```c
/* 从易到难，循序渐进 */

Level 1: 基础数据结构（必须掌握）
├── 数组 (Array)              - 所有数据结构的基础
├── 字符串 (String)           - 字符数组的特殊形式
├── 结构体 (Struct)           - 自定义复合类型
└── 枚举 (Enum)               - 有限值集合

Level 2: 线性数据结构（❗核心重点）  
├── 链表 (Linked List)        - 动态存储的基石
├── 栈 (Stack)                - LIFO，函数调用基础
├── 队列 (Queue)              - FIFO，任务调度基础
└── 双向队列 (Deque)          - 双端操作

Level 3: 树形数据结构（❗进阶必备）
├── 二叉树 (Binary Tree)      - 树结构基础
├── 二叉搜索树 (BST)          - 有序存储
├── 堆 (Heap)                 - 优先队列
├── 哈夫曼树 (Huffman Tree)   - 数据压缩
└── AVL树/红黑树              - 平衡树（高级）

Level 4: 图形数据结构（高级应用）
├── 图的表示
│   ├── 邻接矩阵
│   └── 邻接表
├── 图遍历算法
│   ├── 深度优先搜索 (DFS)
│   └── 广度优先搜索 (BFS)
└── 最短路径算法
    ├── Dijkstra算法
    └── Floyd算法

Level 5: 哈希结构（高效查找）
├── ❗哈希表 (Hash Table)       - O(1)查找
└── 布隆过滤器 (Bloom Filter) - 空间高效的集合

Level 6: 高级/特殊结构（按需学习）
├── 并查集 (Union-Find)       - 集合合并查询
├── 线段树 (Segment Tree)     - 区间查询
├── Trie树 (字典树)           - 字符串检索
└── B树/B+树                  - 数据库索引
```

### 4.2核心特性对比

#### 1.基础时间复杂度

| -------------- | ------------- | ------------- | ---------------- | --------------- | ------------------------ |
| **数组**       | O(1)          | O(n)          | O(n)             | O(n)            | 随机访问快，插入删除慢   |
| **有序数组**   | O(1)          | O(log n)      | O(n)             | O(n)            | 二分查找需有序           |
| **链表**       | O(n)          | O(n)          | O(1)*            | O(1)*           | *已知位置时O(1)          |
| **栈**         | O(1)          | O(n)          | O(1)             | O(1)            | 只能访问栈顶             |
| **队列**       | O(1)          | O(n)          | O(1)             | O(1)            | 只能访问队首/队尾        |
| **哈希表**     | N/A           | O(1)          | O(1)             | O(1)            | 平均情况，可能退化为O(n) |
| **二叉搜索树** | O(log n)      | O(log n)      | O(log n)         | O(log n)        | 平衡时的情况             |
| **AVL/红黑树** | O(log n)      | O(log n)      | O(log n)         | O(log n)        | 自平衡树                 |
| **堆**         | O(1)          | O(n)          | O(log n)         | O(log n)        | 只能访问堆顶             |
| **B树**        | O(log n)      | O(log n)      | O(log n)         | O(log n)        | 用于数据库/文件系统      |
| **Trie树**     | O(k)          | O(k)          | O(k)             | O(k)            | k为键长度                |

#### 2.存储结构空间复杂度

| 数据结构         | 额外空间 | 总空间 | 特点说明                   |
| ---------------- | -------- | ------ | -------------------------- |
| **数组**         | 0        | O(n)   | 连续存储，无额外开销       |
| **链表**         | O(n)     | O(n)   | 每个节点需要next指针       |
| **双向链表**     | O(2n)    | O(n)   | 每个节点需要prev和next指针 |
| **栈/队列**      | O(n)     | O(n)   | 基于数组或链表实现         |
| **哈希表**       | O(n)     | O(n)   | 需要预留额外空间减少冲突   |
| **开放寻址哈希** | O(1)额外 | O(n)   | 所有元素都在数组中         |
| **链地址哈希**   | O(n)额外 | O(n+m) | m为桶数                    |

#### 3.树结构空间复杂度

| 树类型         | 额外空间                 | 总空间 | 备注             |
| -------------- | ------------------------ | ------ | ---------------- |
| **二叉树**     | O(n)                     | O(n)   | 每个节点2个指针  |
| **二叉搜索树** | O(n)                     | O(n)   | 同二叉树         |
| **AVL树**      | O(n)                     | O(n)   | 需要存储平衡因子 |
| **红黑树**     | O(n)                     | O(n)   | 需要颜色标记     |
| **B树**        | O(n)                     | O(n)   | 节点包含多个键   |
| **Trie树**     | O(ALPHABET_SIZE × k × n) | 较大   | k为平均键长      |

#### 4.根据操作频率选择

| 主要操作         | 推荐数据结构    | 原因                         |
| ---------------- | --------------- | ---------------------------- |
| **频繁随机访问** | 数组            | O(1)访问，内存连续           |
| **频繁插入删除** | 链表            | O(1)插入删除（已知位置）     |
| **频繁查找**     | 哈希表          | O(1)平均查找时间             |
| **需要有序性**   | 平衡搜索树      | O(log n)操作且有序           |
| **优先级处理**   | 堆              | O(log n)插入删除，O(1)取最值 |
| **前缀搜索**     | Trie树          | O(k)前缀匹配                 |
| **区间查询**     | 线段树/树状数组 | O(log n)区间操作             |

#### 5.特殊需求选择

| 需求           | 推荐数据结构           | 示例应用   |
| -------------- | ---------------------- | ---------- |
| **线程安全**   | 并发哈希表、无锁队列   | 多线程环境 |
| **持久化存储** | B+树、LSM树            | 数据库系统 |
| **内存受限**   | 压缩结构、位图         | 嵌入式系统 |
| **实时性要求** | 环形缓冲区、优先队列   | 实时系统   |
| **空间效率**   | 压缩trie、简洁数据结构 | 文本处理   |

#### 6.选择指南

```c
/* 根据需求选择合适的数据结构 */

需求: "我需要频繁按索引访问元素"
✅ 数组（随机访问O(1)）
❌ 链表（需要遍历O(n)）

需求: "我需要频繁在中间插入/删除"
✅ 链表（已知位置时O(1)）
❌ 数组（需要移动元素O(n)）

需求: "我需要先进先出的处理顺序"
✅ 队列（FIFO天然支持）
❌ 栈（LIFO，顺序不对）

需求: "我需要后进先出的处理顺序"
✅ 栈（函数调用、括号匹配）
❌ 队列（FIFO，顺序不对）

需求: "我需要快速查找元素"
✅ 哈希表（O(1)查找）
✅ 二叉搜索树（O(log n)查找，且有序）
❌ 无序数组/链表（O(n)查找）

需求: "我需要维护元素优先级"
✅ 堆（优先队列，取最大/最小O(1)）
❌ 数组/链表（需要排序O(n log n)）

需求: "我需要表示层级关系"
✅ 树（文件系统、组织结构）
❌ 线性结构（无法表示层次）

需求: "我需要表示复杂网络关系"
✅ 图（社交网络、地图导航）
❌ 树（只能表示层次关系）

需求: "我需要高效的集合操作"
✅ 并查集（合并、查询集合）
✅ 哈希表（成员判断O(1)）
❌ 数组（需要遍历O(n)）
```

#### 4.3.1 冒泡排序

/**
 * @brief 冒泡排序(以升序比较整数为例)
 *        1.两两比较，n个数比较n-1趟才能完成所有数按顺序排列
 *        2.第1趟比较中要进行n-1次比较才能完成大数沉底，小数上浮一个位置。
 *          比较完一趟可以确定该数为最大数、该数沉底即位置已经确定，剩下比较只需要比较余下的数。
 *        3.第j趟比较中要进行n-j次比较才能完成大数沉底，小数上浮一个位置。
 *          比较条件可以改变。
 * @param array
 * @param len
 */
void bubbleSort(int *array, int len)
{
    int count = len - 1; // 为什么是len-1？
                         // 因为每次比较array[i]和array[i+1]，i最大只能到len-2

    for (int j = 0; j < count; j++)         // 外层循环：控制轮数
    {                                       // 每轮把当前最大的数"冒泡"到最后
        for (int i = 0; i < count - j; i++) // 内层循环：相邻比较
        {                                   // count-j：每轮减少比较次数
                                            // 因为后面的数已经排好序了
            if (array[i] > array[i + 1]) // 如果前面的数比后面大
            {
                // 交换相邻两个数
                int tmp = array[i];
                array[i] = array[i + 1];
                array[i + 1] = tmp;
            }
        }
    }
    return;
}

void selectSort(int *array, int len)
{
    int count = len - 1;  // 为什么是len-1？
                          // 最后一个元素不需要再选（前面都排好了）
    
    for (int j = 0; j < count; j++)  // 外层循环：控制轮数
    {                                // 每轮确定位置j的最终值
        int min_idx = j;  			 // ★ 关键：假设当前位置j就是最小值（擂主）
        
        // 内层循环：在未排序部分找真正的最小值
        for (int i = j + 1; i < len; i++)
        {
            if (array[i] < array[min_idx])
            {
                min_idx = i;  // 更新最小值索引（挑战成功，换擂主）
            }
        }
        
        // 优化：只有找到更小的才交换（避免无用交换：min_idx == j的情况，自交换没意义）--
        if (min_idx != j)     //（避免擂主自己交换）
        {
            int tmp = array[j];
            array[j] = array[min_idx];
            array[min_idx] = tmp;
        }
    }
}
