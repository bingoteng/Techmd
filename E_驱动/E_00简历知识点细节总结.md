### 1、U-Boot

#### 1、什么是`uboot`？`bootloader内核加载引导程序+为linux内核搭建启动环境`

```
uboot 是（bootloader）内核加载引导程序。为 Linux 内核启动初始化相关软硬件，准备合适的环境引导内核启动。
```

#### 2、`uboot`的具体功能？`硬件初始化+引导内核启动（搬+加载）+提供交互界面`

```c
核心三个功能：硬件初始化/引导内核启动/提供交互界面
	1.硬件初始化： CPU与时钟系统初始化/初始化DDR/串口控制台 
	2.引导内核启动：搬移（拷贝）uboot到DDR/加载内核镜像和设备树/跳转到内核入口
	3.提供交互界面：设置环境变量/向内核传参/md
```

#### 3、uboot为什么要向内核传参？传递命令行参数有什么意义？`内核不完美适配具体板子+硬件配置信息`

```c
内核是通用的，同一份内核源码可以跑在不同板子上。但具体到某块板子，DDR 多大、串口在哪、内核自己不知道。

1.串口控制台信息 ---哪个串口-波特率多少
2.根文件挂载位置
3.tcp读写
 
1.bootcmd保存uboot默认命令，uboot倒计时结束以后就会执行bootcmd中的命令；
2.bootargs保存着uboot传递给Linux内核的参数
```

#### 4、`uboot`如何向内核传参？`3个寄存器+bootargs写入dtb的chosen节点`

```
r0 = 0：固定值，标识是 ARM 架构
r1 = 机器 ID：告诉内核是哪款板子，内核根据这个 ID 匹配对应的板级文件
r2 = 启动参数地址：指向一个参数列表或者设备树 DTB 的内存地址
	uboot的bootargs 会被自动写入在设备树的chosen节点中，内核会解析设备树节点数据获得传递参数。
```

#### 7、uboot的相关命令？`环境变量+内存操作+boot命令`

```c
1. 环境变量命令
   setenv/saveenv/printenv
2. 内存操作命令
    md		显示内存值
    mmc read   从emmc读取数据到内存 
    mmc write  将内存数据写入到emmc 
3. boot命令
   1. boot		执行bootcmd环境变量中的命令
   2. bootz		启动zImage形式的内核 
   3. bootm		启动uImage形式的内核
   4. bootcmd保存uboot默认命令，uboot倒计时结束以后就会执行bootcmd中的命令；
```

#### 8、✅uboot的启动流程？`固化bootrom选择sd卡启动+SPL阶段+完整uboot阶段`

```c
1.简略：内核启动前，通过uboot完成软硬件的初始化，将内核搬移到内存，并完成向内核的传参，引导内核启动。
2.详细：以i.mx开发板为例，uboot启动流程分为2个阶段
	阶段一，开发板上电后，I.MX内部固化的(96k）bootrom根据启动方式（sd卡/emmc）；将SPL（一小部分uboot代码）加载到片内的(128k）sram中执行，完成对外部DDR、cpu、时钟的基本初始化并将完整的uboot文件搬移(从sd拷贝)至（512MB）DDR中。
	阶段二，完整的uboot完成对串口（控制台以便打印信息）、网口（tftp）等的深度初始化；倒计时3秒内用户可自行选择进入uboot的交互界面，若不进入自动执行bootcmd默认命令，解析bootargs参数；（通过tftp将zImage内核镜像下载到0x8080000地址，将dtb设备树文件下载到0x8300000地址，bootz 80800000 - 83000000），（设置r0=0, r1=机器 ID, r2=DTB 地址）跳转到内核入口，引导内核启动。
```

#### 7、vmlinux、image、zimage、uimage的区别？`elf+原始+压缩后-bootz+头部信息-bootm`

```c
vmlinux：原生的elf格式内核镜像（可调式的内核）
```

#### 8、为什么内核镜像zImage下载到`0x8080000`的位置？dtb在`0x8300000`位置？`i.mx初始地址0x80000000+防止覆盖`

```c
i.MX6ULL 的 DDR 物理内存从 0x80000000 开始，但前 8MB（0x80000000~0x80800000）是给u-boot保留的空间，将dtb放在0x83000000的位置也是为了给zImage足够大的空间，放着dtb文件将镜像文件覆盖
```

## 二、驱动

#### 1、驱动分哪几类？`按字节流读写+按块(512B)读写+网络数据包/网络协议`

```c
一般按照设备访问方式：分三类
1.字符型设备驱动：		tty/misc/input/fb/iio
	以字符为单位，一个字节一个字节的读写操作设备，以字符流的形式传输数据，不带缓存 （鼠标、键盘、串口）
2.块设备驱动：		mmc/sd
	以固定块的大小为单位，通常是512字节去读写操作设备，带缓存，通常用来存储设备（SD卡、磁盘、硬盘）
3.网络设备驱动：		socket
	将网络数据包从物理层传输到网络层，并将网络层的数据封装成物理层可以传输的形式，需要集成多种网络协议及接口标准（以太网）
按照框架细分：字符设备驱动/平台驱动/子系统驱动
```

#### 2、设备驱动编译流程？静态编译和动态编译的区别？`静态编译复杂+.ko模块/加载卸载`

```c
（1）内核源码目录内：在/drivers/char目录下编写驱动，在Makefile中添加obj -m $(XXXX) += xxx.o，在Kconfig 中添加对应驱动的相关选项信息,在顶层目录中通过make menuconfig找到添加好的驱动选项并选为M/Y（动态编译/静态编译），会将驱动的编译方式写入到.config文件，输入make/make modules即可被静态编译进内核或者编译成.ko模块 
	
    1.在drivers/char下编写驱动程序修改Makefile文件，设置对应的环境变量 obj- $(xxxx) += xxx.o
	2.修改Kconfig文件，增加驱动编译选项
	3.回到内核源码的顶层目录修改make menuconfig
	4.将对应的驱动选项选择为 'Y（*）'  'M'   'N'，将驱动选项保存到.config文件中
	5.make 或 make modules编译对应的驱动模块
    
（2）内核源码目录外：编译好驱动后，通过Makefile指定源码路径，当前目录路径，驱动模块名等，make 编译即可在当前目录下生成驱动模块

1.静态编译：将驱动直接编译进内核，若后续想从内核删除该驱动，需要重新配置make menuconfig将该驱动选项选择为'N'，重新编译内核，对于开发和调试比较复杂。
2.动态编译：将驱动编译.ko模块，若后续想修改该驱动，只需要重新编译生成新的.ko模块，通过insmod/rmmod加载卸载，开发调试相对简单
```

#### 3、✅字符驱动设备实现流程`c_dev+file_operation结构体+注册->初始化->添加->创建类->创建节点的函数接口`

```c
核心：申请设备号->初始化并添加c_dev->创建设备类->创建设备节点->完善驱动操作函数。
    
1.构建c_dev结构体，用来描述字符型设备
2.构建file_operation结构体，用来描述驱动层操作函数
3.通过module_init和module_exit两个宏，指定驱动模块的入口函数和注销函数
4.通过MODULE_LICENSE宏，指定GNU组织规定的GPL协定
    
   *实现驱动模块的入口函数：注册->初始化->添加->创建类->创建节点
	1.通过register_chrdev_region(静态注册，已知主设备号)/alloc_chrdev_region(动态注册)注册字符型设备
	2.调用cdev_init函数，初始化cdev结构体
	3.调用cdev_add函数，将cdev结构体添加到系统
	4.调用class_create函数，创建设备类
	5.调用device_create函数，该类下创建设备节点
	完成对硬件的初始化
   *实现驱动模块的注销函数：注销->删除->删除类->删除节点
	1.通过调用unregister_chrdev_region,注销字符型设备
	2.调用cdev_del，从系统中删除cdev结构体
	3.调用class_destroy，删除类
	4.调用device_destroy, 删除设备节点
	完成对硬件的注销
5.完善file_operation驱动中open、read、write、release等操作函数
```

#### 4、静态注册和动态注册的区别？`需要手动注册+自动分配`

```
1.静态注册(register_chrdev_region)：事先自己定义好主次设备号，容易产生冲突，不推荐
2.动态注册（alloc_chrdev_region）：系统自动分配一个未被占用的设备号
```

#### 5、字符型设备驱动如何手动创建设备节点？主次设备号的区别？主次设备号的大小？如何构建新设备号？`mknod`

```
用户空间 mknod  /dev/ds18b20  c  248 0

/dev/ds18b20：设备节点

0：  次设备号  ---该类设备下具体的某一个设备 device_create

linux下，用32位的unsigned int类型表示设备号

内核空间 通过MKDEV宏，传入主次设备号来构建一个新的设备号
```

#### 6、如何加载驱动ko模块？ insmod和modprobe区别？`依赖关系`


#### 12、互斥锁、自旋锁、读写锁的区别？`cpu可切换+cpu忙等待+读锁共享/写锁独占（类似互斥）`

```c
1.互斥锁mutex：加锁解锁过程中，cpu可以切换调度任务
	机制：如果锁被占用，当前线程会进入睡眠状态，让出 CPU，直到锁被释放才唤醒。
	场景：只能在进程上下文中使用，长时间资源占用使用互斥锁。不能在中断里用，因为中断不能睡眠。
    
2.自旋锁spinlock：加锁解锁过程中，CPU处于忙等待（轮询），不会进行任务调度和切换。
    机制：如果锁被占用，当前线程会一直循环检查（忙等待），不会休眠，直到拿到锁。
	场景：适合持锁时间极短（微秒级）的代码，或者中断上下文、中断下半部机制里。
    
3.读写锁：读锁共享，写锁独占
    机制：把锁分成读锁和写锁。读锁共享（允许多个线程同时读），写锁独占（写的时候不能读也不能写）。
    	当多个线程对共享资源进行读操作时，加读写锁的读锁，此时多个线程均不会阻塞（读锁共享）
		当多个线程对共享资源进行写操作时，可能会改变资源的值，造成竞争，此时写锁的效果和互斥锁相同（写锁独占）
	场景：非常适合读多写少的数据结构。
```

#### 13、`linux`驱动中的中断如何实现？`顶/低 快进快出+软中断/tasklet/workqueue +中断/进程上下文`

```c

	中断服务函数：处理速度要快，不能加延时

```

#### 14、什么是中断上下文/进程上下文？`进程可调度/睡眠+中断严谨睡眠`

```c
1.进程上下文：代表一个进程在执行，有完整的进程信息，可以睡眠、可以调度
	1.有进程描述符，可以访问当前进程的资源
	2.调用 sleep() 睡眠、可以分配内存、可以拷贝用户空间数据 copy_to_user()
2.中断上下文：中断触发时 CPU 被动跳转执行，没有进程信息，当前进程被打断，绝对不能睡眠、不能调度
    1.硬件中断触发，CPU 跳转到 request_irq 注册的中断处理函数中handler执行
    2.严禁睡眠
    
    
udelay：微秒级-是忙等待，死循环消耗 CPU，不能睡眠，适合微秒级短延时。中断上下文
sleep（内核里是 msleep）：毫秒级-是让出 CPU，进程挂起，可以睡眠，适合毫秒级以上长延时 进程上下文
```
